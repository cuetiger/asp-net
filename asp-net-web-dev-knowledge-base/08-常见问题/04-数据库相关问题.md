## 问题1：连接字符串配置错误

### 问题描述
数据库连接字符串配置不正确导致无法建立数据库连接。

### 错误现象

```text
SqlException: A network-related or instance-specific error occurred while establishing a connection to SQL Server.
NpgsqlException: The password must be provided when using authentication mode 'Password'.
MySqlException: Unable to connect to any of the specified MySQL hosts.
```

### 原因分析

1. **服务器地址错误**：主机名、IP地址或端口不正确
2. **认证信息错误**：用户名、密码错误或过期
3. **数据库名称错误**：指定的数据库不存在
4. **特殊字符未转义**：密码中的特殊字符（如`;`, `'`, `"`）未正确处理
5. **连接参数缺失**：缺少必要的连接参数（如TrustServerCertificate）
6. **环境变量引用错误**：appsettings中的占位符未被正确替换

### 解决方案

#### 方法1：标准连接字符串格式
```json
// appsettings.json / appsettings.Development.json
{
  "ConnectionStrings": {
    // SQL Server (本地)
    "DefaultConnection": "Server=(localdb)\\mssqllocaldb;Database=MyAppDb;Trusted_Connection=True;MultipleActiveResultSets=true",

    // SQL Server (远程/生产)
    "SqlServerConnection": "Server=tcp:sqlserver.example.com,1433;Database=ProductionDb;User Id=myuser;Password=mypassword;TrustServerCertificate=true;",

    // PostgreSQL
    "PostgreSQLConnection": "Host=db.example.com;Port=5432;Database=mydb;Username=myuser;Password=mypassword;SSL Mode=Require;",

    // MySQL
    "MySQLConnection": "Server=mysql.example.com;Port=3306;Database=mydb;User Id=myuser;Password=mypassword;AllowUserVariables=true;",

    // SQLite
    "SQLiteConnection": "Data Source=myapp.db"
  }
}
```

#### 方法2：安全地管理敏感连接字符串
```csharp
// Program.cs - 使用Secret Manager（开发环境）和Azure Key Vault（生产环境）

// 开发环境使用User Secrets

{

var connectionString = builder.Configuration.GetConnectionString("DefaultConnection")
    ?? throw new InvalidOperationException("Connection string 'DefaultConnection' not found.");

builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlServer(connectionString));
```

```bash

dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Server=(localdb)\\mssqllocaldb;Database=MyAppDb;Trusted_Connection=True"

# Docker/生产环境通过环境变量注入
docker run -e ConnectionStrings__DefaultConnection="Server=db;Database=prod;..." myapp
```

#### 方法3：多环境连接字符串策略
```csharp
public static class DatabaseConfiguration
{
    public static IServiceCollection AddDatabase(this IServiceCollection services, IConfiguration config, IWebHostEnvironment env)
    {
        var connectionString = config.GetConnectionString("DefaultConnection");

        if (env.IsDevelopment())
        {
            // 开发环境：详细日志 + 自动迁移
            services.AddDbContext<AppDbContext>(options =>
                options.UseSqlServer(connectionString, sqlOptions =>
                {
                    sqlOptions.EnableDetailedErrors();
                    sqlOptions.EnableRetryOnFailure(maxRetryCount: 3);
                    sqlOptions.CommandTimeout(30);
                }));
        }
        else if (env.IsStaging() || env.IsProduction())
        {
            // 生产环境：健康检查 + 连接池优化
            services.AddDbContextPool<AppDbContext>(options =>  // 使用连接池
                options.UseSqlServer(connectionString, sqlOptions =>
                {
                    sqlOptions.EnableRetryOnFailure(
                        maxRetryCount: 3,
                        maxRetryDelay: TimeSpan.FromSeconds(30));
                    sqlOptions.MinPoolSize(5);   // 最小连接数
                    sqlOptions.MaxPoolSize(100); // 最大连接数
                    sqlOptions.CommandTimeout(60); // 更长的超时
                }));

            // 添加数据库健康检查
            services.AddHealthChecks()
                .AddCheck<DbContextHealthCheck>("database");
        }

        return services;
    }
}
```

### 预防措施
- 使用 Secret Manager 或 Key Vault 管理敏感信息
- 不要将连接字符串提交到版本控制
- 为每个环境维护独立的配置文件
- 定期轮换数据库密码
- 使用 `TrustServerCertificate` 仅在开发环境

## 问题2：连接池耗尽（Too many connections）

### 问题描述
应用程序因数据库连接数达到上限而无法获取新连接。

### 错误现象

```text
Timeout expired. The timeout period elapsed prior to obtaining a connection from the pool.
Npgsql: The connection pool has been exhausted.
MySqlException: Too many connections
InvalidOperationException: Timeout expired. The timeout period elapsed prior to obtaining a connection from the pool. This may have occurred because all pooled connections were in use and max pool size was reached.
```

### 原因分析

1. **连接泄漏**：DbContext未正确Dispose，连接未归还池中
2. **Max Pool Size过小**：默认值100可能不够用
3. **长时间运行的操作**：持有连接时间过长
4. **连接未关闭**：手动打开的DbConnection未关闭
5. **高并发场景**：请求量超出连接池容量
6. **慢查询阻塞**：长时间运行的查询占用连接

### 解决方案

#### 方法1：优化连接池配置
```csharp
services.AddDbContextPool<AppDbContext>(options =>
    options.UseSqlServer(connectionString, sqlOptions =>
    {
        sqlOptions.MaxPoolSize(200);     // 最大连接数（根据并发量调整）
        sqlOptions.MinPoolSize(10);      // 最小连接数（预热）
        sqlOptions.ConnectionIdleTimeout(TimeSpan.FromMinutes(5)); // 空闲超时
        sqlOptions.ConnectionLifetimeTimeout(TimeSpan.FromMinutes(30)); // 连接生命周期
    }));

// DbContextPool 的好处：
// - 自动重置 DbContext 状态
// - 减少对象分配开销
// - 避免连接泄漏
```

#### 方法2：确保DbContext正确释放

#### 方法3：监控和诊断连接池状态
```csharp
public class ConnectionPoolMonitor : IHostedService
{
    private readonly ILogger<ConnectionPoolMonitor> _logger;
    private Timer? _timer;

    public ConnectionPoolMonitor(ILogger<ConnectionPoolMonitor> logger)
    {
        _logger = logger;
    }

    public Task StartAsync(CancellationToken ct)
    {
        _timer = new Timer(LogPoolStats, null, TimeSpan.Zero, TimeSpan.FromSeconds(30));
        return Task.CompletedTask;
    }

    public Task StopAsync(CancellationToken ct)
    {
        _timer?.Dispose();
        return Task.CompletedTask;
    }

    private void LogPoolStats(object? state)
    {
        // SQL Server 连接池统计
        var stats = SqlClientPerformanceCounters.Instance?.GetConnectionPoolStats("DefaultConnection");
        if (stats != null)
        {
            _logger.LogInformation(
                "Connection Pool Stats - Active: {Active}, Idle: {Idle}, Waiting: {Waiting}",
                stats.ActiveConnections, stats.IdleConnections, stats.WaitingForConnection);
        }
    }
}
```

- 监控连接池指标设置告警
- 避免长事务和长时间持有的连接

## 问题3：迁移失败（Pending changes/Model mismatch）

### 问题描述
EF Core数据库迁移失败，提示有挂起的模型更改或模型与快照不匹配。

### 错误现象

```text
An operation was scaffolded that may result in data loss. Please review the migration for accuracy.
The model backing the 'DbContext' context has changed since the database was created. Consider using Code First Migrations to resolve this issue.
System.InvalidOperationException: There is already an object named 'TableName' in the database.
```

### 原因分析

1. **模型已更改但未生成迁移**：实体类修改后没有创建对应的Migration
2. **迁移文件丢失**：删除了Migrations文件夹但数据库已有迁移记录
3. **多个开发者冲突**：不同分支的迁移产生冲突
4. **数据丢失风险**：DropColumn等操作可能导致数据丢失
5. **数据库已被外部修改**：直接修改了数据库结构而非通过迁移
6. **快照文件不一致**：ModelSnapshot.csx 与当前模型不匹配

### 解决方案

#### 方法1：标准的迁移工作流
```bash
# 1. 创建新迁移
dotnet ef migrations add InitialCreate --project DataProject --context AppDbContext

# 2. 查看即将执行的SQL（审查数据影响）
dotnet ef migrations script --project DataProject --context AppDbContext

# 3. 应用迁移到数据库
dotnet ef database update --project DataProject --context AppDbContext

# 4. 回滚到指定迁移
dotnet ef database update PreviousMigrationName

# 5. 删除最后一次迁移（如果还没应用到数据库）
dotnet ef migrations remove --project DataProject --context AppDbContext
```

#### 方法2：处理常见迁移问题
```bash
# 问题1：模型已更改但不想创建迁移（开发阶段快速重建）
dotnet ef database drop --force  # 删除数据库
dotnet ef database update         # 从头应用所有迁移

# 问题2：跳过特定迁移的数据检查（确认无数据丢失后）
dotnet ef migrations add MyMigration --no-build
# 编辑生成的迁移文件，移除警告注释

# 问题3：解决合并冲突后的迁移
git checkout --theirs Migrations/*.cs  # 接受对方的迁移
dotnet ef migrations script          # 重新生成完整脚本
rm Migrations/*.cs                   # 删除所有迁移文件
dotnet ef migrations add InitialCreate # 重新创建初始迁移

# 问题4：从现有数据库创建迁移（数据库优先）
dotnet ef dbcontext scaffold "Server=(localdb)\\mssqllocaldb;Database=ExistingDb" Microsoft.EntityFrameworkCore.SqlServer \
    --output-dir Models \
    --context ExistingDbContext \
    --data-annotations
```

#### 方法3：安全的迁移策略
```csharp
// 在程序启动时自动迁移（适合小项目）
public static IHost MigrateDatabase(this IHost host)
{
    using var scope = host.Services.CreateScope();
    var services = scope.ServiceProvider;
    
    try
    {
        var context = services.GetRequiredService<AppDbContext>();
        
        if (context.Database.IsRelational())
        {
            var pendingMigrations = await context.Database.GetPendingMigrationsAsync();
            if (pendingMigrations.Any())
            {
                Console.WriteLine($"Applying {pendingMigrations.Count()} pending migrations...");
                await context.Database.MigrateAsync();
                Console.WriteLine("Migrations applied successfully.");
            }
        }
    }
    catch (Exception ex)
    {
        Console.WriteLine($"Migration failed: {ex.Message}");
        throw;
    }

    return host;
}

// Program.cs
var app = builder.Build();
if (args.Contains("--migrate"))
{
    app.MigrateDatabase();  // 作为独立命令运行
    return;
}
```

### 预防措施
- 将迁移文件纳入版本控制并定期同步
- 不要手动修改数据库结构，始终通过迁移
- 重要操作前备份数据库
- CI/CD流水线中加入迁移步骤
- 多人团队制定迁移命名规范

## 问题4：查询性能慢（缺少索引/N+1问题）

### 问题描述
数据库查询响应缓慢，页面加载时间长。

### 错误现象

- API接口响应时间 > 500ms
- 数据库CPU使用率持续偏高
- EF Core日志显示大量单独的SELECT语句
- 页面渲染时出现"加载中..."

### 原因分析

1. **N+1查询问题**：遍历集合时对每个元素执行额外查询
2. **缺少索引**：WHERE、JOIN、ORDER BY使用的列没有索引
3. **SELECT ***：查询了不需要的列
4. **客户端求值**：LINQ表达式无法翻译为SQL，在内存中执行
5. **全表扫描**：查询条件不能有效利用索引
6. **大数据量返回**：一次查询返回过多行
7. **复杂关联查询**：过多的JOIN操作

### 解决方案

#### 方法1：识别和修复N+1问题
```csharp
// ❌ N+1问题示例
public async Task<List<OrderDto>> GetAllOrdersAsync()
{
    var orders = await _dbContext.Orders.ToListAsync();  // 第1次查询
    
    foreach (var order in orders)
    {
        // 对每个order都执行一次查询 → N次查询
        order.User = await _dbContext.Users.FindAsync(order.UserId);
        
        foreach (var item in order.Items)
        {
            // 对每个item也执行查询 → N*M次查询
            item.Product = await _dbContext.Products.FindAsync(item.ProductId);
        }
    }
    
    return orders.Select(MapToDto).ToList();
}

// ✅ 修复1：使用Include预加载关联数据
public async Task<List<OrderDto>> GetAllOrdersWithIncludeAsync()
{
    var orders = await _dbContext.Orders
        .Include(o => o.User)              // 预加载User（LEFT JOIN）
        .Include(o => o.Items)             // 预加载Items
            .ThenInclude(i => i.Product)   // 再预加载Product（嵌套Include）
        .AsNoTracking()                     // 只读查询不需要变更追踪
        .ToListAsync();
    
    return orders.Select(MapToDto).ToList();
}

// ✅ 修复2：使用Select投影（最推荐，只查需要的列）
public async Task<List<OrderDto>> GetAllOrdersWithProjectionAsync()
{
    return await _dbContext.Orders
        .Select(o => new OrderDto           // 直接在SQL层面投影
        {
            OrderId = o.Id,
            OrderDate = o.OrderDate,
            TotalAmount = o.Items.Sum(i => i.Quantity * i.UnitPrice),
            UserName = o.User.Name,
            Items = o.Items.Select(i => new ItemDto
            {
                ProductName = i.Product.Name,
                Quantity = i.Quantity,
                UnitPrice = i.UnitPrice
            }).ToList()
        })
        .ToListAsync();
}
```

## 问题5：SaveChanges 不生效

### 问题描述
调用 SaveChangesAsync 后，数据库中的数据没有更新。

### 错误现象

```text
代码执行了 Add/Update/Delete 和 SaveChangesAsync，但数据库中没有变化。
或者抛出 DbUpdateConcurrencyException 但数据确实没变。
```

### 原因分析

1. **Change Tracker未跟踪**：实体没有被DbContext跟踪
2. **使用了AsNoTracking**：查询时禁用了变更追踪
3. **不同的DbContext实例**：查询和保存使用了不同的DbContext
4. **事务回滚**：SaveChanges成功但后续事务回滚了
5. **断开的实体**：从序列化/反序列化后的实体失去追踪
6. **主键为0/default**：新增实体的主键是默认值
7. **并发冲突**：乐观并发检测阻止了更新

### 解决方案

#### 方法1：确保实体被正确跟踪
```csharp
public async Task UpdateUserAsync(int id, UpdateUserRequest request)
{
    // ✅ 方式1：先查询再修改（Change Tracker会自动跟踪变化）
    var user = await _dbContext.Users.FindAsync(id);
    if (user == null) throw new NotFoundException();

    user.Name = request.Name;
    user.Email = request.Email;
    user.UpdatedAt = DateTime.UtcNow;

    await _dbContext.SaveChangesAsync();  // Change Tracker检测到变化并生成UPDATE SQL

    // ✅ 方式2：附加断开连接的实体
    var detachedUser = new User { Id = id, Name = request.Name };
    _dbContext.Users.Attach(detachedUser);
    _dbContext.Entry(detachedUser).State = EntityState.Modified;
    // 可选择性标记特定属性为已修改
    // _dbContext.Entry(detachedUser).Property(u => u.Name).IsModified = true;

    await _dbContext.SaveChangesAsync();

    // ✅ 方式3：ExecuteUpdate（EF Core 7+，高性能批量更新）
    var affectedRows = await _dbContext.Users
        .Where(u => u.Id == id)
        .ExecuteUpdateAsync(setters => setters
            .SetProperty(u => u.Name, request.Name)
            .SetProperty(u => u.Email, request.Email)
            .SetProperty(u => u.UpdatedAt, DateTime.UtcNow));

    return affectedRows > 0;
}
```

#### 方法2：处理AsNoTracking场景
```csharp
// 如果必须使用AsNoTracking（如只读API），更新时需要显式附加
public async Task<UserDto> GetUserReadOnly(int id)
{
    // 只读查询，不跟踪
    return await _dbContext.Users
        .AsNoTracking()
        .Where(u => u.Id == id)
        .Select(u => new UserDto { Id = u.Id, Name = u.Name })
        .FirstOrDefaultAsync();
}

public async Task UpdateFromDto(UserDto dto)
{
    // 从DTO重新构建实体并附加
    var user = new User { Id = dto.Id, Name = dto.Name };
    _dbContext.Attach(user);
    _dbContext.Entry(user).Property(u => u.Name).IsModified = true;
    await _dbContext.SaveChangesAsync();
}
```

#### 方法3：验证SaveChanges的结果
```csharp
public async Task<Result> SaveWithValidationAsync()
{
    try
    {
        var affectedRows = await _dbContext.SaveChangesAsync();
        
        if (affectedRows == 0)
        {
            _logger.LogWarning("SaveChanges affected 0 rows. Changes may not have been detected.");
            return Result.Failure("No changes were saved.");
        }

        _logger.LogInformation("Saved {AffectedRows} row(s)", affectedRows);
        return Result.Success(affectedRows);
    }
    catch (DbUpdateConcurrencyException ex)
    {
        _logger.LogWarning(ex, "Concurrency conflict detected");
        return Result.Conflict("The record was modified by another user. Please refresh and retry.");
    }
    catch (DbUpdateException ex)
    {
        _logger.LogError(ex, "Database update failed");
        return Result.Error(ex.InnerException?.Message ?? ex.Message);
    }
}
```

- 了解Change Tracker的工作原理
- 同一操作中使用相同的DbContext实例
- 对于断开连接的场景，明确使用 Attach 或 Update
- 使用 ExecuteUpdate/ExecuteDelete 进行批量操作（EF Core 7+）
- 检查 SaveChanges 的返回值确认操作结果

## 问题6：并发冲突（DbUpdateConcurrencyException）

### 问题描述
多个用户同时编辑同一条数据时产生的冲突。

### 错误现象

```text
Microsoft.EntityFrameworkCore.DbUpdateConcurrencyException: The database operation was expected to affect 1 row(s) but actually affected 0 row(s).
Data may have been modified or deleted since entities were loaded.
```

### 原因分析

1. **最后写入胜出（LWW）**：两个用户同时读取、修改、保存
2. **乐观并发控制失效**：RowVersion/Timestamp检查失败
3. **前端缓存数据陈旧**：用户看到的是旧数据
4. **后台任务与用户操作冲突**

### 解决方案

#### 方法1：实现完整的乐观并发控制
```csharp
// 1. 实体配置并发令牌
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; } = string.Empty;
    public decimal Price { get; set; }

    [Timestamp]  // 或使用Fluent API
    public byte[] RowVersion { get; set; } = null!;
}

// 或 Fluent API:
// modelBuilder.Entity<Product>().Property(p => p.RowVersion).IsRowVersion().IsConcurrencyToken();

// 2. 服务层处理冲突
public class ProductService
{
    public async Task<Result> UpdatePriceAsync(int productId, decimal newPrice, byte[] currentVersion)
    {
        var product = await _productRepository.GetByIdAsync(productId);
        if (product == null) return Result.NotFound("产品不存在");

        // 设置当前的RowVersion用于并发检查
        _dbContext.Entry(product).OriginalValues["RowVersion"] = currentVersion;

        product.Price = newPrice;
        product.UpdatedAt = DateTime.UtcNow;

        try
        {
            await _dbContext.SaveChangesAsync();
            return Result.Success();
        }
        catch (DbUpdateConcurrencyException ex)
        {
            return await HandleConcurrencyConflictAsync(ex, product, newPrice);
        }
    }

    private async Task<Result> HandleConcurrencyConflictAsync(
        DbUpdateConcurrencyException ex, Product product, decimal newPrice)
    {
        var entry = ex.Entries.Single();

        // 选项A：数据库获胜（强制刷新）
        // entry.Reload();
        // product.Price = (decimal)entry.CurrentValues["Price"];
        // await _dbContext.SaveChangesAsync();

        // 选项B：客户端获胜（强制覆盖）
        // entry.OriginalValues.SetValues(entry.CurrentValues);
        // entry.CurrentValues["Price"] = newPrice;
        // await _dbContext.SaveChangesAsync();

        // 选项C：合并策略（给用户选择）
        var dbValues = await entry.GetDatabaseValuesAsync();
        var clientPrice = (decimal)entry.CurrentValues["Price"];
        var dbPrice = (decimal)(dbValues?["Price"] ?? 0m);

        return Result.Conflict(new
        {
            Message = "数据已被其他用户修改",
            CurrentDbValue = dbPrice,
            YourAttemptedValue = newPrice,
            Suggestion = "请刷新页面查看最新数据后重新编辑"
        });
    }
}
```

#### 方法2：前端配合处理并发
```csharp
// DTO 包含并发令牌
public class UpdateProductRequest
{
    public decimal Price { get; set; }
    public string RowVersion { get; set; } = null!;  // Base64编码的timestamp
}

// API控制器
[HttpPut("{id}")]
public async Task<IActionResult> Update(int id, UpdateProductRequest request)
{
    var rowVersion = Convert.FromBase64String(request.RowVersion);
    var result = await _productService.UpdatePriceAsync(id, request.Price, rowVersion);

    return result.Match(
        success => NoContent(),
        notFound => NotFound(result.Message),
        conflict => Conflict(result.Data),  // 返回409和最新数据
        error => BadRequest(result.Message)
    );
}
```

### 预防措施
- 所有可编辑的实体都应该有并发令牌（RowVersion/Timestamp）
- API返回实体时包含并发令牌供客户端提交时带回
- 实现合理的冲突解决策略（数据库胜出/客户端胜出/合并）
- 对于高频更新的计数器等字段，考虑使用原子操作

## 问题7：字符集/编码问题（中文乱码）

### 问题描述
中文数据存储或显示时出现乱码、问号或方框。

### 错误现象

```text
数据库中显示：?????? 或 ä¸­ä½??
网页显示：æ±±å¼ æ±±ç
JSON解析报错：Invalid UTF-8 sequence
```

### 原因分析

1. **数据库编码不一致**：数据库使用latin1而应用使用UTF-8
2. **连接字符串缺少Charset**：MySQL/PostgreSQL未指定字符集
3. **文件编码错误**：源代码文件不是UTF-8 with BOM
4. **HTTP响应编码错误**：Content-Type未指定charset
5. **NVARCHAR vs VARCHAR**：SQL Server使用了VARCHAR而不是NVARCHAR

### 解决方案

#### 方法1：统一使用UTF-8
```csharp
// 1. 连接字符串指定UTF-8
// PostgreSQL: "Host=localhost;Database=test;Username=postgres;Password=xxx;Encoding=UTF8"
// MySQL: "Server=localhost;Database=test;User=root;Password=xxx;Charset=utf8mb4"

// 2. SQL Server 使用 NVARCHAR（Unicode）
modelBuilder.Entity<User>(entity =>
{
    entity.Property(e => e.Name).IsUnicode(true);  // 映射为nvarchar
    entity.Property(e => e.Description).HasColumnType("nvarchar(MAX)");
});

// 3. HTTP响应编码
// ASP.NET Core 默认使用 UTF-8，但可以显式配置
builder.Services.Configure<WebEncoderOptions>(options =>
{
    options.TextEncoderSettings = new TextEncoderSettings(UnicodeRanges.All);  // 允许所有Unicode字符
});
```

#### 方法2：数据库层面的编码设置
```sql
-- MySQL: 创建数据库时指定字符集
CREATE DATABASE myapp CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 检查当前编码
SHOW VARIABLES LIKE 'character_set%';
SHOW VARIABLES LIKE 'collation%';

-- 修改已有表的编码
ALTER TABLE Users CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- PostgreSQL: 创建数据库时指定编码
CREATE DATABASE myapp ENCODING 'UTF8';

-- SQL Server: 确保使用 nvarchar/nchar 类型
ALTER TABLE Users ALTER COLUMN Name NVARCHAR(255) NOT NULL;
```

### 预防措施
- 全栈统一使用 UTF-8 编码
- 数据库创建时就指定正确的字符集
- SQL Server 中文本字段一律使用 NVARCHAR
- 文件头部声明编码（`# -*- coding: utf-8 -*-` for Python, BOM for C# files）
- API 响应明确指定 Content-Type: application/json; charset=utf-8

## 问题8：EF Core LINQ 翻译失败（客户端求值警告）

### 问题描述
LINQ查询无法完全翻译为SQL，部分逻辑在内存中执行，导致性能问题或错误。

### 错误现象

```text
Warning: The LINQ expression could not be translated and will be evaluated locally.
System.NotSupportedException: The LINQ expression '{expression}' could not be translated.
```

### 原因分析

1. **使用了自定义方法**：调用不能翻译为SQL的方法
2. **复杂的条件逻辑**：包含C#特有的语法或方法
3. **类型转换问题**：某些类型转换不被支持
4. **字符串操作**：正则表达式、复杂的字符串函数
5. **日期计算**：某些日期运算不支持
6. **多态调用**：虚方法调用或接口方法

### 解决方案

#### 方法1：识别和修复常见的翻译问题
```csharp
// ❌ 不能翻译的自定义方法
var result = await _dbContext.Users
    .Where(u => IsPremiumUser(u))  // 自定义方法！
    .ToListAsync();

// ✅ 修复：内联逻辑或使用EF.Functions
var result = await _dbContext.Users
    .Where(u => u.SubscriptionLevel >= SubscriptionLevel.Premium &&
                u.SubscriptionExpiryDate > DateTime.UtcNow)
    .ToListAsync();

// ❌ 不能翻译的字符串操作
var result = await _dbContext.Orders
    .Where(o => Regex.IsMatch(o.OrderNo, @"^ORD-\d{6}$"))  // Regex!
    .ToListAsync();

// ✅ 修复：使用EF.Functions.Like或数据库原生函数
var result = await _dbContext.Orders
    .Where(o => EF.Functions.Like(o.OrderNo, "ORD-_____%"))  // SQL LIKE模式
    .ToListAsync();

// ❌ 不能翻译的日期操作
var result = await _dbContext.Users
    .Where(u => (DateTime.Now - u.LastLoginDate).TotalDays > 30)  // TimeSpan算术
    .ToListAsync();

// ✅ 修复：使用 DateDiff 或比较日期
var cutoffDate = DateTime.UtcNow.AddDays(-30);
var result = await _dbContext.Users
    .Where(u => u.LastLoginDate < cutoffDate)
    .ToListAsync();

// ❌ 不能翻译的类型转换
var result = await _dbContext.Products
    .Where(p => Enum.Parse<CategoryType>(p.Category) == CategoryType.Electronics)
    .ToListAsync();

// ✅ 修复：使用枚举比较（如果存的是int/string）或先转换再查询
var electronicsValue = (int)CategoryType.Electronics;
var result = await _dbContext.Products
    .Where(p => p.CategoryId == electronicsValue)
    .ToListAsync();
```

#### 方法2：混合使用服务端和客户端评估
```csharp
// 有时候部分逻辑必须在内存中完成，这时要明确分割
public async Task<List<UserDto>> GetFilteredUsersAsync(string keyword)
{
    // 步骤1：在数据库端做能做的过滤（减少传输量）
    var query = _dbContext.Users
        .AsNoTracking()
        .Where(u => u.IsActive && !u.IsDeleted);

    if (!string.IsNullOrWhiteSpace(keyword))
    {
        // 如果keyword需要模糊匹配且EF Functions不够用：
        // 先在DB端做粗略过滤，再在内存中精确过滤
        query = query.Where(u => u.Name.Contains(keyword) || u.Email.Contains(keyword));
    }

    // 步骤2：获取数据后在内存中处理
    var users = await query.ToListAsync();

    // 步骤3：内存中进行复杂处理
    var result = users
        .Select(u => new UserDto
        {
            Id = u.Id,
            DisplayName = FormatDisplayName(u.FirstName, u.LastName),
            MembershipLevel = CalculateMembershipLevel(u.Points, u.JoinDate),
            AvatarUrl = GenerateAvatarUrl(u.Email)
        })
        .Where(dto => dto.MembershipLevel > 0)  // 内存过滤
        .OrderByDescending(dto => dto.MembershipLevel)
        .ToList();

    return result;
}
```

#### 方法3：使用原始SQL处理复杂查询
```csharp
// 当LINQ实在无法表达时，使用原始SQL
public async Task<PagedResult<OrderReport>> GetOrderReportAsync(OrderReportFilter filter)
{
    var sql = @"
        SELECT 
            DATEPART(YEAR, CreatedAt) as Year,
            DATEPART(MONTH, CreatedAt) as Month,
            COUNT(*) as TotalOrders,
            SUM(TotalAmount) as Revenue,
            AVG(TotalAmount) as AvgOrderValue
        FROM Orders
        WHERE Status <> @CancelledStatus
          AND CreatedAt BETWEEN @StartDate AND @EndDate
        GROUP BY DATEPART(YEAR, CreatedAt), DATEPART(MONTH, CreatedAt)
        ORDER BY Year DESC, Month DESC";

    var parameters = new[]
    {
        new SqlParameter("@CancelledStatus", OrderStatus.Cancelled),
        new SqlParameter("@StartDate", filter.StartDate),
        new SqlParameter("@EndDate", filter.EndDate)
    };

    var reports = await _dbContext.Database
        .SqlQuery<OrderReportRow>(sql, parameters)
        .ToListAsync();

    return new PagedResult<OrderReport>(reports.Count, reports);
}
```
