# ASP.NET 前端集成问题解答

> **适用场景**：ASP.NET应用与前端（Vue/React/Blazor/Angular）集成时遇到的问题
>
> **目标读者**：需要解决前后端分离、CORS、SignalR、SPA路由等问题的全栈开发者

---

## 问题1：CORS 跨域错误

### 问题描述
前端调用后端API时浏览器报跨域错误。

### 错误现象

```text
Access to fetch at 'http://localhost:5000/api/users' from origin 'http://localhost:3000' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

### 原因分析

1. **未配置CORS策略**：后端没有允许跨域请求
2. **Origin不匹配**：配置的允许来源与实际前端地址不一致
3. **预检请求失败**：OPTIONS请求被拒绝
4. **凭证问题**：携带Cookie的请求需要特殊配置

### 解决方案

#### 方法1：完整CORS配置
```csharp
// Program.cs
var builder = WebApplication.CreateBuilder(args);

// 方式A：简单配置（开发环境）
var corsOrigins = builder.Configuration.GetSection("Cors:Origins").Get<string[]>()
    ?? new[] { "http://localhost:3000", "http://localhost:5173" };

builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowSpecificOrigins", policy =>
    {
        policy.WithOrigins(corsOrigins)  // 允许的来源列表
              .AllowAnyHeader()            // 允许所有请求头
              .AllowAnyMethod()            // 允许所有HTTP方法
              .AllowCredentials()           // 允许携带凭证(Cookie)
              .SetIsOriginAllowedToAllowWildcardSubdomains();  // 允许子域名
    });

    // 开发环境允许任意来源
    if (builder.Environment.IsDevelopment())
    {
        options.AddPolicy("AllowDev", policy =>
        {
            policy.AllowAnyOrigin()
                  .AllowAnyMethod()
                  .AllowAnyHeader();
        });
    }
});

var app = builder.Build();

// ⚠️ CORS中间件必须在UseAuthentication和UseAuthorization之前！
app.UseCors(builder.Environment.IsDevelopment() ? "AllowDev" : "AllowSpecificOrigins");
app.UseAuthentication();
app.UseAuthorization();
```

#### 方法2：appsettings.json 配置
```json
{
  "Cors": {
    "Origins": [
      "https://myapp.example.com",
      "https://www.myapp.example.com",
      "http://localhost:3000",
      "http://localhost:5173"
    ]
  },
  "AllowedHosts": "*"
}
```

#### 方法3：Controller级别的CORS
```csharp
[ApiController]
[Route("api/[controller]")]
[EnableCors("AllowSpecificOrigins")]  // 可以为特定控制器启用
public class UsersController : ControllerBase
{
    [HttpGet]
    [EnableCors("PublicApi")]  // 或为特定Action启用不同策略
    public async Task<ActionResult<IEnumerable<User>>> Get()
    {
        return Ok(await _userService.GetAllAsync());
    }
}
```

#### 方法4：Nginx反向代理层处理CORS（生产环境推荐）
```nginx
server {
    listen 80;
    server_name api.example.com;

    location / {
        # Nginx层面添加CORS头，减轻应用服务器负担
        if ($request_method = 'OPTIONS') {
            add_header 'Access-Control-Allow-Origin' '*';
            add_header 'Access-Control-Allow-Methods' 'GET, POST, PUT, DELETE, OPTIONS';
            add_header 'Access-Control-Allow-Headers' 'DNT,X-CustomHeader,Keep-Alive,User-Agent,X-Requested-With,If-Modified-Since,Cache-Control,Content-Type,Authorization';
            add_header 'Access-Control-Max-Age' 1728000;
            add_header 'Content-Type' 'text/plain; charset=utf-8';
            add_header 'Content-Length' 0;
            return 204;
        }

        proxy_pass http://127.0.0.1:5000;
        
        # 非预检请求也添加响应头
        add_header Access-Control-Allow-Origin * always;
    }
}
```

### 预防措施
- 生产环境明确指定允许的Origin，不要使用 `AllowAnyOrigin`
- 携带Cookie时必须指定具体Origin且不能使用通配符 `*`
- 将CORS中间件放在认证和授权之前
- 使用SameSite属性防止CSRF

## 问题2：Blazor WASM 加载失败

### 问题描述
Blazor WebAssembly应用无法加载，blazor.boot.js返回404或加载超时。

### 错误现象

```text
Failed to find a valid digest in the 'integrity' attribute for resource '/_framework/blazor.webassembly.js'
CRITICAL: Unhandled exception in circuit handler
blazor.boot.js:1 Failed to load resource: net::ERR_CONNECTION_REFUSED
```

### 解决方案

#### 方法1：检查基础路径配置
```html
<!-- wwwroot/index.html -->
<!DOCTYPE html>
<html>

<head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>My Blazor App</title>
    
    <!-- ⚠️ base href 必须与应用部署路径一致 -->
    <base href="/" />  <!-- 如果部署在子目录则改为 /subpath/ -->
</head>

<body>
    <!-- 正确引用Blazor资源 -->
    <div id="app">
        <svg class="loading-progress">
            <circle cx="50%" cy="50%" r="40%"></circle>
            <circle cx="50%" cy="50%" r="40%"></circle>
        </svg>
        <span>Loading...</span>
    </div>

    <div id="blazor-error-ui" class="hidden"></div>

    <script src="_framework/blazor.webassembly.js" autostart="false"></script>
    <script>
        Blazor.start({
            loadBootResource: function (type, name, defaultUri, integrity) {
                if (type === 'dotnetjs') {
                    // 自定义加载逻辑（如从CDN加载）
                }
                return { type: 'dotnetjs', response: fetch(defaultUri, {
                    cache: 'no-store',
                    integrity: integrity,
                    headers: { 'Custom-Header': 'value' }
                }) };
            }
        });
    </script>
</body>
</html>
```

#### 方法2：发布配置
```xml
<!-- .csproj -->
<Project Sdk="Microsoft.NET.Sdk.BlazorWebAssembly">

  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
    <!-- 启用压缩以减小下载体积 -->
    <BlazorEnableCompression>true</BlazorEnableCompression>
  </PropertyGroup>

  <ItemGroup>
    <!-- 确保包含运行时 -->
    <RuntimeIdentifier>browser-wasm</RuntimeIdentifier>
  </ItemGroup>

</Project>
```

```bash
# 发布命令
dotnet publish -c Release -o ./publish --runtime browser-wasm --self-contained true
# 将publish目录内容复制到wwwroot即可
```

#### 方法3：IIS/Nginx配置支持WASM MIME类型
```xml
<!-- web.config 中添加MIME类型映射 -->
<staticContent>
    <mimeMap fileExtension=".wasm" mimeType="application/wasm" />
    <mimeMap fileExtension=".dll" mimeType="application/octet-stream" />
    <mimeMap fileExtension=".json" mimeType="application/json" />
    <remove fileExtension=".dat" />
    <mimeMap fileExtension=".dat" mimeType="application/octet-stream" />
    <remove fileExtension=".blat" />
    <mimeMap fileExtension=".blat" mimeType="application/octet-stream" />
</staticContent>
```

```nginx
# Nginx配置
server {
    listen 80;
    server_name blazor.example.com;

    root /var/www/blazor-app/wwwroot;
    index index.html;

    # WASM MIME类型
    types {
        application/wasm wasm;
        application/octet-stream dll dat blat;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }

    # 禁用缓存框架文件（开发用）
    location ~* \.(js|css|wasm|dll)$ {
        expires -1;
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }
}
```

## 问题3：前端路由刷新 404

### 问题描述
Vue/React等SPA应用刷新页面时返回404。

### 解决方案

#### IIS 配置
```xml
<!-- web.config 放在wwwroot根目录 -->
<configuration>
  <system.webServer>
    <rewrite>
      <rules>
        <rule name="SPA Fallback" stopProcessing="true">
          <match url=".*" />
          <conditions logicalGroupingMatchAll>
            <add input="{REQUEST_FILENAME}" matchType="IsFile" negate="true" />
            <add input="{REQUEST_FILENAME}" matchType="IsDirectory" negate="true" />
          </conditions>
          <action type="Rewrite" url="/index.html" />
        </rule>
      </rules>
    </rewrite>
  </system.webServer>
</configuration>
```

#### Nginx 配置
```nginx
location / {
    try_files $uri $uri/ /index.html;  # SPA fallback
}

# 如果有API代理
location /api/ {
    proxy_pass http://127.0.0.1:5000;
}
```

#### Kestrel 中间件方案
```csharp
// Program.cs
app.MapFallbackToFile("/index.html");  // .NET 6+ 内置支持
```

## 问题4：WebSocket 连接失败（SignalR）

### 解决方案

```csharp
// Program.cs
builder.Services.AddSignalR();

// Hub配置
builder.Services.AddHubOptions<ChatHub>(options =>
{
    options.ClientTimeoutInterval = TimeSpan.FromSeconds(30);
    options.HandshakeTimeout = TimeSpan.FromSeconds(15);
    options.KeepAliveInterval = TimeSpan.FromSeconds(15);
    options.MaximumReceiveMessageSize = 1024 * 1024;  // 1MB
});

// Hub实现
[Authorize]
public class ChatHub : Hub
{
    public override async Task OnConnectedAsync()
    {
        var userId = Context.UserIdentifier;
        await Groups.AddToGroupAsync(Context.ConnectionId, $"User_{userId}");
        await base.OnConnectedAsync();
    }

    public async Task SendMessage(string message)
    {
        var user = Context.User?.Identity?.Name ?? "Anonymous";
        await Clients.All.SendAsync("ReceiveMessage", user, message);
    }
}

// JavaScript客户端
const connection = new signalR.HubConnectionBuilder()
    .withUrl("/chatHub", {
        accessTokenFactory: () => getAccessToken(),  // 认证token
        skipNegotiation: false,
        transport: signalR.HttpTransportType.WebSockets | signalR.HttpTransportType.LongPolling
    })
    .withAutomaticReconnect([0, 2000, 10000, 30000])  // 重试间隔
    .configureLogging(signalR.LogLevel.Information)
    .build();

connection.onclose((error) => {
    console.log(`Connection closed: ${error}`);
});
```

#### Nginx WebSocket 支持
```nginx
location /chatHub {
    proxy_pass http://127.0.0.1:5000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;  # 长连接超时设置
    proxy_send_timeout 3600s;
}
```

## 问题5：JWT Token 过期处理

### 解决方案

```typescript
// 前端 Axios拦截器
import axios from 'axios';

const apiClient = axios.create({
    baseURL: import.meta.env.VITE_API_URL || 'http://localhost:5000',
    timeout: 15000,
    withCredentials: true
});

// 请求拦截器：自动附加Token
apiClient.interceptors.request.use(config => {
    const token = localStorage.getItem('access_token');
    if (token) {
        config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
});

// 响应拦截器：处理401自动刷新Token
apiClient.interceptors.response.use(
    response => response,
    async error => {
        const originalRequest = error.config;

        if (error.response?.status === 401 && !originalRequest._retry) {
            originalRequest._retry = true;

            try {
                const refreshToken = localStorage.getItem('refresh_token');
                const response = await axios.post('/api/auth/refresh', { token: refreshToken });
                
                const newToken = response.data.accessToken;
                localStorage.setItem('access_token', newToken);
                
                originalRequest.headers.Authorization = `Bearer ${newToken}`;
                return apiClient(originalRequest);
            } catch (refreshError) {
                localStorage.removeItem('access_token');
                window.location.href = '/login';
                return Promise.reject(refreshError);
            }
        }

        return Promise.reject(error);
    }
);

export default apiClient;
```

```csharp
// 后端Token刷新接口
[HttpPost("refresh")]
public async Task<IActionResult> RefreshToken([FromBody] RefreshTokenRequest request)
{
    var principal = _jwtService.GetPrincipalFromExpiredToken(request.Token);
    if (principal == null)
        return BadRequest("Invalid token");

    var newToken = _jwtService.GenerateToken(principal.Claims);
    return Ok(new { accessToken = newToken, expiresIn = 3600 });
}
```

## 问题6：表单验证消息不显示

### 解决方案

```razor
<!-- Blazor 组件中显示验证消息 -->
<EditForm Model="@userModel" OnValidSubmit="@HandleValidSubmit">
    <DataAnnotationsValidator />

    <div class="form-group">
        <label>用户名</label>
        <InputText @bind-Value="userModel.UserName" class="form-control" />

    </div>

    <ValidationSummary class="text-danger" />

    <button type="submit" class="btn btn-primary">提交</button>
</EditForm>

@code {
    private UserModel userModel = new();

    private async Task HandleValidSubmit()
    {
        // 表单验证通过后才执行
        await _userService.CreateAsync(userModel);
    }
}
```

```typescript
// React + React Hook Form + MUI
import { useForm } from 'react-hook-form';

function UserForm({ onSubmit }) {
    const { register, handleSubmit, formState: { errors } } = useForm({
        mode: 'onBlur',
        defaultValues: { userName: '', email: '' }

    return (

            <TextField
                label="用户名"
```

## 总结

本文档涵盖了ASP.NET前端集成的核心问题：

| 类别 | 关键要点 |
|------|---------|
| CORS | 中件件顺序、预检请求、凭证 |
| Blazor WASM | MIME类型、base href、压缩 |
| SPA路由 | IIS重写规则、Nginx try_files |
| SignalR | WebSocket代理、重连机制 |
| JWT | 刷新Token流程、Axios拦截器 |
| 表单验证 | DataAnnotations、React Hook Form |

**核心原则**：
1. **CORS中间件必须放在认证之前**
2. **SPA fallback要排除API路径**
3. **WebSocket需要特殊的代理配置**
4. **Token过期要有自动刷新机制**
5. **前后端统一错误码规范**
