# ASP.NET 部署相关问题解答

> **适用场景**：将ASP.NET应用部署到IIS、Docker、Linux或云平台时遇到的问题
>
> **目标读者**：需要进行生产环境部署、CI/CD配置、容器化部署的开发者和运维人员

## 问题1：IIS 部署 500.19 错误（配置文件问题）

### 问题描述
在IIS上部署ASP.NET Core应用时出现500.19错误，通常与web.config配置有关。

### 错误现象

```text
HTTP Error 500.19 - Internal Server Error
The requested page cannot be accessed because the related configuration data for the page is invalid.
Error Code: 0x8007000d
Config Error: Configuration file is not well-formed XML
Module: IIS Web Core
```

### 原因分析

1. **web.config格式错误**：XML语法错误或标签未闭合
2. **ASP.NET Core模块缺失**：IIS未安装ASP.NET Core Hosting Bundle
3. **applicationHost.config权限问题**：无法读取IIS配置
4. **重复的配置节**：web.config中有重复的system.webServer节点
5. **路径太长**：Windows路径超过260字符限制

### 解决方案

#### 方法1：安装ASP.NET Core Hosting Bundle
```bash
# 下载并安装 Hosting Bundle
# https://dotnet.microsoft.com/download/dotnet/8.0
# 选择 "Hosting Bundle" 下载项

# 安装后重启IIS
iisreset /restart

# 验证安装
dotnet --list-runtimes  # 应该显示已安装的运行时
```

#### 方法2：修复web.config
```xml
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <location path="." inheritInChildApplications="false">
    <system.webServer>
      <handlers>
        <add name="aspNetCore" path="*" verb="*" modules="AspNetCoreV2"
             resourceType="Unspecified" />
      </handlers>
      <aspNetCore processPath="dotnet"
                  arguments=".\MyApp.dll"
                  stdoutLogEnabled="false"
                  stdoutLogFile=".\logs\stdout"
                  hostingModel="inprocess">
        <environmentVariables>
          <environmentVariable name="ASPNETCORE_ENVIRONMENT" value="Production" />
        </environmentVariables>
      </aspNetCore>
    </system.webServer>
  </location>
</configuration>
```

#### 方法3：检查IIS配置权限
```powershell
# 以管理员身份运行
# 检查IUSRS/IIS_IUSRS组对应用目录有读取权限
icacls "C:\inetpub\wwwroot\myapp" /grant "IIS_IUSRI:(OI)(CI)R" /T

# 检查applicationhost.config
notepad "%windir%\System32\inetsrv\config\applicationhost.config"

# 重置IIS（最后手段）
%windir%\system32\inetsrv\appcmd.exe recycle apppool /apppool:"MyAppPool"
```

## 问题2：IIS 部署 502.5 错误（ANCM 问题）

### 问题描述
应用进程崩溃导致502.5错误。

### 错误现象

```text
HTTP Error 502.5 - ANCM Out-Of-Process Startup Failure
Common causes:
- The application failed to start
- The application started but then crashed
- The application started but cannot listen on the given port
```

### 解决方案

#### 方法1：查看详细日志
```bash
# 日志位置：
# Windows Event Viewer → Windows Logs → Application
# 或直接查看 stdout 日志文件
type C:\inetpub\wwwroot\myapp\logs\stdout\*.log

# 启用详细日志（修改web.config）
<aspNetCore ... stdoutLogEnabled="true" stdoutLogFile=".\logs\stdout" />
```

#### 方法2：常见原因排查
```csharp
// Program.cs 中添加启动日志
try
{
    var app = builder.Build();
    app.Run();
}
catch (Exception ex)
{
    // 写入文件以便排查
    File.WriteAllText("startup-error.log", $"{DateTime.Now}: {ex}");
    throw;
}

// 检查清单：
// 1. 运行时是否安装？ dotnet --list-runtimes
// 2. 端口是否被占用？ netstat -ano | findstr :5000
// 3. 数据库连接字符串是否正确？
// 4. 必需的环境变量是否设置？
```

### 相关知识点
- [ANCM故障排除](https://docs.microsoft.com/zh-cn/aspnet/core/test/troubleshoot-azure-iis?view=aspnetcore-8.0)

## 问题3：Docker 容器启动失败

### 问题描述
Docker容器启动后立即退出，返回非零退出码。

### 错误现象

```text
docker logs mycontainer
# Exit code 1: 应用程序异常
# Exit code 137: OOM killed (内存不足被杀)
# Exit code 139: Segmentation fault
```

### 解决方案

#### 方法1：查看容器日志
```bash
docker logs -f --tail 100 mycontainer

# 进入容器内部调试
docker run -it --rm --entrypoint sh myimage
```

#### 方法2：常见的Exit code及解决
| Exit Code | 含义 | 解决方案 |
|-----------|------|---------|
| 0 | 正常退出 | - |
| 1 | 应用错误 | 查看日志 |
| 137 | OOM Kill | 增加 memory limit |
| 139 | Segfault | 检查依赖库兼容性 |

#### 方法3：健康检查和重启策略
```yaml
# docker-compose.yml
services:
  web:
    image: myapp:latest
    restart: unless-stopped  # 自动重启策略
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s
    deploy:
      resources:
        limits:
          memory: 512M  # 内存限制
        reservations:
          memory: 256M
```

### 相关知识点
- [Docker容器退出码](https://docs.docker.com/reference/run/#exit-status)
- [Docker Compose重启策略](https://docs.docker.com/compose/startup-order/)

## 问题4：环境变量未正确注入

### 问题描述
通过Docker/Kubernetes设置的环境变量在应用中读取不到。

### 解决方案

```csharp
// Program.cs - 调试环境变量
var builder = WebApplication.CreateBuilder(args);

// 开发环境：打印所有环境变量（调试用）
if (builder.Environment.IsDevelopment())
{
    foreach (DictionaryEntry env in Environment.GetEnvironmentVariables())
    {
        if (env.Key.ToString().StartsWith("MyApp_"))
            Console.WriteLine($"{env.Key}={env.Value}");
    }
}

// 使用 IConfiguration 读取（推荐方式）
var mySetting = builder.Configuration["MyApp:SomeSetting"]
               ?? builder.Configuration["SOME_SETTING"]  // Docker环境变量自动映射
               ?? "default-value";

builder.Services.Configure<AppSettings>(builder.Configuration.GetSection("MyApp"));
```

```bash
# Docker 环境变量命名规则：
# MyApp__SomeSetting → 配置中的 MyApp:SomeSetting
# SOME_SETTING → 根级配置中的 SomeSetting

docker run -e MyApp__ConnectionString="Server=db;..." myapp
```

## 问题5：静态文件 404

### 问题描述
部署后静态文件（CSS、JS、图片）返回404。

### 解决方案

```csharp
// Program.cs
var app = builder.Build();

// ✅ 必须显式启用静态文件中间件
app.UseStaticFiles();           // wwwroot 目录
app.UseStaticFiles(new StaticFileOptions
{
    FileProvider = new PhysicalFileProvider(
        Path.Combine(builder.Environment.ContentRootPath, "Uploads")),
    RequestPath = "/uploads"     // 自定义路径
});

// ✅ 生产环境添加缓存头
if (!app.Environment.IsDevelopment())
{
    app.UseStaticFiles(new StaticFileOptions
    {
        OnPrepareResponse = ctx =>
        {
            var headers = ctx.Context.Response.Headers;
            var contentType = headers.ContentType;
            if (contentType != null && contentType.ToString().StartsWith("image/"))
            {
                headers.CacheControl = "public,max-age=31536000,immutable";
                headers[HeaderNames.Expires] = DateTime.UtcNow.AddDays(365).ToString("R");
            }
        }
    });
}
```

```html
<!-- HTML中引用静态文件的正确方式 -->
<link rel="stylesheet" href="~/css/site.css" asp-append-version="true" />
<script src="~/js/app.js" asp-append-version="true"></script>
<!-- ~/ 表示 wwwroot 根目录 -->
<!-- asp-append-version 自动附加版本号防止缓存 -->
```

## 问题6：HTTPS 证书问题

### 解决方案

```bash
# Let's Encrypt（推荐用于公网域名）
# 使用 Certbot
certbot --nginx -d mydomain.com -d www.mydomain.com

# 自签名证书（开发/内网使用）
dotnet dev-certs https --trust

# Docker中使用HTTPS
# 方式A：挂载证书卷
volumes:
  - ./certs:/https:ro

# 方式B：使用环境变量指定证书路径
environment:
  - ASPNETCORE_URLS=https://+:443;http://+:80
  - ASPNETCORE_HTTPS_PORT=443
  - ASPNETCORE_Kestrel__Certificates__Default__Path=/https/aspnetapp.pfx
  - ASPNETCORE_Kestrel__Certificates__Default__Password=your-password
```

## 问题7：端口被占用

### 解决方案

```bash
# 查找占用端口的进程
netstat -ano | findstr :80
# 或
lsof -i :80  # Linux/Mac

# 终止进程
taskkill /PID <pid> /F
kill -9 <pid>  # Linux

# Docker 映射端口冲突
# 修改 docker-compose.yml 的 ports 映射
ports:
  - "8080:80"   # 将容器的80映射到主机的8080
```

## 问题8：反向代理配置（Nginx）

### Nginx 配置示例

```nginx
server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection keep-alive;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # 大文件上传支持
        client_max_body_size 100M;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        
        # WebSocket 支持
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
    
    # 静态文件缓存
    location ~* \.(css|js|png|jpg|jpeg|gif|ico|svg|woff|woff2)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

## 总结

本文档涵盖了ASP.NET部署的核心问题：

| 类别 | 关键要点 |
|------|---------|
| IIS部署 | Hosting Bundle安装、web.config修复、权限配置 |
| Docker容器 | 日志排查、内存限制、重启策略 |
| 环境变量 | 注入顺序、命名规范、Configuration API |
| 静态文件 | UseStaticFiles中间件、缓存策略 |
| HTTPS | Let's Encrypt、自签名证书 |
| 反向代理 | Nginx配置、WebSocket支持 |

**核心原则**：
1. **始终查看日志**：无论是IIS还是Docker，日志是第一手资料
2. **本地能跑通再部署**：确保 `dotnet publish` 的输出能在本地正常运行
3. **环境变量优于硬编码**：连接字符串等敏感信息通过环境变量注入
4. **监控健康检查**：配置/readiness/liveness探针
5. **渐进式发布**：蓝绿部署或金丝雀发布降低风险
