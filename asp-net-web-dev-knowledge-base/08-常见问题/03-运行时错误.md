## 问题1：500 Internal Server Error 通用排查思路

### 问题描述
客户端收到HTTP 500状态码，服务器发生了未处理的异常但具体原因不明。

### 错误现象

```text
HTTP/1.1 500 Internal Server Error
Content-Type: text/html; charset=utf-8
Server: Microsoft-IIS/10.0

浏览器显示：
"500 - Internal Server Error"
或
"Sorry, there was a problem with your request"
```

### 原因分析

1. **未捕获的异常**：代码中抛出了未被try-catch处理的异常
2. **中间件配置错误**：某个中间件在请求处理管道中失败
3. **依赖注入失败**：服务无法创建或解析
4. **配置缺失**：缺少必需的配置项（连接字符串、API密钥等）
5. **数据库连接失败**：数据库不可达或凭据错误
6. **文件系统权限**：无法读写必要的文件或目录
7. **资源耗尽**：内存不足、线程池耗尽、句柄泄漏
8. **第三方服务不可用**：外部API调用超时或返回错误

### 解决方案

#### 方法1：启用详细错误信息（开发环境）
```csharp
// Program.cs 或 Startup.cs
var builder = WebApplication.CreateBuilder(args);

// 开发环境显示详细异常信息
if (builder.Environment.IsDevelopment())
{
    builder.WebHost.UseSetting("detailedErrors", "true");
}

var app = builder.Build();

// 开发环境使用异常页面
if (app.Environment.IsDevelopment())
{
    app.UseDeveloperExceptionPage();  // 显示完整的堆栈跟踪
}
else
{
    // 生产环境使用自定义错误页面
    app.UseExceptionHandler("/Error");
    app.UseHsts();
}
```

#### 方法2：全局异常处理中间件
```csharp
/// <summary>
/// 全局异常处理中间件
/// </summary>
public class ExceptionHandlingMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<ExceptionHandlingMiddleware> _logger;

    public ExceptionHandlingMiddleware(RequestDelegate next, ILogger<ExceptionHandlingMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        try
        {
            await _next(context);
        }
        catch (Exception ex)
        {
            await HandleExceptionAsync(context, ex);
        }
    }

    private async Task HandleExceptionAsync(HttpContext context, Exception exception)
    {
        _logger.LogError(exception, "An unhandled exception occurred: {Message}", exception.Message);

        var response = context.Response;
        response.ContentType = "application/json";

        var errorResponse = new ErrorResponse();

        switch (exception)
        {
            case BadRequestException badRequest:
                response.StatusCode = (int)HttpStatusCode.BadRequest;
                errorResponse.Message = badRequest.Message;
                errorResponse.Errors = badRequest.Errors;
                break;

            case NotFoundException notFound:
                response.StatusCode = (int)HttpStatusCode.NotFound;
                errorResponse.Message = notFound.Message;
                break;

            case UnauthorizedAccessException:
                response.StatusCode = (int)HttpStatusCode.Unauthorized;
                errorResponse.Message = "Unauthorized";
                break;

            case DbUpdateException dbEx:
                response.StatusCode = (int)HttpStatusCode.InternalServerError;
                errorResponse.Message = "Database operation failed";
                errorResponse.Details = IsDevelopment() ? dbEx.InnerException?.Message : null;
                break;

            default:
                response.StatusCode = (int)HttpStatusCode.InternalServerError;
                errorResponse.Message = IsDevelopment() ? exception.Message : "An internal error occurred";
                errorResponse.Details = IsDevelopment() ? exception.StackTrace : null;
                break;
        }

        var result = JsonSerializer.Serialize(errorResponse,
            new JsonSerializerOptions { PropertyNamingPolicy = JsonNamingPolicy.CamelCase });
        await response.WriteAsync(result);
    }

    private bool IsDevelopment()
    {
        return true; // 简化示例，实际应从DI获取IHostEnvironment
    }
}

// 注册中间件（必须在其他中间件之前）
app.UseMiddleware<ExceptionHandlingMiddleware>();
```

## 问题2：NullReferenceException（空引用异常）

### 问题描述
访问空引用对象的成员时抛出NullReferenceException，这是.NET中最常见的运行时异常。

### 错误现象

```text
System.NullReferenceException: Object reference not set to an instance of an object.
   at MyProject.Services.OrderService.ProcessOrder(Order order) in C:\...\OrderService.cs:line 42
```

### 原因分析

1. **对象为null但被访问**：变量赋值为null后直接调用方法或属性
2. **集合元素为null**：List/T数组中的元素可能是null
3. **LINQ查询结果为null**：FirstOrDefault、SingleOrDefault可能返回null
4. **依赖注入解析失败**：GetService返回null（非必需服务）
5. **配置值为null**：appsettings中的值不存在或为null
6. **数据库查询结果null**：EF Core Find/FirstOrDefault返回null

### 解决方案

#### 方法1：使用null条件运算符（最常用）
```csharp
public class UserService
{
    public UserDto? GetUser(int id)
    {
        var user = _userRepository.FindById(id);

        if (user == null) return null;

        return new UserDto
        {
            Id = user.Id,
            Name = user.Name ?? "Unknown",
            Email = user.Profile?.Email ?? "no-email@example.com",
            Address = user.Address?.City ?? "N/A",
            Phone = user.Contacts?.FirstOrDefault(c => c.IsPrimary)?.Number ?? ""
        };
    }
}
```

#### 方法2：使用模式匹配增强null检查
```csharp
public void ProcessOrder(Order? order)
{
    if (order is not null)
    {
        Console.WriteLine($"Processing order {order.Id}");
        ProcessItems(order.Items);
    }
    else
    {
        _logger.LogWarning("Received null order");
    }

    // switch表达式
    var status = order switch
    {
        null => OrderStatus.Unknown,
        { Items.Count: 0 } => OrderStatus.Empty,
        { } => OrderStatus.Normal
    };
}
```

#### 方法3：使用Guard Clause模式
```csharp
public static class Guard
{
    public static T NotNull<T>(T value, [CallerArgumentExpression("value")] string? paramName = null)
    {
        return value ?? throw new ArgumentNullException(paramName);
    }
}

// 使用
public void ProcessData([NotNull] object data)
{
    ArgumentNullException.ThrowIfNull(data);
    // 处理数据...
}
```

### 预防措施
- 启用可空引用类型（`<Nullable>enable</Nullable>`）在编译期检测潜在的null引用
- 使用 `[NotNull]`, `[MaybeNull]` 特性标注API契约
- 遵循"Fail Fast"原则：尽早验证输入参数
- 为所有公共API编写包含null参数的测试用例

## 问题3：InvalidOperationException（操作无效异常）

### 问题描述
当前状态下不允许执行的操作被尝试执行。

### 错误现象

```text
System.InvalidOperation Exception: Collection was modified; enumeration operation may not execute.
System.InvalidOperation Exception: The operation cannot be completed because the DbContext has been disposed.
System.InvalidOperation Exception: A second operation started on this context before a previous operation completed.
```

### 原因分析

1. **遍历时修改集合**：foreach循环中修改了正在遍历的集合
2. **已释放的对象**：使用了已被Dispose的对象
3. **并发DbContext操作**：同一DbContext实例同时执行多个异步操作
4. **状态机冲突**：对象处于不正确的状态

### 解决方案

#### 方法1：解决集合修改问题
```csharp
// ❌ 错误：遍历时删除元素
foreach (var item in items)
{
    if (item.ShouldRemove()) items.Remove(item);  // InvalidOperationException!
}

// ✅ 正确：收集要删除的项目再批量删除
var toRemove = items.Where(i => i.ShouldRemove()).ToList();
foreach (var item in toRemove) items.Remove(item);

// ✅ 或使用RemoveAll
items.RemoveAll(item => item.ShouldRemove());
```

#### 方法2：正确管理DbContext生命周期
```csharp
// ❌ 错误：将DbContext作为Singleton注入
services.AddSingleton<AppDbContext>(...);

// ✅ 正确：使用Scoped生命周期
services.AddDbContext<AppDbContext>(options =>
    options.UseSqlServer(connectionString),
    ServiceLifetime.Scoped);

// BackgroundService中使用IServiceScopeFactory
public class BackgroundWorkerService : BackgroundService
{
    private readonly IServiceScopeFactory _scopeFactory;

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            using var scope = _scopeFactory.CreateScope();
            var dbContext = scope.ServiceProvider.GetRequiredService<AppDbContext>();
            
            try
            {
                await ProcessPendingOrdersAsync(dbContext, stoppingToken);
            }
            finally
            {
                // scope结束时DbContext会被正确dispose
            }
            
            await Task.Delay(TimeSpan.FromMinutes(5), stoppingToken);
        }
    }
}
```

#### 方法3：避免并发DbContext操作
```csharp
// ❌ 错误：并发执行多个异步操作
public async Task<List<Order>> GetOrdersAndUsersAsync()
{
    var ordersTask = _dbContext.Orders.ToListAsync();
    var usersTask = _dbContext.Users.ToListAsync();  // 同一DbContext不能并发！
    await Task.WhenAll(ordersTask, usersTask);
    return ordersTask.Result;
}

// ✅ 正确：顺序执行
public async Task<(List<Order>, List<User>)> GetDataAsync()
{
    var orders = await _dbContext.Orders.ToListAsync();
    var users = await _dbContext.Users.ToListAsync();
    return (orders, users);
}

// ✅ 或使用SplitQuery（EF Core 5+）
public async Task<PagedResult<OrderDto>> GetPagedOrdersAsync(OrderFilter filter)
{
    var query = _dbContext.Orders
        .Include(o => o.User)
        .AsSplitQuery()  // 将一个查询拆分为多个SQL查询
        .Where(BuildPredicate(filter));
    // ...
}
```

### 预防措施
- 了解每种集合类型的线程安全性
- 遵循DbContext的最佳实践（Scoped生命周期、不共享、不缓存）
- 使用状态机模式管理复杂的状态转换
- 单元测试覆盖边界条件和非法状态

## 问题4：ArgumentException / ArgumentOutOfRangeException

### 问题描述
传递给方法的参数不合法或超出有效范围。

### 错误现象

```text
System.ArgumentException: Value does not fall within the expected range.
System.ArgumentOutOfRangeException: Specified argument was out of the range of valid values.
System.ArgumentNullException: Value cannot be null.
```

### 原因分析

1. **空字符串或空白字符串**：传入了不符合要求的字符串
2. **负数索引**：数组/列表索引为负数或超出长度
3. **枚举值无效**：传入的枚举值不在定义范围内
4. **日期范围错误**：开始日期晚于结束日期
5. **数值范围溢出**：超出方法允许的最大/最小值

### 解决方案

#### 方法1：使用参数验证辅助方法
```csharp
public static class Guard
{
    public static T NotNull<T>(T value, [CallerArgumentExpression("value")] string? paramName = null)
        => value ?? throw new ArgumentNullException(paramName);

    public static string NotNullOrWhiteSpace(string? value, [CallerArgumentExpression("value")] string? paramName = null)
        => string.IsNullOrWhiteSpace(value)
            ? throw new ArgumentException($"{paramName} cannot be null or whitespace.", paramName)
            : value;

    public static int Positive(int value, [CallerArgumentExpression("value")] string? paramName = null)
        => value <= 0
            ? throw new ArgumentOutOfRangeException(paramName, value, $"{paramName} must be positive.")
            : value;

    public static int InRange(int value, int min, int max, [CallerArgumentExpression("value")] string? paramName = null)
        => value < min || value > max
            ? throw new ArgumentOutOfRangeException(paramName, value, $"{paramName} must be between {min} and {max}.")
            : value;
}

// 使用示例
public Order CreateOrder(string customerName, int quantity, decimal unitPrice)
{
    Guard.NotNullOrWhiteSpace(customerName);
    Guard.Positive(quantity);
    Guard.Positive(unitPrice);
    
    return new Order(customerName, quantity, unitPrice, DateTime.UtcNow);
}
```

#### 方法2：使用Data Annotations进行模型验证

## 问题5：TimeoutException（超时异常）

### 问题描述
操作耗时超过了预设的超时限制。

### 错误现象

```text
System.TimeoutException: The operation has timed out.
System.Threading.Tasks.TaskCanceledException: A task was canceled.
SqlException: Execution Timeout Expired.
```

### 原因分析

1. **网络延迟高**：HTTP请求或数据库查询在网络状况差时超时
2. **数据库查询慢**：缺少索引或复杂的JOIN导致查询时间过长
3. **外部API响应慢**：调用的第三方服务响应缓慢
4. **死锁**：资源竞争导致等待无限延长
5. **阻塞操作**：同步等待异步操作完成

### 解决方案

#### 方法1：合理配置各种超时
```csharp
public static IServiceCollection ConfigureTimeouts(this IServiceCollection services, IConfiguration config)
{
    services.AddHttpClient("ExternalApi", client =>
    {
        client.Timeout = TimeSpan.FromSeconds(30);
    })
    .ConfigurePrimaryHttpMessageHandler(() => new SocketsHttpHandler
    {
        ConnectTimeout = TimeSpan.FromSeconds(5),
        PooledConnectionLifetime = TimeSpan.FromMinutes(15)
    })
    .AddPolicyHandler(GetRetryPolicy())
    .AddPolicyHandler(GetCircuitBreakerPolicy());

    services.AddDbContext<AppDbContext>(options =>
        options.UseSqlServer(config.GetConnectionString("Default"),
            sqlOptions => sqlOptions.CommandTimeout(30)));

    return services;
}

private static IAsyncPolicy<HttpResponseMessage> GetRetryPolicy()
{
    return HttpPolicyExtensions
        .HandleTransientHttpError()
        .Or<TimeoutException>()
        .WaitAndRetryAsync(3, retryAttempt => 
            TimeSpan.FromSeconds(Math.Pow(2, retryAttempt)));
}
```

#### 方法2：使用CancellationToken统一取消
```csharp
public async Task<OrderResult> ProcessOrderAsync(int orderId, CancellationToken ct = default)
{
    using var cts = CancellationTokenSource.CreateLinkedTokenSource(ct);
    cts.CancelAfter(TimeSpan.FromSeconds(60));  // 整个流程最多60秒

    var order = await _orderRepository.GetByIdAsync(orderId, cts.Token);
    if (order == null) throw new NotFoundException(nameof(Order), orderId);

    // 步骤1：支付（最多30秒）
    using var paymentCts = CancellationTokenSource.CreateLinkedTokenSource(cts.Token);
    paymentCts.CancelAfter(TimeSpan.FromSeconds(30));

    try
    {
        var paymentResult = await _paymentService.ProcessAsync(order, paymentCts.Token);
    }
    catch (OperationCanceledException) when (!ct.IsCancellationRequested)
    {
        throw new TimeoutException("Payment processing timed out.");
    }

    // 步骤2：发送确认邮件（最多10秒）
    using var emailCts = CancellationTokenSource.CreateLinkedTokenSource(cts.Token);
    emailCts.CancelAfter(TimeSpan.FromSeconds(10));
    await _emailService.SendConfirmationAsync(order, emailCts.Token);

    return OrderResult.Success(order);
}
```

#### 方法3：优雅降级策略
```csharp
public async Task<DataResult> GetDataWithFallbackAsync(string key, CancellationToken ct = default)
{
    // 尝试1：从缓存读取
    var cached = await _cache.GetAsync<DataResult>(key, ct);
    if (cached != null) return cached;

    // 尝试2：从主数据源读取
    try
    {
        using var cts = CancellationTokenSource.CreateLinkedTokenSource(ct);
        cts.CancelAfter(TimeSpan.FromSeconds(5));
        var data = await _primarySource.GetDataAsync(key, cts.Token);
        _ = _cache.SetAsync(key, data, TimeSpan.FromMinutes(5));
        return data;
    }
    catch (TimeoutException)
    {
        _logger.LogWarning("Primary source timed out for key: {Key}", key);
    }

    // 尝试3：从备用数据源读取（降级）
    try
    {
        using var cts = CancellationTokenSource.CreateLinkedTokenSource(ct);
        cts.CancelAfter(TimeSpan.FromSeconds(10));
        return await _secondarySource.GetDataAsync(key, cts.Token);
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, "Fallback source also failed for key: {Key}", key);
        throw;
    }
}
```

### 预防措施
- 为所有外部依赖设置合理的超时时间
- 使用 Polly 等库实现重试、断路器、舱壁隔离等弹性模式
- 使用 CancellationToken 支持协作式取消
- 监控P99/P95响应时间来调整超时阈值

## 问题6：TaskCanceledException（任务取消异常）

### 问题描述
异步任务在完成前被取消了。

### 错误现象

```text
System.Threading.Tasks.TaskCanceledException: A task was canceled.
System.OperationCanceledException: The operation was canceled.
```

### 原因分析

1. **用户主动取消**：用户点击了取消按钮
2. **超时触发取消**：CancellationTokenSource.CancelAfter到期
3. **前端断开连接**：浏览器关闭或导航离开
4. **服务器关停**：应用收到SIGTERM信号正在关闭

### 解决方案

#### 方法1：正确处理TaskCanceledException
```csharp
public async Task<LongRunningOperationResult> ExecuteLongOperationAsync(
    int operationId, CancellationToken ct = default)
{
    try
    {
        var result = await PerformWorkAsync(operationId, ct);
        return result;
    }
    catch (OperationCanceledException) when (ct.IsCancellationRequested)
    {
        _logger.LogWarning("Operation {OperationId} was cancelled by user/shutdown", operationId);
        throw;
    }
    catch (OperationCanceledException)
    {
```

## 问题7：DbUpdateException / DbUpdateConcurrencyException

### 问题描述

### 错误现象

```text
Microsoft.EntityFrameworkCore.DbUpdateException: An error occurred while updating the entries.
 ---> Violation of UNIQUE KEY constraint 'IX_Users_Email'.
Microsoft.EntityFrameworkCore.DbUpdateConcurrencyException: The database operation was expected to affect 1 row(s) but actually affected 0 row(s).
```

### 原因分析

1. **唯一约束违反**：插入了重复的唯一键值
2. **外键约束违反**：引用了不存在的主键
3. **非空约束违反**：将null插入NOT NULL列
4. **并发冲突**：乐观并发检测到数据已被其他事务修改

#### 方法1：处理唯一约束违反
```csharp
public async Task<Result<User>> CreateUserAsync(CreateUserRequest request)
{
    if (await _userRepository.ExistsByEmailAsync(request.Email))
        return Result.Failure<User>($"Email '{request.Email}' is already registered.");

    var user = new User(request.UserName, request.Email);
    try
    {
        await _userRepository.AddAsync(user);
        await _unitOfWork.SaveChangesAsync();
        return Result.Success(user);
    }
    catch (DbUpdateException ex) when (IsUniqueConstraintViolation(ex))
    {
        return Result.Failure<User>($"Email '{request.Email}' is already registered.");
    }
}

private static bool IsUniqueConstraintViolation(DbUpdateException ex)
{
    return ex.InnerException is SqlException sqlEx &&
           (sqlEx.Number == 2601 || sqlEx.Number == 2627);
}
```

```csharp
public async Task<Result> UpdatePriceAsync(int productId, decimal newPrice, byte[] rowVersion)
```

```csharp
public async Task<Result<Order>> PlaceOrderAsync(PlaceOrderCommand command)
{
    var strategy = _dbContext.Database.CreateExecutionStrategy();

    return await strategy.ExecuteAsync(async () =>
    {
        await using var transaction = await _dbContext.Database.BeginTransactionAsync(IsolationLevel.Serializable);

        try
        {
            var product = await _dbContext.Products
                .Where(p => p.Id == command.ProductId)
                .FirstOrDefaultAsync();

            if (product == null || product.StockQuantity < command.Quantity)
            {
                await transaction.RollbackAsync();
                return Result.Failure<Order>("Insufficient stock.");
            }

            product.StockQuantity -= command.Quantity;
            var order = new Order(command.UserId, command.ProductId, command.Quantity, product.Price * command.Quantity);
            await _dbContext.Orders.AddAsync(order);

            await _dbContext.SaveChangesAsync();
            await transaction.CommitAsync();

            return Result.Success(order);
        }
        catch (DbUpdateException ex)
        {
            await transaction.RollbackAsync();
            if (IsUniqueConstraintViolation(ex))
                return Result.Failure<Order>("Duplicate order detected.");
            throw;
        }
    });
}
```

```csharp
public interface IHttpService
{
    Task<T?> GetAsync<T>(string uri, CancellationToken ct = default);
    Task<T?> PostAsync<T>(string uri, object body, CancellationToken ct = default);
}

public class HttpService : IHttpService
{
    private readonly HttpClient _httpClient;
    private readonly ILogger<HttpService> _logger;
    private readonly JsonSerializerOptions _jsonOptions;

    public HttpService(IHttpClientFactory httpClientFactory, ILogger<HttpService> logger)
    {
        _httpClient = httpClientFactory.CreateClient("ExternalApi");
        _logger = logger;
        _jsonOptions = new JsonSerializerOptions
        {
            PropertyNameCaseInsensitive = true,
            PropertyNamingPolicy = JsonNamingPolicy.CamelCase
        };
    }

    public async Task<T?> GetAsync<T>(string uri, CancellationToken ct = default)
    {
        try
        {
            _logger.LogDebug("GET {Uri}", uri);
            var response = await _httpClient.GetAsync(uri, ct);
            await EnsureSuccessStatusCodeAsync(response);

            var content = await response.Content.ReadAsStringAsync(ct);
            return JsonSerializer.Deserialize<T>(content, _jsonOptions);
        }
        catch (HttpRequestException ex) when (ex.StatusCode == HttpStatusCode.NotFound)
        {
            _logger.LogWarning("Resource not found: {Uri}", uri);
            return default;
        }
        catch (HttpRequestException ex)
        {
            _logger.LogError(ex, "HTTP GET failed for {Uri}: {Message}", uri, ex.Message);
            throw new ExternalServiceException($"Failed to call external API: {uri}", ex);
        }
    }

    private async Task EnsureSuccessStatusCodeAsync(HttpResponseMessage response)
    {
        if (response.IsSuccessStatusCode) return;

        var responseBody = await response.Content.ReadAsStringAsync();
        _logger.LogError("HTTP request failed. Status: {StatusCode}, Body: {Body}",
            (int)response.StatusCode, responseBody);

        throw new HttpRequestException($"HTTP {(int)response.StatusCode}: {response.ReasonPhrase}",
            inner: null, statusCode: response.StatusCode);
    }
}
```

```csharp
public static class SafeFileOperations
{
    /// <summary>
    /// 安全读取文件内容（带重试）
    /// </summary>
    public static async Task<string> ReadFileWithRetryAsync(string path, int maxRetries = 3, CancellationToken ct = default)
    {
        for (int i = 0; i < maxRetries; i++)
        {
            try
            {
                return await File.ReadAllTextAsync(path, ct);
            }
            catch (FileNotFoundException) { throw; }
            catch (IOException) when (i < maxRetries - 1)
            {
                await Task.Delay(TimeSpan.FromMilliseconds(100 * (i + 1)), ct);
            }
        }
        throw new IOException($"Failed to read file after {maxRetries} attempts: {path}");
    }

    /// <summary>
    /// 原子写入文件（先写临时文件再替换）
    /// </summary>
    public static async Task WriteFileAtomicAsync(string path, string content, CancellationToken ct = default)
    {
        var directory = Path.GetDirectoryName(path)!;
        if (!Directory.Exists(directory))
            Directory.CreateDirectory(directory);

        var tempPath = path + ".tmp";
        try
        {
            await File.WriteAllTextAsync(tempPath, content, new UTF8Encoding(false), ct);
            File.Move(tempPath, path, overwrite: true);
        }
        catch
        {
            if (File.Exists(tempPath)) File.Delete(tempPath);
            throw;
        }
    }
}
```

```csharp
/// 处理Decimal类型的JSON转换（避免浮点精度问题）
/// </summary>
public class DecimalConverter : JsonConverter<decimal>
{
    public override decimal Read(ref Utf8JsonReader reader, Type typeToConvert, JsonSerializerOptions options)
    {
        return reader.TokenType switch
        {
            JsonTokenType.String => decimal.TryParse(reader.GetString(), out var value)
                ? value
                : throw new JsonException($"Cannot convert to Decimal."),
            JsonTokenType.Number => reader.GetDecimal(),
            _ => throw new JsonException($"Unexpected token type: {reader.TokenType}")
        };
    }

    public override void Write(Utf8JsonWriter writer, decimal value, JsonSerializerOptions options)
    {
        writer.WriteStringValue(value.ToString(CultureInfo.InvariantCulture));
    }

/// <summary>
/// 处理DateTimeOffset的JSON转换（支持多种格式）
/// </summary>
public class DateTimeOffsetConverter : JsonConverter<DateTimeOffset>
{
    private static readonly string[] Formats = {
        "yyyy-MM-ddTHH:mm:ss.fffZ",
        "yyyy-MM-ddTHH:mm:ssZ",
        "yyyy-MM-ddTHH:mm:ss.fffzzz",
        "yyyy-MM-dd"
    };

    public override DateTimeOffset Read(ref Utf8JsonReader reader, Type typeToConvert, JsonSerializerOptions options)
    {
        if (reader.TokenType == JsonTokenType.String)
        {
            var stringValue = reader.GetString()!;
            if (DateTimeOffset.TryParseExact(stringValue, Formats,
                CultureInfo.InvariantCulture, DateTimeStyles.None, out var result))
                return result;

            throw new JsonException($"Cannot parse date '{stringValue}'.");
        }

        return reader.GetDateTimeOffset();
    }

    public override void Write(Utf8JsonWriter writer, DateTimeOffset value, JsonSerializerOptions options)
    {
        writer.WriteStringValue(value.ToString("o"));  // ISO 8601 格式
    }
}
```

```csharp
            return ParseResult<int>.Success(result);
```

### 原因分析

### 解决方案

#### 方法1：完善的身份认证配置
```csharp
public static IServiceCollection AddAuthServices(this IServiceCollection services, IConfiguration config)
{
    var jwtSettings = config.GetSection("Jwt");
    var secretKey = jwtSettings.GetValue<string>("SecretKey")
        ?? throw new InvalidOperationException("JWT SecretKey is not configured.");

    services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
        .AddJwtBearer(options =>
        {
            options.TokenValidationParameters = new TokenValidationParameters
            {
                ValidateIssuer = true,
                ValidIssuer = jwtSettings.GetValue<string>("Issuer"),
                ValidateAudience = true,
                ValidAudience = jwtSettings.GetValue<string>("Audience"),
                ValidateIssuerSigningKey = true,
                IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(secretKey)),
                ValidateLifetime = true,
                ClockSkew = TimeSpan.Zero,
                RoleClaimType = "roles",
                NameClaimType = "sub"
            };

            options.Events = new JwtBearerEvents
            {
                OnAuthenticationFailed = context =>
                {
                    _logger.LogError(context.Exception, "Authentication failed");
                    return Task.CompletedTask;
                },
                OnChallenge = context =>
                {
                    context.HandleResponse();
                    context.Response.StatusCode = StatusCodes.Status401Unauthorized;
                    context.Response.ContentType = "application/json";
                    return context.Response.WriteAsync(JsonSerializer.Serialize(new
                    {
                        error = "Unauthorized",
                        message = "You need to authenticate."
                    }));
                },
                OnForbidden = async context =>
                {
                    context.Response.StatusCode = StatusCodes.Status403Forbidden;
                    context.Response.ContentType = "application/json";
                    await context.Response.WriteAsync(JsonSerializer.Serialize(new
                    {
                        error = "Forbidden",
                        message = "Permission denied."
                    }));
                }
            };
        });

    services.AddAuthorization(options =>
    {
        options.AddPolicy("AdminOnly", policy => policy.RequireRole("Admin"));
        options.AddPolicy("CanManageUsers", policy =>
```

## 问题14：async/await 死锁问题

### 问题描述
在ASP.NET Core中由于async/await使用不当导致死锁。

### 错误现象

```text
应用程序挂起，没有任何响应
CPU使用率接近0%
请求永远无法完成
```

### 原因分析

1. **在同步上下文中阻塞异步调用**：`.Result` 或 `.Wait()` 导致死锁
2. **混合使用async和非async代码**
3. **锁 + async的组合**：在持有lock的同时await
4. **旧的同步代码调用异步方法**

### 解决方案

#### 方法1：避免阻塞异步代码
```csharp
// ❌ 致命错误：在ASP.NET Core中阻塞异步调用会导致死锁！
public ActionResult Index()
{
    var data = _service.GetDataAsync().Result;  // 死锁！！！
    return View(data);
}

// ✅ 正确方式：全程async
public async Task<ActionResult> Index()
{
    var data = await _service.GetDataAsync();
    return View(data);
}

// ✅ 如果必须同步调用（仅限非ASP.NET上下文）
public void SyncMethod()
{
    var result = Task.Run(() => _service.GetDataAsync()).GetAwaiter().GetResult();
}
```

#### 方法2：避免在锁内await
```csharp
// ❌ 错误：不能在lock语句内使用await
private readonly object _lock = new();

public async Task ProcessAsync()
{
    lock (_lock)
    {
        // 不能在这里await！编译错误 CS1996
    }
}

// ✅ 正确：使用SemaphoreSlim（异步友好的锁）
private readonly SemaphoreSlim _semaphore = new(1, 1);

public async Task ProcessAsync()
{
    await _semaphore.WaitAsync();
    try
    {
        await DoSomethingAsync();
    }
    finally
    {
        _semaphore.Release();
    }
}
```

#### 方法3：完整的async最佳实践
```csharp
public class AsyncBestPractices
{
    // 规则1：不要混用async/await和阻塞调用
    public async Task GoodExample1()
    {
        var result = await _service.CallAsync();  // ✅
    }

    // 规则2：避免void async（除了事件处理器）
    public async Task GoodExample2() { }         // ✅

    // 规则3：使用CancellationToken
    public async Task GoodExample3(CancellationToken ct = default)
    {

    }

    // 规则4：返回Task而非async Task（如果没有await）
    public Task<Result> GoodExample5()
    {
        return _cache.GetAsync("key");  // 直接返回Task
    }

    // 规则5：使用ValueTask优化热路径
    public ValueTask<int> GetValueAsync(int key)

            ? new ValueTask<int>(value)
            : LoadValueAsync(key);
    }
}
```

```csharp
public class LargeFileProcessor
{
    /// <summary>
    /// 流式读取CSV文件（不一次性加载到内存）
    /// </summary>
    public async IAsyncEnumerable<CsvRecord> ReadCsvAsync(
        string filePath, [EnumeratorCancellation] CancellationToken ct = default)
    {
        await foreach (var line in File.ReadLinesAsync(filePath, ct))
        {
            if (string.IsNullOrWhiteSpace(line)) continue;
            if (line.StartsWith("#")) continue;

            var fields = line.Split(',');
            yield return new CsvRecord(fields[0], fields[1], int.Parse(fields[2]));
        }
    }

    /// <summary>
    /// 流式处理（边读边处理边丢弃）
    /// </summary>
    public async Task ProcessLargeCsvAsync(string filePath, CancellationToken ct = default)
    {
        var batchSize = 1000;
        var batch = new List<CsvRecord>(batchSize);

        await foreach (var record in ReadCsvAsync(filePath, ct).WithCancellation(ct))
        {
            batch.Add(record);

            if (batch.Count >= batchSize)
            {
                await ProcessBatchAsync(batch, ct);
                batch.Clear();  // 及时释放已处理的数据
            }
        }

        if (batch.Count > 0)
            await ProcessBatchAsync(batch, ct);
    }
}
```

## 问题16：StackOverflowException（栈溢出）

### 问题描述

### 错误现象

```text
System.StackOverflowException: Exception of type 'System.StackOverflowException' was thrown。
注意：此异常通常无法被catch捕获，进程会直接终止。
```

### 原因分析

1. **无限递归**：方法直接或间接调用自身且没有正确的终止条件
2. **深度嵌套的结构**：极度深的对象图或XML/JSON
3. **属性的循环调用**：getter/setter互相调用
4. **ToString/Equals/GetHashCode的重写**：不小心形成循环

### 解决方案

#### 方法1：修复无限递归
```csharp
// ❌ 无限递归
public int CalculateFactorial(int n)
{
    if (n <= 0) return 1;
    return n * CalculateFactorial(n - 1);  // 对于很大的n会栈溢出
}

// ✅ 修复1：改用迭代
public int CalculateFactorialIterative(int n)
{
    if (n < 0) throw new ArgumentException("n must be non-negative");
    int result = 1;
    for (int i = 2; i <= n; i++)
        result *= i;
    return result;
}
```

#### 方法2：修复属性循环调用
```csharp
// ❌ 属性循环调用
public class Person
{
    private Person _spouse;

    public Person Spouse
    {
        get => _spouse;
        set
        {
            _spouse = value;
            if (value != null)
                value.Spouse = this;  // 循环调用setter！
        }
    }
}

// ✅ 修复：使用字段和初始化方法
public class Person
{
    private Person _spouse;

    public Person? Spouse => _spouse;

    public void Marry(Person other)
    {
        this._spouse = other;
        other._spouse = this;  // 直接设置字段
    }
}
```

- 优先使用迭代代替递归
- 为所有递归设置最大深度限制
- 重写Equals/GetHashCode时特别小心对象图中的循环引用
- 使用单元测试验证极端输入

## 问题19：依赖注入生命周期错误

### 问题描述
在错误的生命周期作用域中注入了不兼容的服务。

### 错误现象

```text
System.InvalidOperationException: Cannot consume scoped service 'MyDbContext' from singleton 'MyService'.
Cannot resolve scoped service 'IUnitOfWork' from root provider.
A second operation was started on this context before a previous operation completed.
```

### 原因分析

1. **Singleton注入Scoped**：单例服务试图注入作用域服务
2. **从根提供者解析Scoped**：在应用启动时直接从根ServiceProvider解析Scoped服务
3. **Captured Scoped Dependency**：长生命周期的对象持有了Scoped对象的引用
4. **BackgroundService中直接注入DbContext**

### 解决方案

#### 方法1：理解三种生命周期
```csharp
// Transient（瞬态）- 每次注入都创建新实例
services.AddTransient<IOperation, Operation>();

// Scoped（作用域）- 每个HTTP请求内共享同一个实例
services.AddScoped<DbContext, AppDbContext>();

// Singleton（单例）- 整个应用生命周期内只创建一次
services.AddSingleton<ICacheService, RedisCacheService>();
```

#### 方法2：修复生命周期违规
```csharp
// ❌ 错误：Singleton服务注入Scoped服务

    private readonly AppDbContext _dbContext;  // Scoped! 但这是Singleton!

    public CacheInvalidationService(AppDbContext dbContext) { ... }
}

// ✅ 修复：使用IServiceScopeFactory
public class CacheInvalidationService : IHostedService
{
    private readonly IServiceScopeFactory _scopeFactory;

    public CacheInvalidationService(IServiceScopeFactory scopeFactory)
    {
        _scopeFactory = scopeFactory;
    }

    public async Task DoWorkAsync()
    {
        using var scope = _scopeFactory.CreateScope();
        var dbContext = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        // 使用完scope后dbContext会被dispose
        var items = await dbContext.CacheItems.Where(c => c.ExpiresAt < DateTime.UtcNow).ToListAsync();
    }
}
```

#### 方法3：正确的BackgroundService DI模式
```csharp
public class QueueProcessorBackgroundService : BackgroundService
{
    private readonly IServiceScopeFactory _scopeFactory;

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                using var scope = _scopeFactory.CreateScope();
                var messageQueue = scope.ServiceProvider.GetRequiredService<IMessageQueue>();
                
                var message = await messageQueue.DequeueAsync(stoppingToken);
                if (message == null)
                {
                    await Task.Delay(1000, stoppingToken);
                    continue;
                }

                var handler = CreateHandler(message.Type, scope.ServiceProvider);
                await handler.HandleAsync(message, stoppingToken);
            }
            catch (OperationCanceledException)
            {
                break;
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Error processing message");
            }
        }
    }
}
```

### 预防措施
- BackgroundService/IHostedService 始终使用 `IServiceScopeFactory`
- Singleton 服务只依赖 Singleton 或 Transient 服务
- 使用 `ValidateScopes`（开发模式默认开启）检测生命周期违规
- 避免在构造函数中做耗时操作

## 问题20：并发访问共享状态问题

### 问题描述
多线程/多请求同时访问共享的可变状态导致数据损坏或竞争条件。

### 错误现象

- 数据不一致（两个请求读到相同的计数器值然后各自+1）
- 并发修改异常（Collection was modified）
- 偶发的IndexOutOfRangeException
- 缓存击穿/雪崩

### 原因分析

1. **非线程安全的集合**：List/Dictionary在多线程下不安全
2. **非原子的复合操作**：检查-然后-操作不是原子的
3. **静态可变状态**：静态字段被多个请求同时修改
4. **缓存竞争**：多个线程同时重建缓存
5. **单例中的可变状态**

### 解决方案

#### 方法1：使用线程安全的集合
```csharp
public class ConcurrentCollections
{
    // ✅ 线程安全的替代品
    private readonly ConcurrentBag<User> _concurrentBag = new();
    private readonly ConcurrentDictionary<int, User> _concurrentDict = new();
    private readonly ConcurrentQueue<Message> _messageQueue = new();
    private readonly BlockingCollection<TaskItem> _taskQueue = new(1000);

    public void AddUser(User user)
    {
        _concurrentDict.TryAdd(user.Id, user);
    }

    public User? GetUser(int id)
    {
        return _concurrentDict.TryGetValue(id, out var user) ? user : null;
    }
}
```

#### 方法2：正确的同步原语使用
```csharp
public class SynchronizedCounter
{
    // ✅ 使用Interlocked进行原子操作
    private long _atomicCount;

    public long IncrementAtomic()
    {
        return Interlocked.Increment(ref _atomicCount);
    }

    // ✅ 使用lock保护复合操作
    private readonly object _lock = new();
    private int _availableSlots;
    private const int MaxSlots = 100;

    public bool TryReserveSlot()
    {
        lock (_lock)
        {
            if (_availableSlots < MaxSlots)
            {
                _availableSlots++;
                return true;
            }
            return false;
        }
    }

    // ✅ 使用ReaderWriterLockSlim（读多写少场景）
    private readonly ReaderWriterLockSlim _rwLock = new();
    private readonly Dictionary<string, CacheEntry> _cache = new();

    public CacheEntry? GetFromCache(string key)
    {
        _rwLock.EnterReadLock();
        try
        {
            return _cache.TryGetValue(key, out var entry) ? entry : null;
        }
        finally
        {
            _rwLock.ExitReadLock();
        }
    }

    public void UpdateCache(string key, CacheEntry entry)
    {
        _rwLock.EnterWriteLock();
        try
        {
            _cache[key] = entry;
        }
        finally
        {
            _rwLock.ExitWriteLock();
        }
    }
}
```

#### 方法3：Immutable（不可变）数据结构
```csharp
using System.Collections.Immutable;

public class ImmutableDataStore
{
    private ImmutableDictionary<string, UserData> _userData = 
        ImmutableDictionary.Create<string, UserData>.Empty;

    public void AddOrUpdateUser(string userId, UserData data)
    {
        SpinWait.SpinUntil(() =>
        {
            var original = Volatile.Read(ref _userData);
            var updated = original.SetItem(userId, data);
            return Interlocked.CompareExchange(ref _userData, updated, original) == original;
        });
    }

    public UserData? GetUser(string userId)
    {
        return Volatile.Read(ref _userData).GetValueOrDefault(userId);
    }
}
```

### 预防措施
- 优先使用 `Concurrent` 命名空间的集合
- 不可变数据结构天然线程安全
- 共享状态尽量减少或消除
- 使用 `volatile` 或 `Volatile` 类确保可见性
- 编写多线程单元测试（并行执行验证）

## 总结

本文档涵盖了ASP.NET运行时最常见的20个问题，包括：

| 类别 | 问题数量 | 关键要点 |
|------|---------|---------|
| 通用异常处理 | 1 | 500错误排查、全局异常处理 |
| Null相关 | 1 | NullReferenceException防护 |
| 操作有效性 | 2 | InvalidOperationException、ArgumentException |
| 网络/IO异常 | 3 | Timeout、HTTP、Socket、File |
| 数据操作 | 2 | DbUpdateException、JsonException |
| 格式/转换 | 1 | FormatException |
| 权限/认证 | 1 | 401/403处理 |
| 并发/异步 | 4 | 死锁、OOM、StackOverflow、并发状态 |
| 启动/配置 | 2 | 启动崩溃、中间件顺序 |
| DI生命周期 | 1 | 生命周期违规 |
| 共享状态 | 1 | 线程安全 |

**核心原则**：
1. **全局异常处理**是最后一道防线，每个层次都应该有自己的错误处理
2. **Null是最常见的异常来源**，启用可空引用类型可以从源头减少这类问题
3. **异步代码要遵循 "Async all the way"**，绝不使用 `.Result` 或 `.Wait()`
4. **DI生命周期必须严格遵守**：Singleton不能依赖Scoped服务
5. **共享状态要谨慎处理**，优先使用不可变数据和线程安全集合

**快速排查清单**：
- [ ] 是否有全局异常处理中间件？
- [ ] Null检查是否充分？是否启用了可空引用类型？
- [ ] DbContext的生命周期管理是否正确？
- [ ] 是否有未处理的TaskCanceledException？
- [ ] 中间件注册顺序是否符合规范？
- [ ] Singleton服务是否错误地依赖了Scoped服务？
- [ ] 共享的可变状态是否有适当的同步保护？
