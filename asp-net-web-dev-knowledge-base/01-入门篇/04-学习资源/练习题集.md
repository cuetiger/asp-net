### 第4题：值类型与引用类型（简单）

**题目**: 以下哪些是C#中的值类型？（多选）

**选项**:
A. `int`
B. `string`
C. `bool`
D. `class Student`
E. `double`
F. `struct Point`

**正确答案**: A, C, E, F

**详细解析**:

**值类型（直接存储数据）**:
- ✅ **A. int**：整数类型，存储在栈上
- ✅ **C. bool**：布尔类型，true/false
- ✅ **E. double**：双精度浮点数
- ✅ **F. struct Point**：结构体是值类型

**引用类型（存储引用地址）**:
- ❌ **B. string**：虽然是不可变的，但本质是引用类型（特殊引用类型）
- ❌ **D. class Student**：类是典型的引用类型

**关键区别**:

| 特性 | 值类型 | 引用类型 |
|------|--------|----------|
| 存储位置 | 栈（Stack） | 堆（Heap） |
| 赋值行为 | 复制整个数据 | 复制引用地址 |
| 可为null | 不可（除非用可空类型`int?`） | 可以 |
| 默认值 | 0/false/结构体默认值 | null |
| 典型示例 | int, bool, double, struct, enum | string, class, interface, array, delegate |

**代码示例**:
```csharp
// 值类型赋值 - 复制数据
int a = 10;
int b = a;      // b得到a的副本
b = 20;
Console.WriteLine(a); // 输出: 10（a不受影响）

// 引用类型赋值 - 复制引用
string s1 = "Hello";
string s2 = s1;     // s2指向同一内存地址
s2 = "World";
Console.WriteLine(s1); // 输出: Hello（字符串不可变性导致此结果）
```

**知识点标签**: [数据类型] [值类型] [引用类型]

### 第5题：条件判断与循环（简单）

**题目**: 请阅读以下代码，输出最终结果是什么？

```csharp
for (int i = 0; i < 5; i++)
{
    if (i == 2)
        continue;
    if (i == 4)
        break;
    Console.Write(i + " ");
}
```

**选项**:
A. `0 1 2 3 4 `
B. `0 1 3 `
C. `0 1 3 4 `
D. `0 1 2 3 `

**正确答案**: B

**详细解析**:

**执行流程分析**:

| 循环次数 | i的值 | 判断条件 | 执行动作 | 输出 |
|----------|-------|----------|----------|------|
| 第1次 | 0 | i!=2且i!=4 | 正常执行 | 输出"0 " |
| 第2次 | 1 | i!=2且i!=4 | 正常执行 | 输出"1 " |
| 第3次 | 2 | i==2 | **continue**（跳过本次剩余代码） | 无输出 |
| 第4次 | 3 | i!=2且i!=4 | 正常执行 | 输出"3 " |
| 第5次 | 4 | i==4 | **break**（跳出整个循环） | 无输出，循环结束 |

**关键字说明**:
- **continue**: 跳过当前迭代的剩余代码，立即开始下一次迭代
- **break**: 立即终止整个循环结构

**最终输出**: `0 1 3 `（注意每个数字后有空格）

**知识点标签**: [控制流] [for循环] [continue/break]

### 第6题：类的定义与实例化（简单）

**题目**: 观察以下代码，找出其中的错误并说明原因：

```csharp
class Person
{
    public string Name;
    private int age;

    public Person(string name)
    {
        Name = name;
    }

    public void SetAge(int a)
    {
        age = a;
    }
}

// 使用代码
Person p = new Person();
p.Name = "张三";
p.age = 25;
```

**正确答案**: 存在3个错误

**详细解析**:

**错误1**: 构造函数调用错误
```csharp
Person p = new Person(); // 错误！
```
- 问题：Person类只定义了带参数的构造函数`Person(string name)`
- C#编译器不会自动生成无参构造函数（当存在自定义构造函数时）
- **修正**: `Person p = new Person("张三");`

**错误2**: 访问私有字段
```csharp
p.age = 25; // 错误！
```
- 问题：`age`字段被声明为`private`（私有的）
- 私有成员只能在类内部访问，外部无法直接赋值
- **修正**: 使用公共方法 `p.SetAge(25);`

**错误3**: 字段命名不规范（非语法错误，但是最佳实践问题）
```csharp
public string Name; // 应该使用属性而非公共字段
private int age;    // 私有字段通常以下划线开头 _age
```
- **推荐写法**:
```csharp
class Person
{
    public string Name { get; set; }  // 使用属性
    private int _age;                 // 私有字段以下划线开头

    public int Age                    // 通过属性暴露
    {
        get => _age;
        set => _age = value;
    }
}
```

**修正后的完整代码**:
```csharp
Person p = new Person("张三");
p.Name = "李四";       // 可以修改属性
p.SetAge(25);          // 通过方法设置年龄
Console.WriteLine($"{p.Name}今年{p.GetAge()}岁"); // 需要添加GetAge方法
```

**知识点标签**: [面向对象] [类] [封装] [访问修饰符]

### 第7题：数组与集合基础（简单）

**题目**: 以下哪种方式可以正确创建一个包含3个元素的字符串数组？

**多选**（选择所有正确的写法）:

A.
```csharp
string[] arr = new string[3];
arr[0] = "A"; arr[1] = "B"; arr[2] = "C";
```

B.
```csharp
string[] arr = {"A", "B", "C"};
```

C.
```csharp
var arr = new[] { "A", "B", "C" };
```

D.
```csharp
List<string> arr = new() { "A", "B", "C" };
```

**正确答案**: A, B, C

**详细解析**:

✅ **A选项（正确）**:
- 先指定数组长度为3
- 再逐个元素赋值
- 适合需要先分配空间再填充的场景

✅ **B选项（正确）**:
- 数组初始化器语法
- 必须在声明时同时初始化
- 编译器自动推断长度为3

✅ **C选项（正确）**:
- 使用`var`隐式类型 + `new[]`匿名数组
- 编译器根据初始化值推断类型为`string[]`
- 写法简洁，推荐使用

❌ **D选项（错误）**:
- 创建的是`List<string>`（列表），不是数组
- `List<T>`是动态集合，长度可变
- 虽然功能相似，但类型不同

**数组 vs List 对比**:

| 特性 | 数组 (`T[]`) | 列表 (`List<T>`) |
|------|--------------|------------------|
| 长度 | 固定，创建后不可变 | 动态，可增删元素 |
| 性能 | 略快（连续内存） | 稍慢（需维护内部数组） |
| 适用场景 | 长度已知且固定 | 元素数量经常变化 |
| 访问方式 | `arr[i]` | `list[i]` 或 `list.Add()` |

**知识点标签**: [数组] [集合] [List<T>] [初始化]

### 第8题：LINQ基础查询（简单）

**题目**: 给定一个整数列表，使用LINQ筛选出所有大于5的偶数并按升序排列：

```csharp
List<int> numbers = new() { 3, 7, 2, 9, 4, 8, 6, 1, 5 };
```

请从以下选项中选择正确的LINQ查询表达式：

**选项**:
A.
```csharp
var result = from n in numbers
             where n > 5 && n % 2 == 0
             orderby n ascending
             select n;
```

B.
```csharp
var result = numbers.Where(n => n > 5)
                   .Where(n => n % 2 == 0)
                   .OrderBy(n => n);
```

C.
```csharp
var result = numbers.FindAll(n => n > 5 && n % 2 == 0)
                   .Sort();
```

D. A和B都正确

**正确答案**: D

**详细解析**:

✅ **A选项（查询语法 - Query Syntax）**:
- 使用类似SQL的声明式语法
- `where`: 过滤条件（大于5 且 是偶数）
- `orderby ... ascending`: 升序排序
- `select`: 选择结果
- 结果: `[6, 8]`

✅ **B选项（方法语法 - Method Syntax/Fluent API）**:
- 使用Lambda表达式的链式调用
- `.Where()`: 过滤（可链式多次调用）
- `.OrderBy()`: 排序
- 与A选项完全等价，只是写法不同
- 结果: `[6, 8]`

❌ **C选项（错误）**:
- `FindAll()`是List的方法，不是LINQ方法（虽然效果类似）
- `.Sort()`是就地排序，返回void，不能链式调用
- 不符合LINQ标准用法

**两种语法对比**:
```csharp
// 查询语法（更易读，适合复杂查询）
var query = from s in students
            where s.Age > 18
            orderby s.Name
            select s.Name;

// 方法语法（更灵活，适合链式操作）
var method = students
    .Where(s => s.Age > 18)
    .OrderBy(s => s.Name)
    .Select(s => s.Name);

// 两者结果完全相同，可根据场景和个人喜好选择
```

**执行结果**: `[6, 8]`（6和8是唯一满足"大于5且为偶数"条件的数字）

**知识点标签**: [LINQ] [查询语法] [方法语法] [Lambda表达式]

### 第9题：异常处理机制（中等）

**题目**: 阅读以下代码，程序输出什么？如果发生异常，是什么类型的异常？

```csharp
try
{
    int[] numbers = { 1, 2, 3 };
    Console.WriteLine(numbers[5]);
}
catch (IndexOutOfRangeException ex)
{
    Console.WriteLine("索引越界: " + ex.Message);
}
catch (Exception ex)
{
    Console.WriteLine("其他异常: " + ex.Message);
}
finally
{
    Console.WriteLine("finally块总是执行");
}
```

**选项**:
A. 输出数字3
B. 输出"索引越界: ..."和"finally块总是执行"
C. 输出"其他异常: ..."和"finally块总是执行"
D. 程序崩溃，无输出

**正确答案**: B

**详细解析**:

**执行流程**:

1. **try块**: 尝试访问`numbers[5]`
   - 数组`numbers`长度为3，有效索引是0、1、2
   - 索引5超出范围 → 抛出`IndexOutOfRangeException`

2. **catch匹配**: 从上往下查找匹配的catch块
   - 第一个catch捕获`IndexOutOfRangeException` ← 匹配！
   - 执行此catch块，输出："索引越界: 索引超出了数组界限。"
   - 后续catch块不再执行

3. **finally块**: 无论是否发生异常，finally都会执行
   - 输出："finally块总是执行"

**最终输出**:
```
索引越界: 索引超出了数组界限。
finally块总是执行
```

**异常处理要点**:
- catch块的顺序很重要：**具体异常在前，通用异常在后**
- finally常用于资源清理（关闭文件、释放连接等）
- 一个try可以有多个catch，但只能有一个finally

**常见异常类型**:
- `IndexOutOfRangeException`: 索引越界
- `NullReferenceException`: 空引用
- `FormatException`: 格式转换错误（如`int.Parse("abc")`）
- `FileNotFoundException`: 文件未找到
- `InvalidOperationException`: 操作无效

**知识点标签**: [异常处理] [try-catch-finally] [IndexOutOfRangeException]

### 第10题：异步编程基础（中等）

**题目**: 关于C#中的async/await异步编程，以下说法正确的是？（多选）

**选项**:
A. async方法必须有await关键字，否则会有警告
B. async方法的返回类型可以是Task、Task\<T\>或void
C. await只能在async标记的方法内部使用
D. 异步方法一定会创建新线程
E. 使用await时，当前方法会暂停执行直到任务完成

**正确答案**: A, B, C, E

**详细解析**:

✅ **A选项（正确）**:
- 如果async方法中没有await，编译器会产生警告（CS1998）
- 提示您该方法将同步运行，失去了异步的意义
- 解决方案：移除async关键字，或添加真正的异步操作

✅ **B选项（正确）**:
- `Task`: 表示异步操作完成，无返回值
- `Task<T>`: 表示异步操作完成后返回T类型的结果
- `void`: 仅用于事件处理器（不推荐在其他场景使用，因为无法等待）

✅ **C选项（正确）**:
- await是上下文敏感关键字，只能在async方法中使用
- 普通方法中使用await会导致编译错误

❌ **D选项（错误）**:
- **这是最常见的误解！**
- async/await本身**不一定创建新线程**
- 对于I/O操作（网络请求、文件读写），使用线程池中的现有线程或I/O完成端口
- 只有CPU密集型任务（如`Task.Run()`）才会使用新线程
- 异步的核心优势是**不阻塞线程**，而不是创建更多线程

✅ **E选项（正确）**:
- await确实会"暂停"方法的执行
- 但**不会阻塞线程**！线程被释放去做其他工作
- 当异步操作完成时，方法从await处恢复执行

**代码示例**:
```csharp
// 正确的异步模式
public async Task<string> GetDataAsync()
{
    // I/O操作 - 不占用线程，只是等待响应
    using var client = new HttpClient();
    string result = await client.GetStringAsync("https://api.example.com/data");
    return result; // 返回Task<string>
}

// CPU密集型任务 - 使用Task.Run
public async Task<int> ComputeAsync()
{
    // 在线程池线程上执行耗时计算
    int result = await Task.Run(() =>
    {
        int sum = 0;
        for (int i = 0; i < 1000000; i++) sum += i;
        return sum;
    });
    return result;
}
```

**知识点标签**: [异步编程] [async/await] [Task] [线程模型]

### 第11题：接口与多态（困难）

**题目**: 分析以下代码，输出结果是什么？

```csharp
interface IAnimal
{
    void Speak();
    string Name { get; }
}

class Dog : IAnimal
{
    public string Name => "旺财";
    public void Speak() => Console.WriteLine("汪汪！");
}

class Cat : IAnimal
{
    public string Name => "咪咪";
    public void Speak() => Console.WriteLine("喵喵~");
}

class Program
{
    static void Main()
    {
        List<IAnimal> animals = new()
        {
            new Dog(),
            new Cat(),
            new Dog()
        };

        foreach (var animal in animals)
        {
            Console.Write(animal.Name + ": ");
            animal.Speak();
        }

        // 类型判断测试
        if (animals[0] is Dog dog)
        {
            Console.WriteLine($"第一条是狗: {dog.Name}");
        }
    }
}
```

**选项**:
A.
```
旺财: 汪汪！
咪咪: 喵喵~
旺财: 汪汪！
第一条是狗: 旺财
```

B. 编译错误，接口不能实例化
C. 运行时错误，无法将Dog转换为IAnimal
D.
```
Dog: 汪汪！
Cat: 喵喵~
Dog: 汪汪！
```

**正确答案**: A

**详细解析**:

**核心概念演示**:

1. **接口作为类型**:
   - `IAnimal`定义了契约：必须实现`Speak()`方法和`Name`属性
   - `Dog`和`Cat`都实现了这个接口
   - 可以用`IAnimal`类型的变量引用任何实现类的实例

2. **多态性体现**:
   - 相同的代码`animal.Speak()`对不同对象产生不同行为
   - Dog对象调用Dog的实现 → 输出"汪汪！"
   - Cat对象调用Cat的实现 → 输出"喵喵~"
   - 这就是**运行时多态**

3. **is模式匹配**:
   - `animals[0] is Dog dog`：检查animals[0]是否为Dog类型
   - 如果是，将其转换为Dog类型并赋给变量`dog`
   - 这种写法比传统的`(Dog)animals[0]`更安全，避免InvalidCastException

**逐行输出分析**:
```
第1次循环 (Dog对象):
├── animal.Name → "旺财"
├── 输出: "旺财: "
├── animal.Speak() → Dog.Speak()
└── 输出: "汪汪！"

第2次循环 (Cat对象):
├── animal.Name → "咪咪"
├── 输出: "咪咪: "
├── animal.Speak() → Cat.Speak()
└── 输出: "喵喵~"

第3次循环 (Dog对象):
├── 同第1次
└── 输出: "旺财: 汪汪！"

最后if语句:
├── animals[0]确实是Dog ✓
├── dog变量被赋值
└── 输出: "第一条是狗: 旺财"
```

**实际应用价值**:
这种模式在实际开发中非常常见，例如：
- 不同的支付方式（支付宝、微信、银行卡）实现同一接口
- 不同的日志记录器（文件、数据库、控制台）实现同一接口
- 依赖注入框架大量使用接口实现松耦合

**知识点标签**: [接口] [多态] [类型转换] [模式匹配] [面向对象设计]

**逐行深入解读**:

```csharp
// 1️⃣ 创建构建器（Builder Pattern）
var builder = WebApplication.CreateBuilder(args);
// - args: 命令行参数
// - 内部完成：加载配置、设置默认服务、准备依赖注入容器

app.Run();

// - 处理传入的HTTP请求
// - 此方法是阻塞的，应用运行期间不会返回

```

### 第15题：依赖注入基础（中等）

**题目**: 在ASP.NET Core中，以下关于依赖注入（DI）的说法，哪项是**错误**的？

**选项**:
A. DI容器的生命周期包括Transient、Scoped、Singleton三种
B. Transient服务每次请求都会创建新实例
C. Scoped服务在每个HTTP请求范围内共享同一实例
D. Singleton服务在整个应用生命周期内只创建一次
E. 所有服务都必须显式注册才能使用

**正确答案**: E

**详细解析**:

**DI生命周期详解**:

✅ **A、B、C、D选项均正确**:

| 生命周期 | 关键字 | 创建时机 | 典型用途 | 示例 |
|----------|--------|----------|----------|------|
| **瞬时（Transient）** | AddTransient | 每次注入时创建新实例 | 轻量级、无状态服务 | 工具类、计算器 |
| **作用域（Scoped）** | AddScoped | 每个请求/作用域内共享 | 数据库上下文、用户会话 | DbContext、UnitOfWork |
| **单例（Singleton）** | AddSingleton | 首次请求时创建，全局共享 | 缓存、配置、状态服务 | 内存缓存、AppSettings |

❌ **E选项（错误）**:
- **并非所有服务都需要显式注册！**
- ASP.NET Core框架自动注册了许多**框架级服务**：
  - `ILogger<T>`: 日志服务（开箱即用）
  - `IConfiguration`: 配置服务（开箱即用）
  - `HttpContext`: HTTP上下文（Controller中自动可用）
  - `IHostEnvironment`: 环境信息（开箱即用）
- 只需要注册**自定义的业务服务**

**代码示例**:
```csharp
// Program.cs 中注册自定义服务
builder.Services.AddTransient<IMyService, MyService>();  // 瞬时
builder.Services.AddScoped<IDataRepository, SqlRepository>(); // 作用域
builder.Services.AddSingleton<ICacheService, MemoryCacheService>(); // 单例

// Controller中使用（通过构造函数注入）
[ApiController]
[Route("api/[controller]")]
public class UsersController : ControllerBase
{
    private readonly IDataRepository _repo;
    private readonly ILogger<UsersController> _logger;

    // 框架自动解析构造函数参数并注入
    public UsersController(IDataRepository repo, ILogger<UsersController> logger)
    {
        _repo = repo;
        _logger = logger;  // ILogger由框架自动提供，无需注册
    }

    [HttpGet("{id}")]
    public async Task<IActionResult> GetById(int id)
    {
        _logger.LogInformation("获取用户ID: {Id}", id); // 直接使用
        var user = await _repo.GetByIdAsync(id);
        return Ok(user);
    }
}
```

**常见错误与陷阱**:
- ❌ 在Singleton服务中注入Scoped服务（会导致Scoped变成Singleton行为）
- ❌ 在Transient服务中持有DbContext（可能导致并发问题）
- ✅ Controller默认是Scoped生命周期

**知识点标签**: [依赖注入] [DI容器] [服务生命周期] [IoC]

### 第16题：综合理解：完整的请求处理流程（困难）

**题目**: 当浏览器向ASP.NET Core Web API发送一个GET请求 `http://localhost:5000/api/users/42` 时，请按顺序描述从接收到响应的完整处理过程，并指出涉及的关键组件。

**参考答案要点**（开放式问答，评分标准见解析）:

**完整流程（10个关键步骤）**:

```
1. 【HTTP接收】Kestrel服务器监听端口，接收原始HTTP请求
   ↓ 组件: Kestrel（内置跨平台Web服务器）

2. 【请求创建】将原始TCP数据解析为HttpContext对象
   ↓ 包含: HttpRequest、HttpResponse、Session等

3. 【中间件管道】请求经过一系列注册的中间件（按顺序）
   ↓ 典型中间件链:
   ├── ExceptionHandler（全局异常处理）
   ├── HTTPS重定向
   ├── 静态文件（wwwroot）
   ├── 路由匹配（Routing Middleware）← 关键！
   ├── 认证授权（Authentication & Authorization）
   ├── CORS（跨域资源共享）
   └── 终结点映射（Endpoint Middleware）

4. 【路由解析】Routing Middleware解析URL模板
   ↓ 匹配: GET api/users/{id} → UsersController.GetById(int id)

5. 【模型绑定】从请求中提取参数
   ↓ 来源: URL路径(42) → 绑定到 id 参数

6. 【过滤器执行】按顺序执行Action Filters
   ├── [Authorize] 权限检查
   ├── [HttpGet] 方法验证
   └── 自定义过滤器（如日志、缓存）

7. 【Action执行】调用Controller的GetById方法
   ↓ 业务逻辑: _userService.GetUserById(42)

8. 【结果处理】ActionResult被执行
   ↓ 如: Ok(user) → HTTP 200 + JSON body

9. 【响应格式化】Output Formatter序列化结果
   ↓ System.Text.Json将对象转为JSON字符串

10.【HTTP响应】Kestrel发送HTTP响应给客户端
    ↓ 状态码: 200 OK
    ↓ Content-Type: application/json; charset=utf-8
    ↓ Body: {"id":42,"name":"张三","email":"zhangsan@example.com"}
```

**关键组件清单**:

| 组件类别 | 具体组件 | 职责 |
|----------|----------|------|
| **服务器** | Kestrel | HTTP协议处理、端口监听 |
| **宿主** | IHost/DI容器 | 应用生命周期、服务管理 |
| **中间件** | Routing/CORS/Auth | 请求管道处理 |
| **MVC框架** | Controller/Action | 路由分发、模型绑定 |
| **基础设施** | Configuration/Logging | 配置读取、日志记录 |
| **依赖注入** | ServiceProvider | 服务实例化和解析 |

**评分标准**:
- **优秀（90-100分）**: 能说出8-10个步骤，提到关键组件名称，理解中间件管道概念
- **良好（70-89分）**: 能说出5-7个步骤，了解基本的请求→Controller→响应流程
- **及格（60-69分）**: 能说出3-4个主要步骤，知道Controller处理请求
- **需加强（<60分）**: 只能说出1-2个步骤，对整体流程缺乏认识
