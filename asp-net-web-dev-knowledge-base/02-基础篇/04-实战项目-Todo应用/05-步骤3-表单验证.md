# Todo应用 - 步骤3：表单验证

## 一、概述

数据验证是Web应用安全性和可靠性的基石。本步骤将为Todo应用添加完整的**多层验证体系**，确保：

- ✅ **客户端验证** - 即时反馈，提升用户体验
- ✅ **服务端验证** - 安全保障，防止恶意数据
- ✅ **自定义验证规则** - 满足特定业务需求
- ✅ **友好的错误提示** - 清晰的引导信息
- ✅ **AJAX远程验证** - 实时检查（如标题唯一性）

**预计耗时：** 1.5-2小时

**前置条件：**
- 已完成[步骤2 - CRUD实现](./04-步骤2-CRUD实现.md)
- 基本的CRUD功能已能正常工作

## 二、验证架构设计

### 2.1 多层验证策略

```
用户输入 (User Input)
    ↓
┌─────────────────────────────────────┐
│  第1层：HTML5原生验证                │  ← 浏览器内置
│  (required, pattern, min/max)       │
└─────────────────┬───────────────────┘
                  ↓
┌─────────────────────────────────────┐
│  第2层：jQuery Validation            │  ← 客户端即时反馈
│  (Data Annotations → JS规则)        │
└─────────────────┬───────────────────┘
                  ↓ 表单提交
┌─────────────────────────────────────┐
│  第3层：ASP.NET Core Model Binding   │  ← 服务端基础验证
│  (ModelState.IsValid)               │
└─────────────────┬───────────────────┘
                  ↓
┌─────────────────────────────────────┐
│  第4层：Service层业务验证             │  ← 业务规则检查
│  (自定义逻辑)                        │
└─────────────────┬───────────────────┘
                  ↓
┌─────────────────────────────────────┐
│  第5层：数据库约束                    │  ← 最终防线
│  (NOT NULL, CHECK, UNIQUE)          │
└─────────────────────────────────────┘
```

### 2.2 各层职责对比

| 验证层 | 执行位置 | 优点 | 缺点 | 可靠性 |
|--------|---------|------|------|--------|
| **HTML5** | 浏览器 | 无需JS、快速 | 可被禁用、样式有限 | ⚠️ 低 |
| **jQuery Validation** | 客户端JS | 即时反馈、用户体验好 | 可被绕过 | ⚠️ 低 |
| **Model State** | 服务端C# | 安全、不可绕过 | 需要往返服务器 | ✅ 高 |
| **业务逻辑** | Service层 | 复杂规则验证 | 需要编码实现 | ✅ 高 |
| **数据库** | DB引擎 | 最终保障、性能好 | 错误信息不友好 | ✅✅ 最高 |

**黄金法则：永远不要信任客户端数据！**

#### TodoCreateViewModel（创建表单）

**文件位置：** `src/TodoApp.Api/Models/TodoCreateViewModel.cs`

```csharp
using System;
using System.ComponentModel.DataAnnotations;

namespace TodoApp.Api.Models
{
    /// <summary>
    /// 创建待办事项的ViewModel
    /// 包含完整的服务端验证规则
    /// </summary>
    public class TodoCreateViewModel
    {
        #region 标题验证

        /// <summary>
        /// 标题（必填）
        /// 验证规则：
        /// 1. 不能为空
        /// 2. 长度限制：2-200字符
        /// 3. 不能包含特殊控制字符
        /// </summary>
        [Required(ErrorMessage = "⛔ 标题是必填项，请输入待办事项的标题")]
        [StringLength(200, MinimumLength = 2,
            ErrorMessage = "📏 标题长度必须在 {2} 到 {1} 个字符之间")]
        [Display(Name = "标题")]
        [RegularExpression(@"^[\u4e00-\u9fa5a-zA-Z0-9\s\-\.\,\!\?\:\;\(\)\[\]\{\}\"\'\/\\\@\#\$\%\^\&\*\+\=]+$",
            ErrorMessage = "❌ 标题包含非法字符")]
        public string Title { get; set; } = string.Empty;

        #endregion

        #region 描述验证

        /// <summary>
        /// 详细描述（可选）
        /// 验证规则：
        /// 1. 可以为空
        /// 2. 最大长度2000字符
        /// 3. 允许换行和更多特殊字符
        /// </summary>
        [StringLength(2000,
            ErrorMessage = "📝 描述内容过长，最多允许 {1} 个字符")]
        [Display(Name = "详细描述")]
        [AllowHtml]  // 允许部分HTML标签（如果需要）
        public string? Description { get; set; }

        #endregion

        #region 优先级验证

        /// <summary>
        /// 优先级
        /// 值域：0(普通), 1(重要), 2(紧急)
        /// </summary>
        [Required(ErrorMessage = "⭐ 请选择优先级")]
        [Range(0, 2, ErrorMessage = "🎯 优先级值无效，请选择有效选项")]
        [Display(Name = "优先级")]
        public int Priority { get; set; } = 0;

        #endregion

        #region 截止日期验证

        /// <summary>
        /// 截止日期
        /// 自定义验证：不能是过去的时间
        /// </summary>
        [Display(Name = "截止日期")]
        [DataType(DataType.Date)]
        [CustomValidation(typeof(TodoCreateViewModel), "ValidateDueDate")]
        public DateTime? DueDate { get; set; }

        /// <summary>
        /// 自定义验证方法：截止日期不能是过去的日期
        /// 注意：方法必须是 static 的公共方法
        /// </summary>
        public static ValidationResult? ValidateDueDate(DateTime? dueDate, ValidationContext context)
        {
            if (dueDate.HasValue)
            {
                // 允许今天及以后的日期
                if (dueDate.Value.Date < DateTime.Today)
                {
                    return new ValidationResult("📅 截止日期不能是过去的时间");
                }

                // 可选：限制最远日期（如不超过10年）
                if (dueDate.Value.Date > DateTime.Today.AddYears(10))
                {
                    return new ValidationResult("📅 截止日期设置过远，请选择合理的日期范围");
                }
            }

            return ValidationResult.Success;
        }

        #endregion
    }
}
```

```csharp
        [RegularExpression(@"^[\u4e00-\u9fa5a-zA-Z0-9\s\-\.\,\!\?\:\;\(\)\[\]\{\}\"\'\/\\\@\#\$\%\^\&\*\+\=]+$",

        /// 是否完成（布尔值，无需额外验证）
        /// </summary>

        #endregion

        #region 优先级验证

        [Required(ErrorMessage = "⭐ 请选择优先级")]
        [Range(0, 2, ErrorMessage = "🎯 优先级值无效")]
        [Display(Name = "优先级")]
        public int Priority { get; set; } = 0;

        #endregion

        #region 截止日期验证

        [Display(Name = "截止日期")]
        [DataType(DataType.Date)]
        [CustomValidation(typeof(TodoEditViewModel), "ValidateDueDate")]
        public DateTime? DueDate { get; set; }

        /// <summary>
        /// 自定义验证：编辑时允许保留过去的日期（因为可能是旧任务）
        /// 但新设置的日期不能是过去
        /// </summary>
        public static ValidationResult? ValidateDueDate(DateTime? dueDate, ValidationContext context)
        {
            // 编辑模式下，如果是null或未来/今天日期，都通过
            if (!dueDate.HasValue || dueDate.Value.Date >= DateTime.Today)
            {
                return ValidationResult.Success;
            }

            // 如果是过去的日期，给出警告但不阻止（可根据需求调整）
            return new ValidationResult("⚠️ 警告：该截止日期已经过去，是否继续？");
        }

        #endregion
    }
}
```

### 3.2 Data Annotations 特性详解

#### 内置验证特性一览表

| 特性名 | 用途 | 示例 |
|--------|------|------|
| `[Required]` | 必填验证 | 用户名、标题 |
| `[StringLength]` | 字符串长度 | 密码长度限制 |
| `[Range]` | 数值范围 | 年龄、优先级 |
| `[RegularExpression]` | 正则表达式 | 邮箱、电话格式 |
| `[Compare]` | 字段比较 | 确认密码 |
| `[EmailAddress]` | 邮箱格式 | 联系邮箱 |
| `[Url]` | URL格式 | 个人网站 |
| `[Phone]` | 电话号码 | 联系方式 |
| `[CreditCard]` | 信用卡号 | 支付信息 |
| `[DataType]` | 数据类型提示 | Date, Password, etc. |
| `[Display]` | 显示名称 | 表单标签文本 |
| `[CustomValidation]` | 自定义验证 | 业务规则 |

#### 自定义验证特性示例

除了使用`[CustomValidation]`，我们还可以创建**可复用的自定义验证特性**：

**文件位置：** `src/TodoApp.Api/Attributes/FutureDateAttribute.cs`

```csharp
using System;
using System.ComponentModel.DataAnnotations;

namespace TodoApp.Api.Attributes
{
    /// <summary>
    /// 自定义验证特性：确保日期是今天或未来的日期
    /// 可复用于任何需要此规则的属性
    /// </summary>
    [AttributeUsage(AttributeTargets.Property | AttributeTargets.Field | AttributeTargets.Parameter,
                   AllowMultiple = false)]
    public class FutureDateAttribute : ValidationAttribute
    {
        /// <summary>
        /// 是否允许今天的日期（默认true）
        /// </summary>
        public bool AllowToday { get; set; } = true;

        /// <summary>
        /// 构造函数
        /// </summary>
        public FutureDateAttribute()
            : base("{0} 必须是未来的日期")
        {
        }

        /// <summary>
        /// 重写验证逻辑
        /// </summary>
        /// <param name="value">要验证的值</param>
        /// <returns>验证结果</returns>
        public override bool IsValid(object value)
        {
            // 如果值为空或null，返回true（由[Required]处理）
            if (value == null)
            {
                return true;
            }

            if (value is DateTime dateValue)
            {
                if (AllowToday)
                {
                    // 允许今天及以后
                    return dateValue.Date >= DateTime.Today;
                }
                else
                {
                    // 只允许严格未来的日期
                    return dateValue.Date > DateTime.Today;
                }
            }

            // 如果不是DateTime类型，返回false
            return false;
        }

        /// <summary>
        /// 格式化错误消息
        /// </summary>
        protected override ValidationResult? IsValid(object value, ValidationContext validationContext)
        {
            if (!IsValid(value))
            {
                var errorMessage = string.Format(ErrorMessageString,
                    validationContext.DisplayName ?? validationContext.MemberName);

                return new ValidationResult(errorMessage);
            }

            return ValidationResult.Success;
        }
    }
}
```


## 四、Controller中的验证处理

### 4.1 ModelState验证检查

在Controller的POST Action中，必须检查`ModelState.IsValid`：

```csharp
[HttpPost]
[ValidateAntiForgeryToken]
public async Task<IActionResult> Create(TodoCreateViewModel model)
{
    // 🔍 关键步骤1：检查模型验证状态
    if (!ModelState.IsValid)
    {
        // 记录验证失败的详细信息（调试用）
        foreach (var state in ModelState)
        {
            if (state.Value.Errors.Count > 0)
            {
                foreach (var error in state.Value.Errors)
                {
                    _logger.LogWarning(
                        "验证失败 - 字段: {Field}, 错误: {Error}",
                        state.Key,
                        error.ErrorMessage
                    );
                }
            }
        }

        // ❌ 验证失败：返回视图并显示错误信息
        // 注意：这里返回model以保留用户输入的数据
        return View(model);
    }

    // ✅ 验证通过：执行业务逻辑
    try
    {
        // ... 业务代码 ...
    }
    catch (Exception ex)
    {
        // 手动添加模型错误
        ModelState.AddModelError(string.Empty, $"系统错误: {ex.Message}");
        return View(model);
    }
}
```

### 4.2 手动添加错误消息

除了自动验证，还可以手动向ModelState添加错误：

```csharp
// 场景1：全局错误（显示在ValidationSummary中）
ModelState.AddModelError(string.Empty, "发生了一个未知错误");

// 场景2：特定字段的错误
ModelState.AddModelError("Title", "这个标题已经被使用了");

// 场景3：从异常中提取错误
catch (DbUpdateException ex)
{
    if (ex.InnerException?.Message.Contains("UNIQUE") == true)
    {
        ModelState.AddModelError("Title", "标题重复，请使用其他名称");
    }
}
```

### 4.3 AJAX请求的验证响应

对于AJAX请求，返回JSON格式的验证错误：

```csharp
[HttpPost]
public IActionResult ValidateAjax([FromBody] TodoCreateViewModel model)
{
    if (!ModelState.IsValid)
    {
        // 返回字段级别的错误
        var errors = ModelState
            .Where(kvp => kvp.Value.Errors.Count > 0)
            .ToDictionary(
                kvp => kvp.Key,
                kvp => kvp.Value.Errors.Select(e => e.ErrorMessage).ToArray()
            );

        return Json(new { success = false, errors });
    }

    return Json(new { success = true });
}
```

## 五、视图中的错误显示

### 5.1 ValidationSummary（验证摘要）

在表单顶部显示所有错误的汇总：

```html
<!-- 显示所有验证错误 -->
<div asp-validation-summary="All" class="text-danger"></div>

<!-- 或只显示模型级别错误 -->
<div asp-validation-summary="ModelOnly" class="text-danger"></div>

<!-- 排除属性级别错误（只显示我们自己添加的错误）-->
<div asp-validation-summary="ModelOnly" class="alert alert-danger">
    <strong>发现以下问题：</strong>
    <ul>
        @foreach (var error in ViewData.ModelState.Values.SelectMany(v => v.Errors))
        {
            <li>@error.ErrorMessage</li>
        }
    </ul>
</div>
```

**ValidationSummary模式对比：**

| 模式 | 显示内容 | 使用场景 |
|------|---------|---------|
| `None` | 不显示摘要 | 自定义错误显示 |
| `ModelOnly` | 只显示模型级别错误 | 配合字段错误使用 ⭐推荐 |
| `All` | 所有错误（模型+字段） | 简单表单 |

### 6.2 自定义jQuery验证规则

扩展jQuery Validation以满足特殊需求：

```javascript
// 文件：wwwroot/js/custom-validation.js

$(document).ready(function () {

    // ============================================
    // 自定义验证方法：不允许纯空格
    // ============================================
    $.validator.addMethod("noSpaceOnly", function (value, element) {
        return this.optional(element) || $.trim(value) !== '';
    }, "不能只输入空格");

    // ============================================
    // 自定义验证方法：禁止特殊字符（除基本标点外）
    // ============================================
    $.validator.addMethod("noSpecialChars", function (value, element) {
        if (this.optional(element)) return true;
        // 允许：中文、英文、数字、空格、基本标点
        return /^[\u4e00-\u9fa5a-zA-Z0-9\s\-\.,!?;:()\[\]{}\"'\/\\@#$%^&*+=]+$/.test(value);
    }, "包含不允许的特殊字符");

    // ============================================
    // 自定义验证方法：日期范围
    // ============================================
    $.validator.addMethod("futureDate", function (value, element) {
        if (this.optional(element)) return true;
        var selectedDate = new Date(value);
        var today = new Date();
        today.setHours(0, 0, 0, 0);
        selectedDate.setHours(0, 0, 0, 0);
        return selectedDate >= today;
    }, "日期不能是过去的");

    // ============================================
    // 应用自定义规则到对应字段
    // ============================================
    $('form').each(function () {
        $(this).validate({
            // 错误元素包装
            errorElement: 'span',

            // 错误CSS类
            errorClass: 'field-validation-error',

            // 有效时的CSS类
            validClass: 'field-validation-valid',

            // 高亮显示错误字段
            highlight: function (element, errorClass, validClass) {
                $(element).addClass('input-validation-error').removeClass(validClass);
                // 添加抖动动画
                $(element).effect ? $(element).effect('shake') : null;
            },

            // 取消高亮
            unhighlight: function (element, errorClass, validClass) {
                $(element).removeClass('input-validation-error').addClass(validClass);
            },

            // 错误消息位置
            errorPlacement: function (error, element) {
                if (element.parent('.input-group').length) {
                    error.insertAfter(element.parent());  // input-group后面
                } else {
                    error.insertAfter(element);  // 默认在元素后面
                }
            },

            // 提交处理程序
            submitHandler: function (form) {
                // 可以在这里添加额外的客户端逻辑
                form.submit();
            }
        });
    });
});
```

## 七、远程验证（Remote Attribute）

### 7.1 场景：标题唯一性检查

当用户输入标题时，实时检查是否已被使用。

#### 步骤1：在ViewModel中添加Remote特性

```csharp
using Microsoft.AspNetCore.Mvc;

// 在TodoCreateViewModel中修改Title属性：

[Required(ErrorMessage = "⛔ 标题是必填项")]
[StringLength(200, MinimumLength = 2)]
[Remote(action: "VerifyTitle", controller: "Todo",
       HttpMethod = "post",
       ErrorMessage = "😅 该标题已存在，请使用其他名称")]
[Display(Name = "标题")]
public string Title { get; set; } = string.Empty;
```

#### 步骤2：在Controller中添加验证Action

```csharp
/// <summary>
/// 远程验证：检查标题是否唯一
/// AJAX调用，返回JSON结果
/// POST: /Todo/VerifyTitle
/// </summary>
[AcceptVerbs("GET", "POST")]  // GET用于初始验证，POST用于表单提交
public async Task<JsonResult> VerifyTitle(string title)
{
    if (string.IsNullOrWhiteSpace(title))
    {
        return Json("标题不能为空");
    }

    try
    {
        // 查询是否存在相同标题的记录（忽略大小写）
        var exists = await _todoService.TitleExistsAsync(title.Trim());

        if (exists)
        {
            return Json($"标题 \"{title}\" 已被使用");
        }

        return Json(true);  // 表示验证通过
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, "标题唯一性验证失败");
        return Json("验证服务暂时不可用，请稍后再试");
    }
}
```

#### 步骤3：在Service中添加查询方法

```csharp
// ITodoService接口新增：
Task<bool> TitleExistsAsync(string title);

// TodoService实现：
public async Task<bool> TitleExistsAsync(string title)
{
    if (string.IsNullOrWhiteSpace(title))
        return false;

    var todos = await _repository.GetAllAsync();
    return todos.Any(t =>
        t.Title.Equals(title.Trim(), StringComparison.OrdinalIgnoreCase));
}
```

## 十、常见问题及解决方案

### 问题1：客户端验证不生效

**现象：** 表单可以直接提交到服务端，前端没有拦截

**排查步骤：**

1. **确认脚本加载顺序**
   ```html
   <!-- 正确顺序 -->
   <script src="jquery.js"></script>                          <!-- 1. jQuery -->
   <script src="jquery.validate.js"></script>                 <!-- 2. Validate核心 -->
   <script src="jquery.validate.unobtrusive.js"></script>     <!-- 3. Unobtrusive适配器 -->
   ```

2. **检查data属性**
   - 右键点击输入框 → 检查元素
   - 应该看到 `data-val="true"` 和 `data-val-required="..."` 属性
   - 如果没有，说明Tag Helper未正确生成

3. **确认表单标签**
   ```html
   <!-- 必须是form标签，不能是div模拟 -->
   <form asp-action="Create">...</form>
   ```

4. **检查浏览器控制台**
   - F12打开开发者工具 → Console
   - 查看是否有JavaScript错误

---

### 问题2：自定义验证特性不触发

**现象：** `[CustomValidation]` 方法不被调用

**解决方案：**

1. **方法必须是static**
   ```csharp
   // ❌ 错误：实例方法
   public ValidationResult Validate() { ... }

   // ✅ 正确：静态方法
   public static ValidationResult Validate(...) { ... }
   ```

2. **方法签名正确**
   ```csharp
   // 正确签名
   public static ValidationResult? MethodName(object value, ValidationContext context)
   ```

3. **返回值类型**
   ```csharp
   // 成功时
   return ValidationResult.Success;

   // 失败时
   return new ValidationResult("错误消息");
   
   // 或者带字段名的错误
   return new ValidationResult("错误消息", new[] { "PropertyName" });
   ```

### 问题3：远程验证频繁请求

**现象：** 每次按键都发送AJAX请求，导致服务器压力大

**优化方案：**

```javascript
// 设置防抖延迟（毫秒）
$.validator.setDefaults({
    onfocusout: false,  // 失去焦点时不立即验证
    onkeyup: false,     // 输入时不立即验证（Remote验证默认如此）
});

// 或者针对Remote字段单独设置延迟
$('input[data-val-remote]').on('input', function() {
    var $this = $(this);
    clearTimeout($this.data('timer'));
    $this.data('timer', setTimeout(function() {
        $this.removeData('timer');
        // 触发验证
        $this.valid();
    }, 800));  // 800ms延迟
});
```

### 问题4：中文字符计数不准确

**现象：** 英文按字符计数，但中文应该按字计数更合理

**解决方案：**

```javascript
// 统计实际字符数（中文字算1个）
function countCharacters(text) {
    return [...text].length;  // ES6展开运算符，正确处理Unicode
}

// 或者考虑中文占位更多
function displayCount(text) {
    const len = [...text].length;
    // 中文按2个宽度计算（近似）
    const displayLen = Array.from(text).reduce((acc, char) => {
        return acc + (char.charCodeAt(0) > 0x4E00 ? 2 : 1);
    }, 0);
    
    return `${len}字符 (${displayLen}宽度)`;
}
```

## 附录：常用正则表达式参考

| 用途 | 正则表达式 | 说明 |
|------|-----------|------|
| **中文** | `^[\u4e00-\u9fa5]+$` | 仅中文字符 |
| **英文** | `^[a-zA-Z]+$` | 仅英文字母 |
| **数字** | `^\d+$` | 仅数字 |
| **用户名** | `^[a-zA-Z0-9_]{4,16}$` | 4-16位字母数字下划线 |
| **邮箱** | `^\w+([-+.]\w+)*@\w+([-.]\w+)*\.\w+([-.]\w+)*$` | 标准邮箱格式 |
| **手机号** | `^1[3-9]\d{9}$` | 中国大陆手机号 |
| **密码强度** | `^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)[a-zA-Z\d]{8,}$` | 至少大小写字母和数字 |
| **URL** | `^https?:\/\/.+` | HTTP/HTTPS链接 |
| **IP地址** | `^((25[0-5]|2[0-4]\d|[01]?\d\d?)\.){3}(25[0-5]|2[0-4]\d|[01]?\d\d?)$` | IPv4地址 |
| **不含特殊字符** | `^[\u4e00-\u9fa5a-zA-Z0-9\s\-\.,!?]+$` | 常用字符（本项目使用） |
