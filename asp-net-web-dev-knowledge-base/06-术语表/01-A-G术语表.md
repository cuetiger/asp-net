# ASP.NET/Web开发术语表（A-G）

> 本文档收录A-G开头的ASP.NET及Web开发核心术语，按字母顺序排列，供学习过程中快速查阅。

---

## A

### API (Application Programming Interface) - 应用程序编程接口
- **定义**：软件组件之间进行交互的约定和工具集合，定义了请求和响应的格式规范
- **通俗理解**：就像餐厅菜单——你不需要知道厨房怎么做饭，只需要知道点什么菜、菜长什么样
- **所属领域**：Web开发/后端开发/系统集成
- **相关术语**：RESTful API, SDK, Library, Endpoint
- **相关教程**：[[进阶篇/01-RESTful-API/01-REST原则与最佳实践]]

### ASP.NET Core - ASP.NET核心框架
- **定义**：微软推出的开源、跨平台的高性能Web开发框架，是.NET生态系统中的主流Web开发技术栈
- **通俗理解**：构建网站和应用的基础"脚手架"，提供了路由、依赖注入、中间件等开箱即用的功能
- **所属领域**：.NET/Web框架/后端开发
- **相关术语**：.NET, MVC, Razor, Middleware, Kestrel
- **相关教程**：[[入门篇/01-环境搭建与第一个项目]]

### Async/Await - 异步编程模式
- **定义**：C#中用于编写异步代码的关键字组合，async标记异步方法，await等待异步操作完成而不阻塞线程
- **通俗理解**：就像点外卖——下单后不用一直等在店门口，可以先做别的事，外卖到了再取
- **所属领域**：C#编程/并发编程
- **相关术语**：Task, Thread, Promise, Callback, Concurrency
- **相关教程**：[[基础篇/05-C#高级特性/01-异步编程]]

### Assembly - 程序集
- **定义**：.NET中的编译输出单元，包含中间语言(IL)代码、类型元数据和资源，通常以.dll或.exe为扩展名
- **通俗理解**：一个打包好的"功能盒子"，里面装着编译好的代码和相关资源，可供其他程序引用使用
- **所属领域**：.NET运行时/编译原理
- **相关术语**：DLL, IL, CLR, GAC, NuGet Package
- **相关教程**：[[基础篇/02-.NET运行时基础]]

### Attribute - 特性/注解
- **定义**：一种将声明性信息（元数据）附加到程序元素（类、方法、属性等）上的机制，可在运行时通过反射读取
- **通俗理解**：给代码贴的"标签"，告诉程序或框架这个代码片段有什么特殊属性或要求
- **所属领域**：C#编程/元编程
- **相关术语**：Reflection, Annotation, Data Annotation, Metadata
- **相关教程**：[[基础篇/04-C#面向对象/03-特性与反射]]

### AOP (Aspect-Oriented Programming) - 面向切面编程
- **定义**：一种编程范式，通过将横切关注点（如日志、事务、安全）从业务逻辑中分离出来，以"切面"的形式统一管理
- **通俗理解**：像给所有门统一安装防盗锁——不需要每扇门单独处理，而是用一个统一的方案搞定所有门
- **所属领域**：软件架构/设计模式
- **相关术语**：Interceptor, Middleware, Decorator, Cross-cutting Concern
- **相关教程**：[[进阶篇/03-设计模式/08-AOP与拦截器]]

### Abstract Class - 抽象类
- **定义**：不能被实例化的类，可以包含抽象成员（只有声明没有实现）和具体实现，用作基类被其他类继承
- **通俗理解**："动物"是一个抽象类——你不能创建一只纯粹的"动物"，但可以创建继承它的"猫"或"狗"
- **所属领域**：C#编程/OOP
- **相关术语**：Interface, Inheritance, Polymorphism, Virtual Method
- **相关教程**：[[基础篇/04-C#面向对象/01-类与对象]]

### Aggregation - 聚合关系
- **定义**：对象之间的一种关联关系，表示"整体-部分"关系但部分可以独立于整体存在（弱拥有关系）
- **通俗理解**：班级和学生——班级由学生组成，但学生离开班级后依然存在
- **所属领域**：UML/OOP设计
- **相关术语**：Composition, Association, Dependency, UML
- **相关教程**：[[进阶篇/03-设计模式/01-UML与设计原则]]

### Agile - 敏捷开发
- **定义**：一种迭代式、增量式的软件开发方法论，强调快速交付可工作软件、持续反馈和团队协作
- **通俗理解**：不是一次性盖好整栋楼，而是先盖好一层就能用，边用边往上盖
- **所属领域**：软件工程/项目管理
- **相关术语**：Scrum, Kanban, Sprint, CI/CD, DevOps
- **相关教程**：[[附录篇/01-敏捷开发实践]]

### Algorithm - 算法
- **定义**：解决特定问题的一系列明确步骤或规则，描述了输入如何转换为输出的过程
- **通俗理解**：做菜的食谱——按照步骤操作，就能从食材得到成品菜肴
- **所属领域**：计算机科学/数据结构
- **相关术语**：Data Structure, Time Complexity, Sorting, Searching
- **相关教程**：[[基础篇/06-数据结构与算法入门]]

### Array - 数组
- **定义**：一种存储固定大小的同类型元素的有序集合，通过索引（下标）访问每个元素
- **通俗理解**：一排编号的储物柜——每个柜子放一样的东西，按编号找东西
- **所属领域**：数据结构/C#编程
- **相关术语**：List, Collection, Index, IEnumerable
- **相关教程**：[[基础篇/03-C#基础语法/04-数组与集合]]

### Authentication - 认证
- **定义**：验证用户身份的过程，确认"你是谁"，常见方式包括用户名密码、JWT令牌、OAuth2等
- **通俗理解**：像进门刷身份证——保安检查你的证件，确认身份后才让进
- **所属领域**：安全/身份管理
- **相关术语**：Authorization, JWT, OAuth2, Identity, Cookie, Session
- **相关教程**：[[进阶篇/05-安全与认证/01-认证与授权基础]]

### Authorization - 授权
- **定义**：确定已认证用户是否有权执行特定操作或访问特定资源的过程，即"你能做什么"
- **通俗理解**：像不同级别的门禁卡——虽然你知道我是谁（认证），但还要看我有没有权限进入这个房间（授权）
- **所属领域**：安全/权限管理
- **相关术语**：Authentication, RBAC, Role, Policy, Claim
- **相关教程**：[[进阶篇/05-安全与认证/02-基于角色的访问控制]]

### Auto-Mapping - 自动映射
- **定义**：在不同对象模型之间自动进行属性值复制的机制，常用于DTO与Entity之间的转换
- **通俗理解**：像搬家时的自动打包服务——你告诉它源地址和目标地址，它自动把对应物品搬过去
- **所属领域**：数据映射/工具库
- **相关术语**：DTO, Entity, AutoMapper, Projection, Value Object
- **相关教程**：[[进阶篇/02-EF Core/04-数据传输对象与映射]]

### Azure - 微软云平台
- **定义**：微软提供的云计算服务平台，提供计算、存储、数据库、AI等各种云服务，支持托管ASP.NET应用
- **通俗理解**：微软经营的"超级数据中心"——你不用自己买服务器，租用它的基础设施来跑你的应用
- **所属领域**：云计算/DevOps
- **相关术语**：Cloud, App Service, Azure SQL, Docker, Kubernetes
- **相关教程**：[[进阶篇/07-部署与运维/02-部署到Azure]]

## B

### Blazor - Blazor框架
- **定义**：ASP.NET Core中的Web UI框架，允许使用C#和HTML构建交互式客户端Web应用，支持WebAssembly和服务端渲染两种模式
- **通俗理解**：用C#代替JavaScript写前端网页——对.NET开发者来说太友好了
- **所属领域**：.NET/Web前端/全栈
- **相关术语**：Razor, WebAssembly, SignalR, Component, SPA
- **相关教程**：[[进阶篇/09-Blazor开发/01-Blazor基础入门]]

### Backend - 后端
- **定义**：应用程序的服务器端部分，负责数据处理、业务逻辑实现、API提供、数据库交互等核心功能
- **通俗理解**：餐厅的厨房——顾客看不到但负责实际烹饪和处理订单的地方
- **所属领域**：软件架构/Web开发
- **相关术语**：Frontend, Server, API, Database, Business Logic
- **相关教程**：[[入门篇/02-前后端分离概念]]

### Base Class - 基类
- **定义**：被其他类继承的父类，提供通用的属性和方法供子类复用和扩展
- **通俗理解**：手机的"基础款"——厂商在此基础上推出各种升级版（子类），都继承了基础款的功能
- **所属领域**：OOP/C#编程
- **相关术语**：Derived Class, Inheritance, Abstract Class, Override
- **相关教程**：[[基础篇/04-C#面向对象/01-类与对象]]

### Binding - 绑定
- **定义**：将数据源与UI元素或组件属性关联起来的机制，当数据变化时UI自动更新（数据绑定）
- **通俗理解**：像温度计和水银柱的关系——水温变化时，水银柱自动升降显示当前温度
- **所属领域**：数据绑定/UI开发
- **相关术语**：Model Binding, Data Binding, Two-way Binding, ViewModel
- **相关教程**：[[基础篇/08-MVC基础/03-模型绑定]]

### Bootstrap - Bootstrap框架
- **定义**：最流行的前端CSS框架，提供响应式网格系统、预定义样式组件和JavaScript插件，加速Web界面开发
- **通俗理解**：装修用的"精装套餐"——按钮、表单、导航栏都有现成好看的样式，拿来就用
- **所属领域**：前端开发/CSS框架
- **相关术语**：CSS, Responsive Design, Grid System, Frontend Framework
- **相关教程**：[[入门篇/04-前端基础/02-CSS与Bootstrap]]

### Breakpoint - 断点
- **定义**：调试时设置的代码位置标记，程序执行到此处会暂停，允许开发者检查变量状态和调用栈
- **通俗理解**：视频播放器的暂停键——程序跑到这里停下来，让你看看当时发生了什么
- **所属领域**：调试/IDE
- **相关术语**：Debug, Watch Window, Call Stack, Step Over
- **相关教程**：[[附录篇/02-调试技巧指南]]

### Build - 构建
- **定义**：将源代码编译、链接并打包成可执行文件或发布包的过程
- **通俗理解**：把原材料（源代码）加工成最终产品（可运行的程序）的生产过程
- **所属领域**：构建工具/DevOps
- **相关术语**：Compile, MSBuild, Release, Publish, CI/CD
- **相关教程**：[[进阶篇/07-部署与运维/01-项目构建与发布]]

### Bundling - 打包/捆绑
- **定义**：将多个CSS或JavaScript文件合并成一个文件的过程，减少HTTP请求数量以提高页面加载性能
- **通俗理解**：快递打包——本来要寄10个小包裹，捆成一个大包裹一起寄，省运费又省时间
- **所属领域**：前端优化/性能调优
- **相关术语**：Minification, Webpack, Asset Optimization, HTTP/2
- **相关教程**：[[进阶篇/06-性能优化/02-前端资源优化]]

### Bytecode - 字节码
- **定义**：一种中间表示形式的指令集，介于源代码和机器码之间，需要虚拟机或运行时解释执行
- **通俗理解**：世界语——不是任何国家的母语，但各国人都能通过翻译器（虚拟机）理解和执行
- **所属领域**：编译原理/运行时
- **相关术语**：IL, JVM, CLR, Machine Code, Interpreter
- **相关教程**：[[基础篇/02-.NET运行时基础]]

### Business Logic Layer (BLL) - 业务逻辑层
- **定义**：分层架构中的一层，负责处理应用程序的核心业务规则和工作流程，位于表现层和数据访问层之间
- **通俗理解**：公司的"决策部门"——接收需求后根据规则做出判断和决定
- **所属领域**：软件架构/分层设计
- **相关术语**：DAL, Presentation Layer, Three-tier Architecture, Service Layer
- **相关教程**：[[进阶篇/04-架构设计/02-分层架构详解]]

### Bounded Context - 限界上下文
- **定义**：DDD（领域驱动设计）中的核心概念，指一个特定的边界内，某个领域模型具有明确且一致的含义
- **通俗理解**：同一个词在不同部门有不同意思——"订单"在销售部和财务部的含义和规则就不一样
- **所属领域**：DDD/领域建模
- **相关术语**：Domain, Ubiquitous Language, Context Map, DDD
- **相关教程**：[[进阶篇/04-架构设计/05-领域驱动设计(DDD)]]

### Batch Processing - 批处理
- **定义**：将大量任务或数据集中在一起一次性处理的方式，而非逐个实时处理
- **通俗理解**：像洗碗机——攒够一批碗筷后一起洗，比一个个手洗效率高很多
- **所属领域**：数据处理/后台任务
- **相关术语**：Background Job, Queue, Scheduler, Hangfire
- **相关教程**：[[进阶篇/08-后台任务与调度]]

## C

### C# - C Sharp编程语言
- **定义**：微软开发的现代、类型安全的面向对象编程语言，是.NET平台的主要开发语言
- **通俗理解**：.NET世界的"官方语言"——语法优雅、功能强大，适合从桌面到云的各种开发场景
- **所属领域**：编程语言/.NET
- **相关术语**：.NET, CLR, Visual Studio, OOP, Type Safety
- **相关教程**：[[基础篇/03-C#基础语法/01-C#语言概述]]

### CLR (Common Language Runtime) - 公共语言运行时
- **定义**：.NET框架的核心执行引擎，负责内存管理（GC）、异常处理、安全性、JIT编译等运行时服务
- **通俗理解**：.NET程序的"操作系统"——管理程序运行所需的一切底层事务
- **所属领域**：.NET运行时
- **相关术语**：.NET, IL, GC, JIT, Assembly, BCL
- **相关教程**：[[基础篇/02-.NET运行时基础/01-CLR与执行模型]]

### CLI (Common Language Infrastructure) - 公共语言基础设施
- **定义**：规定.NET应用程序运行环境的开放标准规范，包括CTS（通用类型系统）、CLS（公共语言规范）和CLR等组成部分
- **通俗理解**：.NET世界的"宪法"——规定了所有.NET语言和运行时必须遵循的基本规则
- **所属领域**：.NET标准/ECMA标准
- **相关术语**：CLR, CTS, CLS, IL, .NET Standard
- **相关教程**：[[基础篇/02-.NET运行时基础]]

### Class - 类
- **定义**：面向对象编程中的基本构造单元，定义了一类对象的属性（字段）和行为（方法）的蓝图或模板
- **通俗理解**：汽车的"设计图纸"——按照这张图纸可以制造出无数辆具体的汽车（对象）
- **所属领域**：OOP/C#编程
- **相关术语**：Object, Instance, Field, Method, Property, Constructor
- **相关教程**：[[基础篇/04-C#面向对象/01-类与对象]]

### Constructor - 构造函数
- **定义**：类中特殊的方法，在创建对象实例时自动调用，用于初始化对象的状态
- **通俗理解**：新员工入职培训——刚招进来的人（新对象）先经过这个过程了解岗位要求和初始设置
- **所属领域**：OOP/C#编程
- **相关术语**：Class, Instance, Initialization, Destructor, this
- **相关教程**：[[基础篇/04-C#面向对象/01-类与对象]]

### Clean Architecture - 整洁架构
- **定义**：一种软件架构模式，强调依赖方向始终指向内部（核心业务逻辑），外部层次依赖内部层次，使核心逻辑独立于框架、UI和数据库
- **通俗理解**：洋葱模型——核心业务像洋葱心，外层依次是接口适配、框架、基础设施，每一层只依赖内层
- **所属领域**：软件架构/设计模式
- **相关术语**：SOLID, DIP, Onion Architecture, Hexagonal Architecture
- **相关教程**：[[进阶篇/04-架构设计/03-整洁架构实践]]

### Closure - 闭包
- **定义**：函数与其引用的外部变量（词法环境）的组合，即使在外部函数返回后仍能访问这些变量
- **通俗理解**：带记忆的信封——函数不仅包含执行的代码，还"记住"了创建时周围的环境变量
- **所属领域**：函数式编程/C#
- **相关术语**：Lambda, Delegate, Anonymous Method, Scope
- **相关教程**：[[基础篇/05-C#高级特性/03-Lambda与闭包]]

### Collection - 集合
- **定义**：.NET中用于存储和管理一组对象的类的统称，包括List、Dictionary、Queue、Stack等多种数据结构
- **通俗理解**：各种容器——列表像排队的人、字典像查号簿、队列像候车队伍
- **所属领域**：数据结构/.NET BCL
- **相关术语**：IEnumerable, IList, Dictionary<T,K>, List, Array
- **相关教程**：[[基础篇/03-C#基础语法/04-数组与集合]]

### COM (Component Object Model) - 组件对象模型
- **定义**：微软的二进制接口标准，允许不同语言编写的软件组件相互通信，是Windows平台上组件化编程的基础
- **通俗理解**：不同品牌零件的"通用接口标准"——只要符合COM规格，任何零件都能装到一起协作
- **所属领域**：Windows编程/互操作
- **相关术语**：Interop, P/Invoke, RCW, CCW, COM+
- **相关教程**：[[进阶篇/10-.NET互操作]]

### Component - 组件
- **定义**：可独立开发、测试和复用的软件单元，具有明确定义的接口，封装了特定的功能
- **通俗理解**：乐高积木块——每个积木有固定的形状和连接口，可以自由拼搭成各种造型
- **所属领域**：软件工程/组件化开发
- **相关术语**：Module, Reusability, Interface, Encapsulation, Blazor Component
- **相关教程**：[[进阶篇/09-Blazor开发/02-组件化开发]]

### Composition - 组合关系
- **定义**：对象间的一种强关联关系，表示整体拥有部分且部分不能脱离整体独立存在（强拥有关系）
- **通俗理解**：人和心脏——心脏是人的一部分，人没了心脏就不能活，心脏离了人也没意义
- **所属领域**：UML/OOP设计
- **相关术语**：Aggregation, Association, "Has-a", UML
- **相关教程**：[[进阶篇/03-设计模式/01-UML与设计原则]]

### Concurrency - 并发
- **定义**：多个任务在同一时间段内交替执行的能力，看起来像是同时运行但实际上可能是在单个处理器上切换
- **通俗理解**：一个人同时应付多件事——一会儿回邮件，一会儿接电话，来回切换但看起来都在处理
- **所属领域**：多线程/并行编程
- **相关术语**：Parallelism, Thread, Async/Await, Task, Race Condition
- **相关教程**：[[基础篇/05-C#高级特性/02-多线程基础]]

### Configuration - 配置
- **定义**：应用程序的可调整参数和设置，通常存储在配置文件（如appsettings.json）中，控制应用行为而无需重新编译
- **通俗理解**：应用的"设置菜单"——你可以改数据库连接字符串、日志级别等，不用改代码
- **所属领域**：应用配置/DevOps
- **相关术语**：appsettings.json, Options Pattern, Environment Variable, IConfiguration
- **相关教程**：[[基础篇/08-MVC基础/06-配置管理]]

### Connection Pool - 连接池
- **定义**：预先创建并维护的一组数据库连接，应用程序需要时从池中获取，用完归还，避免频繁创建销毁连接的开销
- **通俗理解**：共享单车池——用完的车归还原处，下个人直接骑走，不用每次都造一辆新车
- **所属领域**：数据库/性能优化
- **相关术语**：Database, EF Core, Connection String, Performance
- **相关教程**：[[进阶篇/02-EF Core/03-性能优化技巧]]

### Container - 容器
- **定义**：轻量级的操作系统级虚拟化技术，将应用程序及其依赖打包成独立的可移植运行单元（如Docker容器）
- **通俗理解**：标准化集装箱——不管里面装什么货物，集装箱的尺寸和接口都是统一的，方便运输和部署
- **所属领域**：Docker/云原生/DevOps
- **相关术语**：Docker, Image, Kubernetes, Pod, Containerization

### Controller - 控制器
- **定义**：MVC架构模式中的组件，负责接收用户请求、调用业务逻辑处理、选择视图返回响应，充当模型和视图之间的协调者
- **通俗理解**：餐厅服务员——接收顾客点单（请求），传达给厨房（模型），然后把做好的菜端给顾客（视图）
- **所属领域**：MVC/ASP.NET Core

### Cookie - Cookie/小甜饼
- **定义**：服务器发送到浏览器并保存在本地的小段文本数据，后续请求时会自动携带，用于状态保持（如登录态、购物车）
- **通俗理解**：餐厅给的会员卡——下次来的时候出示卡片，餐厅就知道你是谁、有什么偏好

### CORS (Cross-Origin Resource Sharing) - 跨域资源共享
- **定义**：一种HTTP机制，允许受限资源（如API）被指定来源之外的网页访问，通过特殊的HTTP头实现跨域安全控制

## D

### DDD (Domain-Driven Design) - 领域驱动设计
- **定义**：一种软件开发方法论，以领域模型为核心，通过与领域专家紧密合作来构建反映真实业务复杂性的软件系统
- **通俗理解**：先搞懂业务再写代码——深入理解业务领域的规则和术语，用代码精确表达这些知识
- **所属领域**：软件架构/设计方法论
- **相关术语**：Domain, Entity, Value Object, Bounded Context, Aggregate Root
- **相关教程**：[[进阶篇/04-架构设计/05-领域驱动设计(DDD)]]

### DLL (Dynamic Link Library) - 动态链接库
- **定义**：Windows平台上的共享库文件格式，包含可被多个程序同时使用的代码和数据，运行时动态加载
- **通俗理解**：公共工具箱——多个程序都可以借用里面的工具（函数），不用各自带一份
- **所属领域**：Windows/.NET
- **相关术语**：Assembly, GAC, P/Invoke, Native Code
- **相关教程**：[[基础篇/02-.NET运行时基础]]

### DTO (Data Transfer Object) - 数据传输对象
- **定义**：用于在进程或层之间传输数据的简单对象，通常只包含属性而没有行为，起到数据载体的作用
- **通俗理解**：快递包裹——只负责把数据从一个地方运到另一个地方，不关心也不处理数据
- **所属领域**：设计模式/数据架构
- **相关术语**：Entity, ViewModel, Auto-Mapping, Serialization
- **相关教程**：[[进阶篇/02-EF Core/04-数据传输对象与映射]]

### DI (Dependency Injection) - 依赖注入
- **定义**：一种设计模式，将对象的依赖关系由外部容器（如ASP.NET Core的DI容器）在运行时自动注入，而非对象自行创建
- **通俗理解**：外卖配送——你（对象）不用自己做饭（创建依赖），外卖员（DI容器）把饭菜送到你手上
- **所属领域**：设计模式/IOC
- **相关术语**：IOC, DIP, Service Lifetime, Constructor Injection, IServiceProvider
- **相关教程**：[[进阶篇/03-设计模式/04-依赖注入详解]]

### DIP (Dependency Inversion Principle) - 依赖倒置原则
- **定义**：SOLID原则之一，高层模块不应依赖低层模块，两者都应依赖于抽象；抽象不应依赖于细节，细节应依赖于抽象
- **通俗理解**：插头和插座——电器（高层）不直接依赖某品牌的电线（低层），而是依赖标准的插座接口（抽象）
- **所属领域**：设计模式/SOLID
- **相关术语**：SOLID, DI, IOC, Interface, Abstraction
- **相关教程**：[[进阶篇/03-设计模式/02-SOLID原则]]

### Database - 数据库
- **定义**：按照数据结构组织、存储和管理数据的仓库系统，支持数据的增删改查、事务、索引等功能
- **通俗理解**：电子化的档案柜——有序地存放大量数据，能快速查找和更新
- **所属领域**：数据存储/后端开发
- **相关术语**：SQL, Table, Schema, Index, Transaction, Connection Pool
- **相关教程**：[[基础篇/07-数据库基础/01-SQL与关系型数据库]]

### Data Annotation - 数据标注
- **定义**：通过Attribute（特性）为模型属性添加验证规则、显示名称、格式等元数据的方式
- **通俗理解**：给表格填写的"说明标签"——这格只能填数字、那格必填、最大长度是多少
- **所属领域**：数据验证/MVC
- **相关术语**：Attribute, Validation, Model State, Fluent Validation
- **相关教程**：[[基础篇/08-MVC基础/05-数据验证]]

### Debug - 调试
- **定义**：发现、定位和修复程序错误（Bug）的过程，通常使用断点、单步执行、变量监视等工具辅助
- **通俗理解**：像医生诊断病情——通过各种检查手段找出病因（Bug所在），然后对症治疗
- **所属领域**：开发工具/质量保障
- **相关术语**：Breakpoint, Watch, Call Stack, Exception, Log
- **相关教程**：[[附录篇/02-调试技巧指南]]

### Deploy - 部署
- **定义**：将开发完成的应用程序安装或发布到生产环境中使其对外提供服务的过程
- **通俗理解**：开店营业——把准备好的产品摆上货架，正式开始接待客户
- **所属领域**：DevOps/运维
- **相关术语**：Release, Production, CI/CD, Hosting, Server

### Delegate - 委托
- **定义**：C#中的类型安全的函数指针，可以引用具有相同签名的方法，用于实现回调和事件机制
- **通俗理解**：任务委托书——上面写着要做什么样的任务（签名），可以把具体执行委托给任何人（方法）

### Dependency - 依赖
- **定义**：一个模块或类需要另一个模块或类才能正常工作的关系，良好的设计应尽量降低耦合度
- **通俗理解**：手机依赖电池——没电池手机就动不了，这就是依赖关系

- **通俗理解**：流水线作业——每个工序完成后自动传给下一道工序，一气呵成

### Factory Pattern - 工厂模式

- **通俗理解**：披萨店的订单系统——你只说要点什么类型的披萨（接口），厨房（工厂）负责制作具体的那种

- **通俗理解**：机场安检关卡——乘客（请求）必须依次通过各个安检站（过滤器），任何一个不通过就被拦下

- **定义**：.NET运行时自动管理内存的机制，定期检测并释放不再被程序使用的对象所占用的内存空间

- **相关术语**：CLR, Managed Memory, Generation, Dispose, Finalizer
