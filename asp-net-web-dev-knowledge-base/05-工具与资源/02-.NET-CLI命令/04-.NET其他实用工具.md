# .NET 其他实用工具

除了核心的 `dotnet new`、`dotnet ef` 等命令外，.NET 生态系统还提供了丰富的工具链，涵盖性能分析、HTTP 调试、代码生成、包管理等多个方面。本文将系统介绍这些实用工具的安装、配置和使用方法。

## 一、dotnet tool 命令详解

### 1.1 工具管理基础

#### 全局工具 vs 本地工具

```
┌─────────────────────────────────────────────────────────────┐
│                    .NET 工具类型对比                          │
├──────────────────────┬──────────────────────────────────────┤
│     全局工具          │           本地工具                     │
├──────────────────────┼──────────────────────────────────────┤
│ 安装位置：            │ 安装位置：                             │
│ ~/.dotnet/tools/     │ .config/dotnet-tools.json             │
│                      │                                      │
│ 作用域：所有项目       │ 作用域：当前项目/解决方案               │
│                      │                                      │
│ 版本控制：不纳入       │ 版本控制：纳入 Git（推荐）              │
│                      │                                      │
│ 适用场景：个人常用工具 │ 适用场景：团队共享工具                  │
│                      │                                      │
│ 示例命令：            │ 示例命令：                             │
│ dotnet tool install   │ dotnet new tool-manifest             │
│ --global <tool>       │ dotnet tool install <tool>           │
└──────────────────────┴──────────────────────────────────────┘
```

### 1.2 核心命令参考

```bash
# ===== 工具安装 =====

# 全局安装
dotnet tool install --global <PACKAGE_ID>
dotnet tool install --global dotnet-ef --version 8.0.10

# 本地安装（需先初始化 manifest）
dotnet new tool-manifest                    # 创建 .config/dotnet-tools.json
dotnet tool install <PACKAGE_ID>             # 安装到本地清单
dotnet tool install <PACKAGE_ID> --version 1.0.0  # 指定版本

# 从特定源安装
dotnet tool install <PACKAGE_ID> \
  --add-source https://nuget.example.com/v3/index.json

# ===== 工具管理 =====

# 列出已安装工具
dotnet tool list                            # 本地工具
dotnet tool list --global                   # 全局工具

# 更新工具
dotnet tool update <PACKAGE_ID>             # 更新本地工具
dotnet tool update --global <PACKAGE_ID>    # 更新全局工具
dotnet tool update --global .*              # 更新所有全局工具

# 卸载工具
dotnet tool uninstall <PACKAGE_ID>          # 卸载本地工具
dotnet tool uninstall --global <PACKAGE_ID> # 卸载全局工具

# 运行本地工具（在其他目录）
dotnet tool run <tool-name> [args]          # 使用完整路径
dotnet tool run <tool-name> [args] \
  --tool-path ./path/to/project             # 指定工具路径

# ===== 工具还原 =====
# 当克隆项目后，还原所有本地工具
dotnet tool restore
```

### 1.3 工具清单文件 (dotnet-tools.json)

```json
{
  "version": 1,
  "isRoot": true,
  "tools": {
    "dotnet-ef": {
      "version": "8.0.10",
      "commands": ["dotnet-ef"]
    },
    "dotnet-reportgenerator-globaltool": {
      "version": "5.2.0",
      "commands": ["reportgenerator"]
    },
    "dotnet-coverage": {
      "version": "17.11.3",
      "commands": ["dotnet-coverage"]
    }
  }
}
```

**配置选项说明**：

| 字段 | 说明 |
|------|------|
| `version` | 清单格式版本（当前为 1） |
| `isRoot` | 是否为根清单（子目录可继承父级清单） |
| `tools` | 已安装的工具列表 |
| `version` (tool) | 工具的具体版本号 |
| `commands` | 工具提供的可执行命令列表 |

### 2.4 性能与诊断工具

#### 7-10. Microsoft.Diagnostics.NETCore.Client 工具集

这些是 .NET 官方提供的性能分析工具：

##### dotnet-trace — 进程跟踪

```bash
# 安装
dotnet tool install -g dotnet-trace

# 收集正在运行的进程跟踪
dotnet trace collect -p <PID> --output trace.nettrace

# 启动并跟踪应用
dotnet trace collect -- ./myapp.exe

# 收集 CPU 跟踪（默认 30 秒）
dotnet trace collect -p <PID> --duration 00:00:30

# 收集 GC 信息
dotnet trace collect -p <PID> --providers Microsoft-Windows-DotNETRuntime:4

# 分析跟踪文件
dotnet trace report trace.nettrace
```

**常用 Provider 配置**：

| Provider | 级别 | 用途 |
|----------|------|------|
| `Microsoft-Windows-DotNETRuntime` | 5 (Verbose) | 完整运行时信息 |
| `Microsoft-DotNETCore-SampleProfiler` | 3 (Information) | CPU 采样 |
| `Microsoft-Windows-DotNETRuntimeRundown` | 1 (Critical) | 加载/卸载信息 |

##### dotnet-counters — 实时性能计数器

## 三、ASP.NET Core 特定工具

### 3.1 aspnet-codegenerators — 脚手架代码生成

```bash
# 此工具通常作为 SDK 内置工具使用
# 通过 dotnet aspnet-codegenerator 调用

# 生成 Controller
dotnet aspnet-codegenerator controller \
  -name ProductsController \
  -m Product \
  -dc ApplicationDbContext \
  -outDir Controllers \
  --referenceScriptLibraries \
  --useDefaultLayout \
  --restWithViews

# 生成 View
dotnet aspnet-codegenerator view \
  -name Create \
  -m Product \
  -dc ApplicationDbContext \
  -outDir Views/Product \
  --referenceScriptLibraries \
  --useDefaultLayout

# 生成 Identity 页面
dotnet aspnet-codegenerator identity \
  -dc ApplicationDbContext \
  --files Account.Register,Account.Login,Account.Logout

# 可用的生成器类型
# controller        - MVC 控制器
# view              - Razor 视图
# identity          - Identity UI 页面
# razorpage         - Razor Page
```

**常用参数说明**：

| 参数 | 说明 |
|------|------|
| `-name` / `-n` | 生成的类名 |
| `-model` / `-m` | 模型类 |
| `-dataContext` / `-dc` | DbContext 类 |
| `-outDir` / `-outdir` | 输出目录 |
| `-namespace` | 命名空间 |
| `-referenceScriptLibraries` | 引入验证脚本 |
| `-useDefaultLayout` | 使用默认布局 |
| `-restWithViews` | REST 风格 + 视图 |
| `-files` | 指定生成的文件（逗号分隔） |

### 3.2 user-secrets — 用户密钥管理

```bash
# 设置密钥
dotnet user-secrets set "ConnectionStrings:Default" "Server=(localdb);Database=MyDb;"
dotnet user-secrets set "Jwt:Secret" "your-super-secret-key"
dotnet user-secrets set "SendGrid:ApiKey" "SG.xxxxx"

# 列出所有密钥
dotnet user-secrets list

# 显示特定密钥
dotnet user-secrets get "ConnectionStrings:Default"

# 删除密钥
dotnet user-secrets remove "Jwt:Secret"

# 清除所有密钥
dotnet user-secrets clear

# 初始化（如果尚未初始化）
dotnet user-secrets init \
  --project src/MyProject \
  --id <user-secret-id>
```

**在代码中使用**：

```csharp
// Program.cs 或 Startup.cs
builder.Configuration.AddUserSecrets<Program>();

// 访问密钥
var connectionString = builder.Configuration.GetConnectionString("Default");
var jwtSecret = builder.Configuration["Jwt:Secret"];
```

**注意事项**：
- 密钥存储在用户配置目录（Windows: `%APPDATA%\microsoft\UserSecrets\`）
- 不要将 secrets.json 提交到版本控制
- 生产环境应使用环境变量或 Azure Key Vault

### 4.2 dotnet-counters 实战场景

#### 场景一：监控生产环境健康状态

```bash
# 编写监控脚本 monitor.sh
#!/bin/bash
PID=$(pgrep -f "MyApp")
echo "Monitoring process $PID..."
dotnet counters monitor -p $PID \
  --counters \
    System.Runtime[cpu-usage,working-set,gc-heap-size,exception-rate,threadpool-thread-count,active-timer-count,assembly-count], \
    Microsoft-AspNetCore.Server-Kestrel[connections-per-second,total-connections,current-upgraded-requests] \
  --refresh-interval 5 \
  --output $(date +%Y%m%d_%H%M%S)_counters.csv
```

#### 场景二：内存泄漏检测

```bash
# 长期监控内存趋势
dotnet counters monitor -p <PID> \
  --counters System.Runtime[working-set,gc-heap-size,gen-2-gc-count] \
  --duration 01:00:00 \
  --output memory-monitor.csv

# 如果看到 gc-heap-size 持续增长且 gen-2-gc 不释放，
# 可能存在内存泄漏，需要进一步用 gcdump 分析
```

### 4.3 dotnet-dump 故障排查流程

```bash
# 步骤 1: 发现异常（高 CPU 或无响应）

# 步骤 2: 收集转储
dotnet dump collect -p <PID> --type full -o crash.dmp

# 步骤 3: 分析转储
dotnet dump analyze crash.dmp

# 步骤 4: 在 SOS 提示符下执行命令

# 查看线程状态
> threads

# 查看托管堆栈
> clrstack

# 查看对象统计
> dumpheap -stat

# 查看大对象
> dumpheap -mt <MT_Address> -min 10000

# 查找根引用
> gcroot <Object_Address>

# 查看字符串内容
> dumpobj <String_Object_Address>
> !do <Object_Address>

# 查看异常
> pe
> !pe <Exception_Address>
```

**常见问题诊断命令速查**：

| 问题 | 诊断命令 |
|------|----------|
| 高 CPU | `threads` -> `clrstack` 查看热点线程 |
| 死锁 | `syncblk` 查看锁等待 |
| 内存泄漏 | `dumpheap -stat` 查看大对象 |
| 异常频繁 | `dumpheap -type Exception -stat` |
| 线程池耗尽 | `threadpool` 查看状态 |

### 5.2 publish-trimmed — 裁剪发布

```bash
# 发布裁剪后的应用（移除未使用的代码）
dotnet publish -c Release \
  --self-contained true \
  -r win-x64 \
  /p:PublishTrimmed=true

# 裁剪级别
/p:PublishTrimmed=true          # 默认级别（兼容性优先）
/p:TrimMode=link                # 激进裁剪（体积更小，可能破坏反射代码）
/p:TrimMode=copyused            # 复制使用的程序集（保守）

# 排除程序集不被裁剪
/p:TrimmerRootAssembly=MyAssembly
<publishtrimmed>true</publishtrimmed>
<TrimmerRemoveSymbols>true</TrimmerRemoveSymbols>
<TrimmerDefaultAction>link</TrimmerDefaultAction>
```

**警告处理**：

```xml
<!-- 忽略特定的裁剪警告 -->
<ItemGroup>
  <TrimmerRootAssembly Include="MyReflectionLibrary" />
  <TrimmerRootDescriptor Include="link.xml" />
</ItemGroup>
```

**link.xml 示例**：

```xml
<linker>
  <assembly fullname="MyLibrary" preserve="all">
    <type fullname="MyLibrary.MyClass" preserve="all" />
  </assembly>
</linker>
```

### 6.2 开发环境初始化脚本

```powershell
# setup-dev.ps1 - Windows PowerShell 开发环境初始化

Write-Host "=== .NET 开发环境初始化 ===" -ForegroundColor Cyan

# 1. 检查 .NET SDK
$dotnetVersion = dotnet --version 2>$null
if ($dotnetVersion) {
    Write-Host "[OK] .NET SDK: $dotnetVersion" -ForegroundColor Green
} else {
    Write-Host "[FAIL] 未检测到 .NET SDK" -ForegroundColor Red
    exit 1
}

# 2. 还原本地工具
Write-Host "[...] 正在还原本地工具..." -ForegroundColor Yellow
dotnet tool restore
if ($LASTEXITCODE -eq 0) {
    Write-Host "[OK] 本地工具还原完成" -ForegroundColor Green
}

# 3. 安装全局工具（可选）
$globalTools = @(
    @{ Name = "dotnet-ef"; Package = "dotnet-ef"; Version = "8.0.10" },
    @{ Name = "dotnet-trace"; Package = "dotnet-trace"; Version = "8.0.401805" },
    @{ Name = "dotnet-counters"; Package = "dotnet-counters"; Version = "8.0.401805" },
    @{ Name = "dotnet-dump"; Package = "dotnet-dump"; Version = "8.0.401805" },
    @{ Name = "dotnet-gcdump"; Package = "dotnet-gcdump"; Version = "8.0.401805" },
    @{ Name = "dotnet-stack"; Package = "dotnet-stack"; Version = "8.0.401805" },
    @{ Name = "dotnet-httprepl"; Package = "Microsoft.dotnet-httprepl"; Version = "7.0.0" }
)

foreach ($tool in $globalTools) {
    $installed = dotnet tool list --global | Select-String $tool.Name
    if (-not $installed) {
        Write-Host "[...] 正在安装 $($tool.Name)..." -ForegroundColor Yellow
        dotnet tool install --global $tool.Package --version $tool.Version
    } else {
        Write-Host "[OK] $($tool.Name) 已安装" -ForegroundColor Green
    }
}

# 4. 配置开发证书
Write-Host "[...] 检查开发证书..." -ForegroundColor Yellow
$certCheck = dotnet dev-certs https --check 2>&1
if ($certCheck -match "valid") {
    Write-Host "[OK] 开发证书有效" -ForegroundColor Green
} else {
    Write-Host "[...] 正在创建开发证书..." -ForegroundColor Yellow
    dotnet dev-certs https -t
}

# 5. 完成
Write-Host ""
Write-Host "=== 开发环境准备完成 ===" -ForegroundColor Green
Write-Host "运行 'dotnet restore && dotnet build' 开始开发" -ForegroundColor Cyan
```

### 7.2 问题排查速查

| 现象 | 可能原因 | 解决方案 |
|------|----------|----------|
| 工具命令未找到 | 未安装或 PATH 问题 | `dotnet tool install` 或检查 PATH |
| 版本冲突 | 全局/本地版本不一致 | 统一使用本地工具清单 |
| 权限错误 | 需要 admin 权限 | 以管理员身份运行 |
| NuGet 源超时 | 网络或源地址问题 | 检查网络，更换源 |
| 证书信任失败 | 证书过期或未信任 | `dotnet dev-certs https --trust --clean` |

合理运用这些 .NET 工具，可以显著提升开发效率、代码质量和运维能力。建议根据项目需求选择性安装和配置，并通过团队规范确保一致性。
