## 一、.NET CLI 概述

### 1.1 为什么学习 .NET CLI？

```
┌─────────────────────────────────────────────────────────────┐
│                  学习 .NET CLI 的理由                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ✅ 跨平台一致性                                             │
│     Windows / macOS / Linux 上完全相同的命令和参数           │
│                                                             │
│  ✅ CI/CD 自动化必备                                         │
│     GitHub Actions / Azure DevOps / Jenkins 全部基于 CLI    │
│                                                             │
│  ✅ 更深入的理解                                             │
│     了解 IDE 背后实际执行的操作                              │
│                                                             │
│  ✅ 远程开发场景                                             │
│     SSH 到服务器时，CLI 是唯一选择                           │
│                                                             │
│  ✅ Docker 容器化                                            │
│     Dockerfile 中使用 CLI 构建和运行应用                     │
│                                                             │
│  ✅ 效率提升                                                 │
│     很多操作用 CLI 比 GUI 更快                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 与 Visual Studio 的关系

| 场景 | Visual Studio | VS Code + CLI |
|------|--------------|---------------|
| 项目创建向导 | 图形化界面丰富选项 | `dotnet new` + 参数 |
| 编码体验 | 强大的设计器/编辑器 | 扩展支持 |
| 构建/调试 | F5 一键启动 | `dotnet build/run` |
| NuGet 管理 | GUI 包管理器 | `dotnet add/remove` |
| 发布部署 | 发布向导 | `dotnet publish` |
| CI/CD | 需要额外配置 | 天然适配 |
| 资源占用 | 较大（数GB） | 轻量级 |

**核心结论**：VS 提供更好的编码体验，但底层操作都是通过 CLI 完成的。两者互补而非替代关系。

### 1.3 CLI 基本语法

```bash
# dotnet 命令的基本结构
dotnet [command] [arguments] [options]

# 示例
dotnet build MyApp.sln --configuration Release --verbosity detailed

# 各部分说明：
# command:   build (要执行的命令)
# arguments: MyApp.sln (命令的参数)
# options:   --configuration Release (可选参数)
#            --verbosity detailed (日志级别)
```

### 1.4 获取帮助

```bash
# 查看所有可用命令
dotnet --help

# 查看特定命令的帮助
dotnet build --help
dotnet new --help

# 查看子命令的帮助
dotnet ef migrations --help

# 使用 -h 作为 --help 的简写
dotnet run -h
```

## 二、项目管理命令

### 2.1 dotnet new — 创建项目

`dotnet new` 是最常用的命令之一，用于从模板创建新项目。

#### 基本用法

```bash
# 创建一个 ASP.NET Core Web API 项目
dotnet new webapi -n MyApi -o ./src/MyApi

# 创建一个类库项目
dotnet new classlib -n MyLibrary -o ./src/MyLibrary

# 创建一个解决方案文件
dotnet new sln -n MySolution

# 创建 xUnit 测试项目
dotnet new xunit -n MyTests -o ./tests/MyTests
```

#### 常用参数详解

| 参数 | 缩写 | 说明 | 示例 |
|------|------|------|------|
| `--name` | `-n` | 项目名称 | `-n MyProject` |
| `--output` | `-o` | 输出目录 | `-o ./src/Web` |
| `--framework` | `-f` | 目标框架 | `-f net8.0` |
| `--force` | | 强制覆盖已有文件 | `--force` |
| `--no-restore` | | 创建后不恢复依赖 | `--no-restore` |

#### 实际工作流示例

```bash
# ===== 完整的项目初始化流程 =====

# Step 1: 创建解决方案
dotnet new sln -n ECommerce

# Step 2: 创建各层项目
dotnet new webapi -n ECommerce.Api -o src/ECommerce.Api
dotnet new classlib -n ECommerce.Domain -o src/ECommerce.Domain
dotnet new classlib -n ECommerce.Application -o src/ECommerce.Application
dotnet new classlib -n ECommerce.Infrastructure -o src/ECommerce.Infrastructure

# Step 3: 将项目添加到解决方案
dotnet sln add src/ECommerce.Api/src/ECommerce.Domain/src/ECommerce.Application/src/ECommerce.Infrastructure

# Step 4: 添加项目引用
dotnet add src/ECommerce.Api reference src/ECommerce.Application
dotnet add src/ECommerce.Application reference src/ECommerce.Domain
dotnet add src/ECommerce.Application reference src/ECommerce.Infrastructure
dotnet add src/ECommerce.Infrastructure reference src/ECommerce.Domain

# Step 5: 创建测试项目
dotnet new xunit -n ECommerce.Tests -o tests/ECommerce.Tests
dotnet sln add tests/ECommerce.Tests
dotnet add tests/ECommerce.Tests reference src/ECommerce.Application

# Step 6: 还原依赖并构建
dotnet restore
dotnet build
```

### 2.2 dotnet sln — 解决方案管理

管理 `.sln` 解决方案文件中的项目。

#### 常用操作

```bash
# 创建新的解决方案文件
dotnet new sln -n MySolution -o .

# 列出解决方案中的所有项目
dotnet sln list

# 将项目添加到解决方案
dotnet sln MySolution.sln add src/MyApp/MyApp.csproj
dotnet sln add **/*.csproj          # 使用通配符批量添加

# 从解决方案中移除项目
dotnet sln MySolution.sln remove src/OldProject/OldProject.csproj

# 在指定解决方案文件夹中添加项目
dotnet sln add src/MyApp/MyApp.csproj --solution-folder src
```

#### 解决方案文件夹组织

```bash
# 创建带文件夹结构的解决方案布局
dotnet new sln -n EnterpriseApp

# 添加到不同文件夹
dotnet sln add src/Api/Api.csproj --solution-folder "src/API"
dotnet sln add src/Core/Core.csproj --solution-folder "src/Core"
dotnet sln add tests/UnitTests/UnitTests.csproj --solution-folder "tests"
dotnet sln add tests/IntegrationTests/IntegrationTests.csproj --solution-folder "tests"

# 最终效果：
# EnterpriseApp/
# ├── src/
# │   ├── API/
# │   └── Core/
# └── tests/
#     ├── UnitTests/
#     └── IntegrationTests/
```

### 2.3 dotnet add — 添加包和引用

#### 添加 NuGet 包

```bash
# 添加最新版本的 NuGet 包
dotnet add package Microsoft.EntityFrameworkCore.SqlServer

# 添加指定版本
dotnet add package Newtonsoft.Json --version 13.0.3

# 添加到特定项目
dotnet add src/MyApp/MyApp.csproj package Serilog.AspNetCore

# 添加预发布版本
dotnet add package Azure.Identity --prerelease

# 添加特定源（私有 NuGet 源）
dotnet add package MyPrivatePackage \
  --source https://nuget.mycompany.com/v3/index.json

# 添加 NoDependencies 模式（不安装依赖）
dotnet add package SomePackage --no-dependencies
```

#### 添加项目引用

```bash
# 添加对另一个项目的引用
dotnet add src/MyApp/MyApp.csproj reference src/Common/Common.csproj

# 同时添加多个引用
dotnet add MyApp.csproj reference ../Domain/Domain.csproj ../Infrastructure/Infrastructure.csproj
```

#### 添加框架引用

```bash
# 引入特定的框架程序集
dotnet add MyApp.csproj reference System.Runtime
```

### 2.4 dotnet remove — 移除包和引用

```bash
# 移除 NuGet 包
dotnet remove package Newtonsoft.Json

# 移除项目引用
dotnet remove reference src/Legacy/Legacy.csproj
```

### 2.5 dotnet list — 列出包和引用

```bash
# 列出项目的所有 NuGet 包及其版本
dotnet list src/MyApp/MyApp.csproj package

# 列出过时的包（有更新版本可用）
dotnet list src/MyApp/MyApp.csproj package --outdated

# 列出有过时版本的包（包括预发布版）
dotnet list src/MyApp/MyApp.csproj package --outdated --include-prerelease

# 列出易受攻击的包（已知安全漏洞）
dotnet list src/MyApp/MyApp.csproj package --vulnerable

# 列出项目引用
dotnet list src/MyApp/MyApp.csproj reference

# 列出整个解决方案的所有包
dotnet list MySolution.sln package --outdated
```

**输出示例**：


## 三、构建与运行命令

### 3.1 dotnet build — 构建项目

`dotnet build` 是日常开发中使用频率最高的命令之一。

#### 基本用法与参数

```bash
# 基本构建（默认 Debug 配置）
dotnet build

# 指定配置
dotnet build -c Release
dotnet build --configuration Debug

# 构建解决方案
dotnet build MySolution.sln

# 构建特定项目
dotnet build src/MyApp/MyApp.csproj

# 详细输出（排查构建问题）
dotnet build --verbosity diagnostic

# 不恢复依赖直接构建（加速）
dotnet build --no-restore

# 强制重新构建所有代码
dotnet build --no-incremental

# 指定输出目录
dotnet build -c Release -o ./publish/output

# 多处理器并行构建（加速大型项目）
dotnet build -c Release --maxCpuCount
```

#### 重要构建参数详解

| 参数 | 说明 | 推荐值 |
|------|------|--------|
| `-c, --configuration` | Debug 或 Release | 开发用 Debug，发布用 Release |
| `--framework` | 目标框架 | 如 `net8.0`, `net6.0` |
| `--runtime` | 目标运行时标识符 | 如 `win-x64`, `linux-x64` |
| `--self-contained` | 自包含部署模式 | `true` 或 `false` |
| `-p:PublishTrimmed=true` | 启用裁剪 | 减小发布体积 |
| `--no-restore` | 跳过恢复 | 依赖未变时使用 |
| `--verbosity` | 日志级别 | `q/m/n/d/diagnostic` |
| `--warnaserror` | 将警告视为错误 | CI 环境推荐启用 |

#### 构建属性传递

```bash
# 通过 -p 传递 MSBuild 属性
dotnet build -c Release \
  -p:TreatWarningsAsErrors=true \
  -p:VersionPrefix=1.2.0 \
  -p:VersionSuffix=beta.1

# 常用的 MSBuild 属性
-p:DefineConstants=DEBUG;TRACE        # 定义编译常量
-p:LangVersion=latest                  # C# 语言版本
-p:Nullable=enable                     # 可空引用类型
-p:GenerateDocumentationFile=true      # 生成 XML 文档
-p:NoWarn=CS1591                       # 抑制特定警告
```

#### 构建输出解读

```
# 成功的构建输出
MSBuild version 17.x.x.x for .NET
  Determining projects to restore...
  All projects are up-to-date for restore.
  MyApp -> bin\Release\net8.0\MyApp.dll

  Build succeeded.
      0 Warning(s)
      0 Error(s)

  Time Elapsed 00:00:03.42

# 有警告的构建（需要关注！）
  Build succeeded.
      12 Warning(s)    ← 关注这些警告
      0 Error(s)

# 失败的构建
  Build FAILED.
      0 Warning(s)
      3 Error(s)       ← 必须修复这些错误

  错误详情会列出具体文件和行号：
  CS0103 C:\Projects\MyApp\Controllers\UserController.cs(15,30):
         The name 'GetUser' does not exist in the current context
```

### 3.2 dotnet run — 运行应用

用于运行 .NET 应用程序的源代码，无需显式编译或启动命令。

#### 基本用法

```bash
# 运行当前目录的项目
dotnet run

# 指定项目运行
dotnet run --project src/MyApp/MyApp.csproj

# 使用特定启动配置
dotnet run --launch-profile "Production"

# 传递应用参数
dotnet run -- arg1 arg2

# 设置环境变量
dotnet run --environment "Staging"

# 不先构建（假设已构建且无变更）
dotnet run --no-build

# 不还原依赖
dotnet run --no-restore

# 指定框架
dotnet run --framework net8.0
```

#### 启动配置 (Launch Profiles)

ASP.NET Core 支持多个启动配置，定义在 `Properties/launchSettings.json` 中：

```json
{
  "profiles": {
    "Development": {
      "commandName": "Project",
      "dotnetRunMessages": true,
      "launchBrowser": false,
      "applicationUrl": "https://localhost:5001;http://localhost:5000",
      "environmentVariables": {
        "ASPNETCORE_ENVIRONMENT": "Development"
      }
    },
    "Docker": {
      "commandName": "Docker",
      "launchBrowser": false,
      "environmentVariables": {
        "ASPNETCORE_ENVIRONMENT": "Development",
        "ASPNETCORE_HTTPS_PORTS": "5001",
        "ASPNETCORE_HTTP_PORTS": "5000"
      }
    },
    "Staging": {
      "commandName": "Project",
      "environmentVariables": {
        "ASPNETCORE_ENVIRONMENT": "Staging"
      }
    }
  }
}
```

使用方式：

```bash
# 使用 Development 配置运行
dotnet run --launch-profile "Development"

# 使用 Staging 配置运行
dotnet run --launch-profile "Staging"
```

### 3.3 dotnet clean — 清理构建产物

```bash
# 清理当前项目
dotnet clean

# 清理整个解决方案
dotnet clean MySolution.sln

# 清理特定配置
dotnet clean -c Release

# 只清理输出，保留项目文件
dotnet clean --output ./clean-output

# 结合 build 使用（完全重建）
dotnet clean && dotnet build -c Release
```

### 3.4 dotnet publish — 发布部署包

将应用程序及其依赖打包为可部署的形式。

#### 基本发布方式

```bash
# 依赖框架发布（Framework-Dependent Deployment - FDD）
# 需要目标机器安装对应的 .NET Runtime
dotnet publish -c Release -o ./publish/fdd

# 自包含发布（Self-Contained Deployment - SCD）
# 包含完整的 .NET Runtime，不需要目标机器安装 .NET
dotnet publish -c Release \
  --self-contained \
  -r win-x64 \
  -o ./publish/scd-win

# Linux 自包含发布
dotnet publish -c Release \
  --self-contained \
  -r linux-x64 \
  -o ./publish/scd-linux

# 单文件发布（所有 DLL 打包为一个 exe）
dotnet publish -c Release \
  -r win-x64 \
  --self-contained \
  -p:PublishSingleFile=true \
  -o ./publish/singlefile
```

#### 发布裁剪优化（Trimming）

裁剪可以显著减小发布体积，移除未使用的代码：

```bash
# 启用裁剪
dotnet publish -c Release \
  -r win-x64 \
  --self-contained \
  -p:PublishTrimmed=true \
  -o ./publish/trimmed

# 裁剪级别控制
-p:PublishTrimmed=true              # 基础裁剪（默认 copyused）
-p:TrimMode=link                    # 激进裁剪（IL Linker）
-p:TrimMode=partial                 # 部分裁剪

# 裁剪警告处理
-p:SuppressTrimAnalysisWarnings=WIL1019,WIL2141
```

#### ReadyToRun 预编译

```bash
# 启用 ReadyToRun（减少 JIT 编译时间，加快启动速度）
dotnet publish -c Release \
  -p:PublishReadyToRun=true \
  -p:PublishReadyToRunShowWarnings=true \
  -o ./publish/rtr
```

#### AOT 编译（原生发布）

.NET 8+ 支持 AOT（Ahead-of-Time）原生编译：

```bash
# 原生 AOT 发布（生成真正的机器码）
dotnet publish -c Release \
  -r win-x64 \
  -p:PublishAot=true \
  -o ./publish/aot

# 注意：AOT 有一些限制（不支持反射等特性）
# 适用于容器化和云原生场景
```

#### 发布大小对比

```
发布方式                大小示例（简单 Web API）  启动时间  适用场景
─────────────────────────────────────────────────────────────────
FDD (框架依赖)           ~15 MB                   ~2s     开发/Docker
SCD (自包含)            ~60 MB                   ~1s     无 .NET 环境
SCD + Single File       ~60 MB                   ~1s     简单部署
SCD + Trimmed           ~25 MB                   ~1s     减小体积
SCD + Trimmed + RTR     ~28 MB                   ~0.5s   快速启动
Native AOT              ~10 MB                   ~0.05s  云原生极致性能
```

## 四、测试命令

### 4.1 dotnet test — 运行单元测试

```bash
# 运行当前目录下的测试项目
dotnet test

# 运行指定测试项目
dotnet test tests/MyApp.UnitTests/

# 运行整个解决方案中的所有测试
dotnet test MySolution.sln

# 按配置运行
dotnet test -c Release

# 显示详细测试结果
dotnet test --verbosity normal

# 不构建直接运行（加速重复测试）
dotnet test --no-build

# 不还原依赖
dotnet test --no-restore
```

#### 测试筛选器

筛选器允许你只运行特定的测试，这是调试单个失败测试的关键功能：

```bash
# 按完全限定名筛选
dotnet test --filter "FullyQualifiedName~UserServiceTests"

# 按测试类名筛选
dotnet test --filter "ClassName~OrderServiceTests"

# 按测试方法名筛选
dotnet test --filter "DisplayName~AddItem_WhenValid_ShouldSucceed"

# 按命名空间筛选
dotnet test --filter "Namespace~MyApp.Services"

# 组合条件（使用 & | ! 运算符）
dotnet test --filter "ClassName~UserTests&DisplayName~Create"

# 排除特定测试
dotnet test --filter "ClassName!~IntegrationTests"

# 只运行失败的测试
dotnet test --filter "State!=Passed"

# 按 Trait（xUnit 特性）筛选
dotnet test --filter "Category=Unit"
dotnet test --filter "Priority=High"
```

#### 测试覆盖率

```bash
# 使用 coverlet 收集覆盖率（需要安装 coverlet.msbuild 包）
dotnet test /p:CollectCoverage=true \
  /p:CoverletOutputFormat=opencover \
  /p:CoverletOutput=./coverage/ \
  /p:Include="[MyApp.*]*" \
  /p:Exclude="[*.Tests]*[*]*"

# 生成 HTML 格式的覆盖率报告
dotnet test /p:CollectCoverage=true \
  /p:CoverletOutputFormat=cobertura \
  /p:CoverletOutput=./coverage/

# 设置覆盖率阈值（低于阈值则构建失败）
dotnet test /p:CollectCoverage=true \
  /p:ThresholdType=line \
  /p:Threshold=80 \
  /p:ThresholdStat=total
```

#### 并行测试

```bash
# 启用并行测试执行
dotnet test --settings coverage.runsettings

# coverage.runsettings 内容：
<?xml version="1.0" encoding="utf-8"?>
<RunSettings>
  <DataCollectionRunSettings>
    <DataCollectors>
      <DataCollector friendlyName="Code Coverage">
        <Configuration>
          <CodeCoverage>
            <ModulePaths>
              <Exclude>.*Tests.*</Exclude>
            </ModulePaths>
          </CodeCoverage>
        </Configuration>
      </DataCollector>
    </DataCollectors>
  </DataCollectionRunSettings>
</RunSettings>
```

### 4.2 dotnet vstest — 灵活的测试执行

`dotnet vstest` 用于运行已编译的程序集中的测试，提供更灵活的控制。

```bash
# 运行特定的测试程序集
dotnet vstest bin/Debug/net8.0/MyApp.Tests.dll

# 运行多个测试程序集
dotnet vstest bin/**/*Tests.dll

# 指定测试框架设置
dotnet vstest MyApp.Tests.dll --settings:test.runsettings

# 并行执行
dotnet vstest Tests.dll --Parallel

# 指定架构
dotnet vstest Tests.dll --Framework:FrameworkCore10

# 指定测试适配器路径
dotnet vstest Tests.dll --TestAdapterPath:./test-adapters
```

## 五、工具与信息命令

### 5.1 dotnet tool — 工具管理

.NET CLI 支持全局工具和本地工具两种形式。

#### 全局工具管理

```bash
# 安装全局工具
dotnet tool install -g dotnet-format
dotnet tool install -g dotnet-reportgenerator-globalemitter

# 列出已安装的全局工具
dotnet tool list -g

# 更新全局工具
dotnet tool update -g dotnet-format

# 卸载全局工具
dotnet tool uninstall -g dotnet-format

# 运行全局工具
dotnet-format ./src
reportgenerator
```

#### 本地工具（推荐用于团队项目）

本地工具通过 `manifest` 文件管理，可以纳入版本控制：

```bash
# 初始化本地工具清单（创建 dotnet-tools.json）
dotnet new tool-manifest

# 安装本地工具
```

### 日常开发工作流速查

```bash
# ===== 新建项目 =====
dotnet new sln -n MyApp && \
dotnet new webapi -n MyApp.Api -o src/MyApp.Api && \
dotnet new classlib -n MyApp.Core -o src/MyApp.Core && \
dotnet sln add src/**/*.csproj && \
dotnet add src/MyApp.Api/MyApp.Api.csproj reference src/MyApp.Core/MyApp.Core.csproj && \
dotnet restore && dotnet build

# ===== 日常开发循环 =====
dotnet build                          # 修改代码后构建
dotnet run --project src/Api          # 运行 API
dotnet test --filter "~UserService"   # 运行相关测试

# ===== 添加新依赖 =====
dotnet add package NewPackage
dotnet build                           # 验证兼容性
dotnet test                            # 确保没有破坏测试

# ===== 发布部署 =====
dotnet clean
dotnet publish -c Release \
  --self-contained -r linux-x64 \
  -p:PublishSingleFile=true \
  -o ./publish/linux

# ===== CI/CD 典型流程 =====
dotnet restore --configfile NuGet.config
dotnet build -c Release --no-restore \
  -p:TreatWarningsAsErrors=true
dotnet test -c Release --no-build \
  --verbosity normal
dotnet publish -c Release -o ./artifacts
```

### 常见问题快速解决

| 问题 | 命令 | 说明 |
|------|------|------|
| 依赖冲突 | `dotnet restore --force-evaluate-resolves` | 强制重新解析 |
| 构建缓存脏了 | `dotnet clean && dotnet build` | 完全重建 |
| NuGet 源问题 | `dotnet nuget locals all --clear` | 清理缓存 |
| SDK 版本不对 | `dotnet new globaljson --sdk-version 8.0.200` | 锁定版本 |
| 测试不稳定 | `dotnet test --blame` | 分析超时测试 |
| 内存不足 | `dotnet build -m:1` | 限制并行度 |
| 找不到工具 | `dotnet tool restore` | 还原本地工具 |

.NET CLI 是每个 ASP.NET 开发者必须掌握的核心技能。本文涵盖了项目管理、构建运行、测试和工具管理等各个方面：

**必须熟练掌握的 5 个命令**：
1. `dotnet new` — 项目脚手架
2. `dotnet build` — 构建验证
3. `dotnet run` — 快速运行
4. `dotnet test` — 测试驱动
5. `dotnet publish` — 打包发布

**进阶技能**：
- 熟练使用 `--filter` 进行精准测试
- 掌握各种发布模式和优化选项
- 使用本地工具管理团队共享的开发工具
- 通过 MSBuild 属性自定义构建行为

建议在每天的编码中刻意使用 CLI 命令，逐步形成肌肉记忆。
